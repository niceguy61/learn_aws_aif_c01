# AIF-C01 Task 2.1 Part 5 - 생성형 AI 프로젝트/파운데이션 모델 수명 주기 (2.1 마무리)

> 프로젝트 구상부터 시작까지 매핑하는 프레임워크, 시험 가이드 공식 수명 주기

## 1. 생성형 AI 프로젝트 수명 주기 7단계

**프레임워크 단계:**
1. **사용 사례 식별**
2. **실험 및 선택**
3. **적응 (Adaptation)**
4. **정렬 및 증강 (Alignment & Augmentation)**
5. **평가 (Evaluation)**
6. **배포 및 반복 (Deployment & Iteration)**
7. **모니터링 (Monitoring)**

### AI 주기 3단계로 재정리

- **1단계 - 목표/데이터/모델 선택/훈련:** 목표 정의, 데이터 수집, 데이터 처리, 모델 선택, 모델 훈련/개발
- **2단계 - 모델 개발:** 특성 추출, 구축, 테스트, 검증, 최적화, 확장 사용
- **3단계 - 배포/유지 보수:** 모델 평가, 배포, 피드백, 업데이트, 보안, 확장성 포함

## 2. 파운데이션 모델 수명 주기 (시험 가이드 공식 - 암기 필수)

**시험 가이드 나열 순서:**

`데이터 선택 → 모델 선택 → 사전 훈련 → 미세 조정 → 평가 → 배포 → 피드백`

| 단계 | 설명 |
| :--- | :--- |
| **데이터 선택** | 훈련 데이터 수집/처리/품질 큐레이션 (토큰 1~3%만 사용) |
| **모델 선택** | 처음부터 직접 훈련 vs 기존 파운데이션 모델 사용 결정 |
| **사전 훈련** | GB/TB/PB 텍스트, 자가 지도 학습, GPU 많이 필요, 패턴/구조 내재화 |
| **미세 조정** | 특정 사용 사례 맞춤 지도 학습 |
| **평가** | 성능/선호도 부합 확인, 다양한 지표/벤치마크 사용 |
| **배포** | 인프라 배포/애플리케이션 통합, 모델/컴퓨팅 리소스 최적화, 뛰어난 UX 확인 |
| **피드백** | 피드백 수집/업데이트/보안/확장성 |

## 3. 가장 중요한 단계: 범위 정의

- **핵심:** 모든 프로젝트에서 가장 중요한 단계 = **범위 최대한 정확/좁게 정의**
- LLM이 특정 애플리케이션에서 수행할 기능 생각
  - 예) 긴 형식 텍스트 생성 포함 여러 태스크 수행 필요? 
  - 아니면 명명된 엔터티 인식처럼 훨씬 구체적, 한 가지 태스크만 잘 수행하면 됨?
- 구체적으로 파악하면 **시간 절약 + 컴퓨팅 비용 절약**

## 4. 개발 흐름 - 실험부터 정렬까지 (반복적)

### Step 1: 실험 및 선택

- 모델 요구 사항 만족/범위 정해지면 개발 시작 준비
- 첫 결정: **처음부터 직접 훈련 vs 기존 기본 모델 사용**

### Step 2: 프롬프트 엔지니어링부터 시작

- 모델 성능 평가, 애플리케이션 필요 시 추가 훈련 완료
- 때로 **프롬프트 엔지니어링**이 성능 높이는 데 도움
- **시작 추천:** 태스크/사용 사례 적합 예제 사용 **컨텍스트 내 학습** 시도
- 제로샷/원샷/퓨샷 추론 시도

### Step 3: 미세 조정 필요 시

- 원샷/퓨샷 사용해도 필요한 만큼 작동 안할 수 있음 -> **미세 조정** 시도
- 이 프로세스 = **지도 학습 프로세스**

### Step 4: 정렬 - RLHF

- 모델 성능 향상됨에 따라 배포 시 **인간 선호도 맞는 방식으로 제대로 작동** 확인 점점 중요
- 추가 미세 조정 기법 **RLHF (인간의 피드백 통한 강화 학습)** 포함하면 모델 제대로 동작 확인 도움

### 반복적 개발 원칙

- 적응/정렬 포함 개발 단계는 **매우 반복적**
- 선호 흐름: **프롬프트 엔지니어링 시도 + 결과 평가 -> 미세 조정으로 성능 개선 -> 프롬프트 엔지니어링 재검토 + 평가** 반복

## 5. 배포와 인프라 고려

- 성능 요구 충족 + 잘 정렬된 모델 있으면 배포
- 모델 인프라 배포 + 애플리케이션 통합
- 배포 위한 모델/컴퓨팅 리소스 최적화, 애플리케이션이 사용자에게 뛰어난 경험 제공 확인
- 마지막 매우 중요한 단계: 애플리케이션 작동 필요 추가 인프라 고려

## 6. LLM 근본적 한계 (훈련만으로 극복 어려움)

- **환각 (Hallucination):** 답 모르는 경우 정보 만들어냄
- **복잡한 추론/수학 제한된 능력**

## 7. 시험 체크포인트

- 프로젝트 수명 주기: 사용 사례 식별/실험 및 선택/적응/정렬 및 증강/평가/배포 및 반복/모니터링, 3단계: 목표 정의 데이터 수집 처리 모델 선택 훈련 개발/특성 추출 구축 테스트 검증 최적화 확장/평가 배포 피드백 업데이트 보안 확장성
- 파운데이션 모델 수명 주기 시험 가이드 순서: 데이터 선택 모델 선택 사전 훈련 미세 조정 평가 배포 피드백 (암기)
- 범위 정의 가장 중요, 정확 좁게, LLM 기능 생각 긴 형식 여러 태스크 vs NER 한 태스크, 시간 비용 절약
- 개발: 처음부터 훈련 vs 기존 기본 모델, 성능 평가 추가 훈련, 프롬프트 엔지니어링 먼저 컨텍스트 내 학습 제로 원 퓨샷, 안되면 미세 조정 지도 학습, 성능 향상 시 정렬 중요 RLHF 인간 선호도, 평가 지표 벤치마크, 매우 반복적 프롬프트->평가->미세 조정->재검토
- 배포: 인프라 배포 통합 리소스 최적화 UX, 추가 인프라 고려
- 한계: 환각 답 모르면 만들어냄, 복잡 추론 수학 제한
