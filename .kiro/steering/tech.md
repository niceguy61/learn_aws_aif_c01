# 문서 기술 규칙

## 기본 형식
- 모든 학습 자료는 UTF-8 Markdown으로 작성한다.
- 파일명과 디렉터리명은 영문 소문자와 숫자, 하이픈을 사용한다.
- 본문은 짧은 문단과 명확한 제목을 사용한다. 한 문단에 하나의 핵심 주장만 둔다.
- 표는 비교·암기·선택에 유리할 때 사용하고, 모바일 화면에서도 읽을 수 있도록 열 수를 과도하게 늘리지 않는다.
- Mermaid나 외부 렌더러에 의존하지 않고도 핵심 내용을 읽을 수 있도록 텍스트 설명을 함께 둔다.

## 권장 문서 메타데이터
도메인별 학습 문서는 다음 YAML front matter를 사용한다.

```yaml
---
title: "문서 제목"
domain: "D1"
level: "beginner"
status: "draft"
source_urls:
  - "https://공식-출처"
source_checked: "YYYY-MM-DD"
---
```

`status` 값은 `draft`, `review`, `verified` 중 하나다. 검증되지 않은 문서는 `verified`로 표시하지 않는다.

## 문서 내부 기본 순서
1. 이 문서에서 배울 것
2. 선수 지식과 한 줄 요약
3. 핵심 개념을 쉬운 말로 설명
4. AWS 관점과 관련 서비스
5. 비슷한 개념·서비스 비교
6. 실무형 시나리오
7. 시험에서 판단하는 단서
8. 자주 하는 오해
9. 핵심 정리
10. 스스로 답하는 확인 질문
11. 연결된 다음 문서

## 출처와 최신성
- AWS 공식 문서를 1차 출처로 우선한다.
- 출처 URL, 문서 제목, 확인 날짜를 문서 끝의 `출처` 섹션에 기록한다.
- 원문을 통째로 복사하지 말고 학습 목적에 맞게 재구성·요약한다. 꼭 필요한 짧은 인용만 사용하고 출처 링크를 바로 붙인다.
- AWS 서비스 기능, 모델명, 요금, 리전, 할당량처럼 변할 수 있는 정보는 작성일 기준을 표시하고 공식 페이지에서 다시 확인한다.
- 서로 다른 공식 문서에서 표현이 다르면 양쪽 링크를 남기고 차이를 설명한다.

## 링크와 추적성
- 모든 외부 링크는 Markdown 링크로 작성한다.
- 수집한 URL은 `sources/` 아래의 링크 인벤토리에서 도메인, 주제, 연결 문서, 상태와 함께 추적한다.
- 링크를 열 수 없거나 내용이 확인되지 않으면 내용을 만들어내지 말고 상태를 `blocked`로 기록한다.
