## Way of Working

- 버전 관리형 Markdown을 짧은 작업 단위로 작성하고 `main`에 통합한다.
- 가능하면 짧은 수명의 작업 브랜치와 squash-merge를 사용한다.
- 문서 변경은 작은 단위로 나누고, 변경된 출처·추적성·검토 결과를 함께 기록한다.
- 애플리케이션 배포나 장기 실행 환경은 이 프로젝트의 작업 방식에 포함하지 않는다.

## Walking Skeleton

- 첫 문서 수직 슬라이스를 사용한다.
- 첫 문서는 공식 출처 연결, 개념 문서 작성, 정적 품질 검사, 초보자 관점 검토까지 처음부터 끝까지 통과시킨다.
- 첫 슬라이스에서 확인한 문서 구조·출처 추적·문서 연결·검토 절차를 기준선으로 삼아 D1부터 D5 순서로 확장한다.
- 이 walking skeleton은 애플리케이션의 실행·배포 슬라이스가 아니라 문서 제작 흐름의 최소 완결 단위다.

## Testing Posture

- **Methodology**: test-after
- **Ordering**: 문서를 작성한 다음 해당 문서와 변경 범위에 맞는 문서 품질 검증을 실행하고, 실패 항목을 수정한 뒤 결과를 기록한다.
- 문서 품질 게이트는 특정 도구에 종속되지 않으며 다음 검사를 포함한다.
  - Markdown 문법, 제목 계층, 필수 섹션, YAML front matter 필수 필드와 허용 상태값을 검사한다.
  - 내부 링크, 다음 문서 연결, 용어 사전 연결이 실제 대상과 일치하는지 검사한다.
  - `sources/`의 출처 레지스트리와 문서의 URL·제목·확인 날짜·접근 상태·연결 문서가 일치하는지 검사한다.
  - AIF-C01 공식 시험 안내서의 D1~D5 모든 작업·기술 항목이 문서 또는 명시적인 `해당 없음`·`확장` 기록으로 양방향 추적되는지 검사한다.
  - 공식 범위와 실무 확장을 문서 안에서 구분하고, 공식 사실과 학습자용 해설·예시를 대조한다.
  - 선수 지식, 쉬운 예시, AWS 서비스 선택 단서, 비교, 시나리오, 오해 교정, 확인 질문을 초보자 관점에서 검토한다.
  - UTF-8 인코딩, 파일명·디렉터리명 규칙, CSV 형식과 구조를 검사한다.
  - 예시·로그·검사 결과에 비밀, 자격 증명, 토큰, 실제 개인정보(PII), 실제 계정 식별자를 포함하지 않는지 검사한다.
  - 출처가 차단되거나 동적 내용·인증·네트워크 문제로 확인되지 않으면 `blocked` 또는 확인 필요 상태와 사유를 기록하며, 확인하지 못한 내용을 추측하지 않는다.
  - Mermaid 다이어그램은 학습 내용을 실질적으로 개선할 때 허용하며, 모든 Mermaid 다이어그램 가까이에 일반 텍스트 또는 Markdown 설명을 둔다. 핵심 의미가 외부 렌더러에 의존해서는 안 된다.
  - 문서를 `verified`로 표시하기 전에 Mermaid 구문을 검증하고, 다이어그램은 단순하고 모바일에서 읽기 쉽게 유지한다.
  - 원격 이미지의 접근 가능 여부를 확인하고, URL이 차단되거나 변경되어도 읽을 수 있도록 이미지가 아닌 텍스트 대체 설명을 보존한다.
  - 출처 검증과 초보자 검토의 결과는 문서 또는 관련 추적 기록에 남긴다. 검증되지 않은 문서는 `verified`로 승격하지 않는다.
  - 이미지의 한국어 대체 텍스트는 의미를 설명해야 하며, 캡션 또는 주변 설명과 텍스트 대체 경로를 함께 제공한다. 이미지와 색상만으로 주장을 전달하지 않는다.
  - AWS 호스팅 공식 이미지는 출처 페이지, 직접 이미지·원본 URL, 제목, 접근일, 저작자 표시와 재사용·사용 조건을 `sources/`에 기록할 수 있을 때만 사용한다. 권리 또는 조건이 불명확하면 다운로드하거나 재배포하지 않는다.
  - AWS 공식 이미지와 가이드 자체 설명용 다이어그램을 분리하고, AWS가 이 가이드를 보증하는 것처럼 표현하지 않는다.

## Deployment

- 애플리케이션 배포는 해당 없음이다. 이 프로젝트는 정적 학습 Markdown 산출물을 만든다.
- 문서의 전달 경계는 필수 문서 품질 검증을 통과한 변경을 `main`에 통합하는 시점이다.
- staging·production 환경, 배포 파이프라인, 운영 모니터링은 만들지 않는다.

## Code Style

- 모든 학습 자료는 UTF-8 Markdown으로 작성한다.
- 파일명과 디렉터리명은 영문 소문자·숫자·하이픈을 사용한다.
- 본문은 짧은 문단과 명확한 제목을 사용하고, 표는 비교·암기·선택에 유용할 때만 사용한다.
- 한국어 prose를 기본으로 하되 AWS 서비스명·API명·CLI 명령·URL·공식 문서 제목과 핵심 영어 용어의 원문 표기를 보존한다.
- Mermaid 다이어그램은 개념 관계나 흐름을 실제로 더 잘 이해하게 할 때 사용하며, 단순한 구조와 모바일 가독성을 유지한다.
- 모든 Mermaid 다이어그램에는 가까운 일반 텍스트 또는 Markdown 설명을 함께 두어 외부 렌더러 없이도 핵심 의미를 이해할 수 있게 한다.
- AWS 호스팅 공식 이미지를 사용할 때는 출처 페이지, 직접 이미지·원본 URL, 제목, 접근일, 저작자 표시와 재사용·사용 조건을 `sources/`에 기록한다. 조건이 불명확한 이미지는 다운로드하거나 재배포하지 않는다.
- 모든 이미지는 의미 있는 한국어 alt text, 캡션 또는 주변 설명, 텍스트 대체 경로를 갖는다. 이미지나 색상만으로 핵심 주장을 전달하지 않는다.
- AWS 공식 이미지 콘텐츠와 가이드 자체 설명용 다이어그램을 구분하고, AWS의 가이드 보증으로 오해될 표현을 사용하지 않는다.
- 원격 이미지의 접근 가능 여부를 확인하고, URL이 차단되거나 변경되어도 사용할 수 있는 텍스트 대체 설명을 보존한다.
- 문서 메타데이터와 출처 섹션을 일관된 형식으로 유지하고, 외부 렌더러 없이도 핵심 내용을 이해할 수 있게 텍스트 설명을 함께 둔다.
