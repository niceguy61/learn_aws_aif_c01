# User Stories 단계 평가

## Decision

**Execute**

## Rationale

이 프로젝트는 완전 초보자를 위한 사용자-facing 한국어 학습 제품이다. 최종 사용자는 AI/ML과 AWS를 처음 접하는 학습자이며, 제품 소유자와 집필·검토 흐름에 참여하는 역할도 존재한다. 따라서 요구사항을 문서 목록으로만 전달하면 학습자의 가치, 콘텐츠 운영자의 목표, 품질 검토자의 확인 가능성을 하나의 실행 단위로 연결하기 어렵다.

또한 결과물은 단일 문서가 아니라 공식 시험 범위 등록, 도메인별 학습 문서, 4주 학습 경로, 카드·퀴즈·용어 사전·Anki 자료, 100문항 이상 문제은행, 출처·품질 검증 기록으로 구성된다. 이처럼 여러 문서 워크플로가 서로 연결되므로 사용자 스토리는 요구사항에서 학습 가치와 검증 가능한 수용 기준으로 내려가는 추적성을 보강한다.

## Factors considered

- **프로젝트 유형**: 실행형 애플리케이션은 아니지만, 학습자가 읽고 판단하고 복습하는 사용자 경험을 제공하는 정적 학습 제품이다.
- **사용자-facing 범위**: 초보 학습자가 개념 이해에서 AWS 서비스 선택, 시나리오 판단, 복습·평가로 이동해야 한다.
- **페르소나 신호**: 주 학습자 외에 제품 소유자, 콘텐츠 작성·유지관리자, 출처·품질 검토 역할의 관심사가 있다.
- **복잡성 신호**: D1~D5 전체 범위, 공식 기준선·문서·문항·카드·퀴즈·Anki 간 양방향 추적, 출처 최신성 상태, 초보자 검토와 문서 품질 검사가 필요하다.
- **협업 신호**: 제품 관점의 가치, 디자인 관점의 읽기 흐름, 개발 관점의 문서 구조 실현 가능성, 품질 관점의 수용 기준을 함께 맞춰야 한다.

## Key areas where stories add value

1. **학습자 여정**: 개념 이해 → AWS 관점의 선택 기준 → 시나리오 판단 → 복습·평가를 독립적으로 검토 가능한 가치 단위로 연결한다.
2. **공식 범위와 추적성**: 시험 기준선이 학습 문서와 문제·카드·퀴즈·Anki로 이어지는 사용자·제품 가치를 명확히 하고, 고아 산출물을 식별한다.
3. **문서 제작 워크플로**: 출처 조사, 작은 개념 문서 작성, 도메인 연결, 품질 검증, 검토 기록을 집필·유지관리자가 반복 가능한 흐름으로 다룬다.
4. **문제은행과 복습 자료**: 초보 학습자가 자신의 이해를 확인하고 제품 소유자가 준비 지표와 범위 커버리지를 점검할 수 있게 한다.
5. **품질·최신성 검증**: 출처 상태, 시험 범위/실무 확장 구분, 초보자 관점, 민감정보 검사를 검증 가능한 acceptance criteria로 표현한다.
6. **우선순위와 인수인계**: MoSCoW로 시험 핵심과 지원 산출물을 구분하고, 이후 설계·단위·전달 계획 단계가 사용할 안정적인 US/AC 추적 ID를 제공한다.

## Scope guardrail

승인된 범위, 완전 초보자 대상, D1→D5 작성 순서, 승인된 산출물 목록, 한국어·UTF-8 Markdown/CSV 형식, 코드·유료 실습·애플리케이션 구축 제외 제약은 다시 결정하지 않는다. 이 단계에서는 페르소나의 강조점과 스토리 세분화 수준만 확인한다.
