## 공통 범위 원칙

- 공식 AIF-C01의 5개 도메인을 D1→D2→D3→D4→D5 순서로 다룬다.
- 공식 시험 안내서에 근거한 내용은 `시험 범위`로 표시한다. 서비스 선택, 비교, 기본 시나리오, 학습 예시는 관련 공식 기준선 ID를 먼저 표시한 `실무 확장`으로 표시하며 공식 출제 범위로 단정하지 않는다.
- 모든 결과물은 한국어 UTF-8 Markdown 또는 승인된 UTF-8 CSV로 제공한다. AWS 서비스명·API명·CLI 명령·URL·공식 문서 제목과 핵심 영어 용어의 원문 표기는 보존한다.
- 문서·문항·카드·퀴즈·Anki 항목은 안정 ID, `baseline_ids` 또는 명시적인 `실무 확장` 근거, 공식 출처 메타데이터를 갖고 정방향·역방향으로 추적할 수 있어야 한다. 기준선 레코드는 `revision_title`, `official_source_url`, `official_source_title`, `checked_date`, `status`를 고정하고 파생 항목은 기준선 ID로 해당 revision에 역추적된다.
- 문서 상태(`draft|review|verified`)와 출처 상태(`discovered|downloaded|summarized|reviewed|verified|blocked`)는 별도 의미로 유지한다. `blocked` 또는 `확인 필요` 출처에 의존하는 자료는 `verified`가 될 수 없다.
- 코드, 코드가 필수인 학습 경로, 유료 AWS 실습, AWS 계정 생성, 프로덕션 시스템·API·데이터베이스·인프라 구축, 학습자 데이터 저장은 포함하지 않는다.
- 출처 원문을 통째로 재배포하지 않고 한국어로 재구성하며, 필요한 짧은 인용에는 공식 링크를 붙인다. 검증되지 않은 AWS 세부사항은 `확인 필요` 또는 보류 상태로 남긴다.
- 정적 산출물의 `선택·이동·확인·완료`는 Markdown 링크, 도메인 목차, 현재/이전/다음 문서 링크, 체크리스트와 상태 표지로 구현하며 웹 애플리케이션 상호작용이나 자동 저장을 뜻하지 않는다.

## US1.1 — 공식 범위와 학습 지도를 확인한다

**스토리**

> As a 처음 시작하는 AIF-C01 학습자(P1), I want 공식 AIF-C01 5개 도메인과 D1→D5 학습 지도를 확인하고 싶다, so that 무엇을 어떤 순서로 공부해야 하는지 판단할 수 있다.

**우선순위**: Must Have  
**요구사항 연결**: FR1, FR2.1, FR2.6, NFR3, NFR8  
**의존성**: 없음. US1.2와 US2.1이 이 지도의 정보를 사용한다.  
**관계**: US1.2 `enables`, US2.1 `precedes`, US5.1 `is validated by`  
**범위 분류**: 공식 시험 범위 중심; 학습 지도 표현은 학습자용 해설이다.

### Acceptance criteria

- **AC1.1.1**  
  **Given** 공식 AIF-C01 시험 안내서와 기준선 등록 정보가 확인되어 있을 때  
  **When** 학습자가 시작 안내와 도메인 개요를 열면  
  **Then** D1 AI 및 ML의 기초(20%), D2 GenAI의 기초(24%), D3 파운데이션 모델의 적용(28%), D4 책임 있는 AI에 대한 가이드라인(14%), D5 AI 솔루션의 보안·규정 준수 및 거버넌스(14%)가 공식 명칭과 함께 표시된다.

- **AC1.1.2**  
  **Given** 학습자가 AI/ML과 AWS를 처음 접할 때  
  **When** 학습 지도를 읽으면  
  **Then** 선수 지식, 각 도메인의 목표, D1→D5 읽기 순서, 다음 문서 연결이 쉬운 한국어로 설명된다.

- **AC1.1.3**  
  **Given** 공식 작업·기술 항목이 기준선에 등록되어 있고 `sources/aws-sidebar-index.md`와 `sources/source-registry.yaml`의 공식 링크 인벤토리가 완전성 검사에 통과했을 때  
  **When** 학습자가 도메인 또는 학습 항목을 확인하면  
  **Then** 도메인 README와 목차에서 안정 ID(`AIF-C01-D<n>-T<n>`)를 확인하고, 해당 ID가 있는 학습 문서·문제·복습 자료의 상대 Markdown 링크를 따라 이동할 수 있으며, 각 대상에서 기준선으로 되돌아갈 수 있다.

- **AC1.1.4**  
  **Given** 공식 시험 범위에 없는 실무 확장 내용이 학습 지도에 함께 표시될 때  
  **When** 학습자가 범위 표지를 확인하면  
  **Then** 실무 확장으로 명확히 구분되고 관련 공식 기준선 ID가 먼저 표시되며 공식 출제 범위로 오해할 수 없게 설명된다.

**INVEST 메모**

- **Independent**: 범위·지도 자체를 검토할 수 있고 다른 학습 콘텐츠의 상세 작성과 분리된다.
- **Negotiable**: 탐색 표현과 링크 배치는 협의 가능하나 공식 명칭·비율·순서·표지 규칙은 요구사항으로 고정된다.
- **Valuable**: 학습자가 범위를 빠뜨리지 않고 다음 학습을 선택한다.
- **Estimable**: 기준선·도메인 개요·읽기 경로로 범위가 명확하다.
- **Small**: 시작 안내와 공식 범위 지도로 한정한다.
- **Testable**: AC의 도메인, 비율, ID, 링크, 범위 표지를 검사할 수 있다.

## US1.2 — 4주 상대 학습 경로를 따른다

**스토리**

> As a 처음 시작하는 AIF-C01 학습자(P1), I want 특정 시험일 없이 1주차부터 4주차까지의 학습·복습·평가 계획을 보고 싶다, so that 한 달 이내의 준비를 스스로 진행하고 완료 여부를 확인할 수 있다.

**우선순위**: Must Have  
**요구사항 연결**: FR3.1, NFR1, NFR2, NFR9  
**의존성**: US1.1의 공식 범위 지도  
**관계**: US1.1 `depends on`, US4.1·US4.2 `feeds`  
**범위 분류**: 학습 운영 지원; 시험일이나 합격을 보장하지 않는다.

### Acceptance criteria

- **AC1.2.1**  
  **Given** 학습자가 정해진 시험일을 제공하지 않았을 때  
  **When** 4주 진도표를 열면  
  **Then** 특정 날짜가 아닌 1주차·2주차·3주차·4주차의 상대 일정으로 표시된다.

- **AC1.2.2**  
  **Given** D1→D5와 통합 복습이 학습 계획에 포함되어야 할 때  
  **When** 학습자가 각 주차를 확인하면  
  **Then** 각 주차에 도메인 학습, 복습, 문제 풀이 또는 최종 점검 중 필요한 최소 활동과 완료 기준이 배치되고, 네 주차 전체에서 D1·D2·D3·D4·D5·통합 복습·문제 풀이·최종 점검이 빠짐없이 연결된다.

- **AC1.2.3**  
  **Given** 학습자가 자신의 진도를 외부 서비스에 저장하지 않을 때  
  **When** 주차 계획을 사용하면  
  **Then** 각 활동에 정적 완료 체크 항목과 로컬 수기 사용 안내가 제공되고, 체크 상태는 자동 저장·동기화되지 않으며 계정·답안·진도 데이터를 수집하지 않는다.

- **AC1.2.4**  
  **Given** 학습자가 코드 경험이나 유료 AWS 실습 환경이 없을 때  
  **When** 진도표의 활동을 수행하면  
  **Then** 코드 작성, AWS 계정 생성, 유료 실습 없이 Markdown·문제·정적 워크시트만으로 완료할 수 있다.

**INVEST 메모**

- **Independent**: 범위 지도를 전제로 하지만 진도표는 별도로 검토·사용할 수 있다.
- **Negotiable**: 주차별 문서 배치와 활동량은 Delivery Planning에서 조정한다.
- **Valuable**: 초보자가 준비 기간을 구체적인 행동으로 바꾼다.
- **Estimable**: 네 주차, 활동 종류, 완료 기준이 명시된다.
- **Small**: 상대 일정과 체크리스트에 한정한다.
- **Testable**: 네 주차·활동·완료 체크·비수집 경계를 확인할 수 있다.

## US2.1 — D1부터 D5까지 기초 개념을 이해한다

**스토리**

> As a 처음 시작하는 AIF-C01 학습자(P1), I want 핵심 영어 용어와 개념을 선수 지식 없이 쉬운 설명·예시·비교로 배우고 싶다, so that D1부터 D5의 시험 주제를 서로 연결해 설명할 수 있다.

**우선순위**: Must Have  
**요구사항 연결**: FR2.1~FR2.5, NFR1, NFR2, NFR5, NFR8  
**의존성**: US1.1  
**관계**: US3.1 `enables`, US4.1 `summarized by`, US5.1 `validates`  
**범위 분류**: 공식 범위 개념과 기준선에 연결된 학습자용 해설; 실무 확장은 섹션 수준에서 별도 표지한다.

### Acceptance criteria

- **AC2.1.1**  
  **Given** 학습자가 AI/ML·GenAI 용어를 처음 볼 때  
  **When** D1→D5 문서를 읽으면  
  **Then** 핵심 영어 용어가 최초 등장 시 한국어 설명과 영어 원문으로 제시되고, 선수 지식·한 줄 요약·쉬운 예시가 제공된다.

- **AC2.1.2**  
  **Given** 하나의 문서가 하나의 핵심 개념 또는 밀접한 작은 묶음을 다룰 때  
  **When** 학습자가 문서를 끝까지 읽으면  
  **Then** AWS 관점과 관련 서비스, 비슷한 개념 비교, 실무형 시나리오, 시험 판단 단서, 오해 교정, 확인 질문, 다음 문서 링크를 문서 구조에 따라 확인할 수 있고, 현재 문서·이전 문서·다음 문서가 명시되어 관련 없는 개념이 섞이지 않는다.

- **AC2.1.3**  
  **Given** 문서가 D1부터 D5까지 작성될 때  
  **When** 학습자가 도메인 README를 열면  
  **Then** 각 도메인의 목표, 공식 시험 항목, 선수 지식, 문서 읽기 순서와 다른 도메인으로의 연결을 확인할 수 있고, 기본 경로와 P2용 빠른 비교·약점 보완 링크가 구분된다.

- **AC2.1.4**  
  **Given** 문서에 서비스 선택이나 시나리오 설명이 포함될 때  
  **When** 학습자가 해당 설명을 읽으면  
  **Then** 서비스가 무엇인지, 언제 쓰는지, 무엇과 구분하는지, 시험에서 고르는 단서가 구분되어 제시되고 변할 수 있는 사실은 공식 출처 또는 `확인 필요` 상태와 함께 표시된다.

- **AC2.1.5**  
  **Given** 문서가 이미지나 Mermaid를 선택적으로 사용할 때  
  **When** 학습자가 외부 렌더러 없이 일반 Markdown 뷰어에서 문서를 읽으면  
  **Then** 한국어 alt text·캡션·인접한 단계별 텍스트 설명만으로 노드·분기·순서·결론을 이해할 수 있고, 제목 계층·링크 문구·색상에만 의존하지 않으며, Mermaid 소스나 이미지가 유일한 의미 전달 수단이 아니다.

**INVEST 메모**

- **Independent**: 문서 단위의 학습 가치를 검토할 수 있으며 전체 문제은행 구현에 종속되지 않는다.
- **Negotiable**: 설명 예시와 문서 묶음은 검토 과정에서 조정한다.
- **Valuable**: 초보자가 암기 전에 개념 구조를 이해한다.
- **Estimable**: 도메인 순서와 문서 필수 구조가 명확하다.
- **Small**: 개념 문서와 도메인 README를 하나의 학습 경로로 제한하고, 개별 문서는 더 작게 분해한다.
- **Testable**: 필수 섹션·용어·예시·비교·판단 단서·링크·대체 경로를 검증할 수 있다.

## US3.1 — AWS 서비스 선택과 시나리오 판단을 연습한다

**스토리**

> As a 처음 시작하는 AIF-C01 학습자(P1), I want 목적·제약·비교 대상이 드러나는 AWS 시나리오를 읽고 서비스 선택 단서를 연습하고 싶다, so that 시험 문제에서 비슷한 서비스와 개념 중 적절한 답을 판단할 수 있다.

**우선순위**: Must Have  
**요구사항 연결**: FR2.5, FR2.6, FR4.2, FR4.3, NFR1, NFR3, NFR4, NFR8  
**의존성**: US2.1  
**관계**: US4.2 `assessed by`, US5.1 `constrained by`  
**범위 분류**: 공식 기준선에 연결된 시험 판단과 `실무 확장` 시나리오를 명시적으로 구분한다.

### Acceptance criteria

- **AC3.1.1**  
  **Given** 시나리오에 사용 목적, 입력·출력, 주요 제약, 비교 가능한 서비스 또는 개념이 있을 때  
  **When** 학습자가 판단 단서를 읽으면  
  **Then** `목적 → 입력/출력 → 제약 → 비교 대상 → 선택·제외 근거` 순서로 왜 특정 서비스·개념을 선택하거나 제외하는지 초보자가 따라갈 수 있는 설명을 확인할 수 있다.

- **AC3.1.2**  
  **Given** 문제·시나리오가 공식 작업·기술 기준선에 연결될 때  
  **When** 학습자가 문항 메타데이터를 확인하면  
  **Then** 도메인, 안정 기준선 ID, 공식 출처 URL·제목, 기준선 `revision_title`, 확인 날짜, 출처 접근 상태, 난이도, `시험 범위` 또는 `실무 확장` 분류가 고정된 문항 스키마로 제공된다.

- **AC3.1.3**  
  **Given** AWS 기능·모델명·요금·리전·할당량처럼 변할 수 있는 사실이 답의 근거가 될 때  
  **When** 문항 또는 해설이 작성되거나 검토되면  
  **Then** 확인된 공식 출처와 확인 날짜·접근 상태가 연결되거나, 확인 전까지 문항·해설이 `blocked`·`확인 필요` 또는 `review`로 표시되고 `verified` 자료에 포함되지 않는다.

- **AC3.1.4**  
  **Given** 오답 선택지가 포함된 시나리오 문항이 있을 때  
  **When** 학습자가 정답 해설을 확인하면  
  **Then** 오답이 왜 현재 단서와 맞지 않는지 설명되어 단순한 정답 암기로 끝나지 않는다.

**INVEST 메모**

- **Independent**: 개념 문서가 제공하는 용어를 사용하지만 시나리오 묶음 자체를 별도로 검토할 수 있다.
- **Negotiable**: 시나리오 표현과 예시 수는 조정 가능하나 기준선·출처·범위 표지는 필수다.
- **Valuable**: 시험의 단서 기반 판단과 AWS 서비스 구분을 연습한다.
- **Estimable**: 문항 필드와 시나리오 판단 구조가 정의되어 있다.
- **Small**: 서비스 선택과 기본 시나리오 판단에 한정하며 실습 환경 구축은 포함하지 않는다.
- **Testable**: 시나리오 단서, 정답·오답 해설, 출처, 범위 분류를 확인할 수 있다.

## US4.1 — 복습 자료로 핵심 용어와 혼동 지점을 반복한다

**스토리**

> As a 처음 시작하는 AIF-C01 학습자(P1), I want 도메인별 카드·용어 사전·퀴즈·Anki 자료로 핵심 용어와 혼동하기 쉬운 선택 기준을 반복하고 싶다, so that 긴 문서를 다시 읽지 않고 약점을 보완할 수 있다.

**우선순위**: Should Have  
**요구사항 연결**: FR3.2, FR3.3, FR3.4, NFR1, NFR3, NFR6, NFR8  
**의존성**: US2.1, 일부 항목은 US3.1  
**관계**: US4.2 `supports`, US1.2 `scheduled in`  
**범위 분류**: 공식 기준선에 연결된 복습 지원 자료; 해설·예시는 별도 범위 표지를 유지한다.

### Acceptance criteria

- **AC4.1.1**  
  **Given** 각 도메인의 핵심 용어와 혼동 지점이 학습 문서에 정의되어 있을 때  
  **When** 학습자가 카드·용어 퀴즈·용어 사전을 열면  
  **Then** 한국어 설명, 영어 원문, 관련 문서 링크, 기준선 ID 또는 원본 출처, 자료 안정 ID가 서로 추적되고, 각 도메인에 최소 하나의 카드 매핑과 하나의 용어 퀴즈 매핑이 존재한다.

- **AC4.1.2**  
  **Given** 학습자가 반복 학습을 위해 Anki를 사용하려 할 때  
  **When** UTF-8 CSV를 가져오면  
  **Then** 필수 헤더 `front,back`과 추적 필드의 열 구조가 고정되고, UTF-8 인코딩·구분자·큰따옴표 quoting·쉼표와 줄바꿈이 포함된 값·개행을 일반 CSV 파서로 읽을 수 있으며, 각 행에 원본 문서 또는 출처와 기준선 연결 정보가 있다.

- **AC4.1.3**  
  **Given** 한 학습 문서에 핵심 용어가 포함되어 있을 때  
  **When** 핵심 용어 inventory와 복습 자료의 누락 검사를 수행하면  
  **Then** 해당 용어가 `glossary.md`, 카드 또는 용어 퀴즈 중 하나 이상으로 연결되고, 확인된 기준선 행·학습 문서·도메인의 최소 매핑과 양방향 링크가 충족되며 고아 복습 항목이 남지 않는다.

- **AC4.1.4**  
  **Given** 복습 자료가 공식 시험 범위와 실무 확장을 함께 요약할 때  
  **When** 학습자가 카드·퀴즈·Anki 행을 보면  
  **Then** 각 항목 수준에서 `시험 범위` 또는 관련 기준선 ID가 있는 `실무 확장`이 표시되어 둘을 혼동하지 않는다.

**INVEST 메모**

- **Independent**: 하나의 도메인 또는 용어 묶음으로 검토 가능하고 문제은행 전체가 없어도 가치가 있다.
- **Negotiable**: 카드 형식과 Anki의 부가 필드는 호환성 검토 후 조정한다.
- **Valuable**: 반복 학습 비용을 줄이고 용어 혼동을 드러낸다.
- **Estimable**: 카드·사전·퀴즈·CSV의 필수 연결 필드가 정해져 있다.
- **Small**: 복습 자료 생성·연결에 한정하며 자동 학습 서비스는 만들지 않는다.
- **Testable**: 도메인별 매핑, 용어 연결, CSV 인코딩·필드, 범위 표지를 검사할 수 있다.

## US4.2 — 문제은행과 정적 점수 워크시트로 준비도를 점검한다

**스토리**

> As a 처음 시작하는 AIF-C01 학습자(P1), I want 전 범위를 다루는 100문항 이상의 문제은행과 정적 점수 워크시트를 사용하고 싶다, so that 첫 전체 풀이의 결과로 약점과 합격 준비 참고 수준을 확인할 수 있다.

**우선순위**: Must Have  
**요구사항 연결**: FR4.1~FR4.5, FR3.1, NFR3, NFR4, NFR6, NFR7, NFR8, NFR9  
**의존성**: US1.1, US2.1, US3.1; 복습 자료는 선택적 보조 입력이다.  
**관계**: US4.1 `supports`, US5.1 `quality-gates`  
**범위 분류**: 자체 제작 문제은행은 `시험 범위`와 기준선 연결을 우선하고, 문제 형식·학습 해설은 가이드 작성 자료다.

### Acceptance criteria

- **AC4.2.1**  
  **Given** 공식 기준선 행과 도메인별 문제 분포가 확정되어 있을 때  
  **When** 학습자가 문제은행을 열면  
  **Then** 고유 문항 ID가 `N >= max(100, 확인된 기준선 행 수)`를 만족하고, 확인된 각 기준선 행에 최소 하나의 문항이 연결되며 추가 문항은 항목별 최소 커버리지 후 공식 도메인 가중치를 따른다.

- **AC4.2.2**  
  **Given** 학습자가 한 문항을 풀 때  
  **When** 문항과 해설을 확인하면  
  **Then** 고정된 문항 스키마에 문항 ID, 도메인, 공식 기준선 ID, 질문, 모든 선택지, 정답, 해설, 공식 출처 URL·제목, 기준선 revision·확인 날짜·접근 상태, 난이도, 범위 분류가 포함되고 대상 기준선으로 되돌아갈 수 있다.

- **AC4.2.3**  
  **Given** 학습자가 문제은행 전체를 첫 번째로 풀 때  
  **When** 정적 워크시트에 결과를 기록하면  
  **Then** 전체 문항 수, 정답 수, 미응답 수, `정답률 = 정답 문항 수 / 전체 문항 수 × 100`, 소수 첫째 자리 반올림, 80% 이상을 참고 지표로 해석하는 안내가 제공된다.

- **AC4.2.4**  
  **Given** 학습자가 문제를 다시 풀거나 문항 최종 검토를 수행할 때  
  **When** 재시도 또는 품질 결과를 기록하면  
  **Then** 재시도 점수는 별도 행에 기록되어 첫 전체 풀이 지표를 대체하지 않고, 모든 문항에 대해 정답 타당성·각 오답 선택지 타당성·난이도·중복 여부를 각각 `통과|실패|보류`로 판정한 검토 증거와 실패 항목의 수정·재검사 결과가 남으며, 점수 기록과 사실 정확성 검토는 별도로 관리된다.

- **AC4.2.5**  
  **Given** 학습자가 자신의 답안·진도·계정 정보를 외부에 제출하지 않을 때  
  **When** 워크시트를 사용하면  
  **Then** 자료는 로컬 수기 기록용 정적 Markdown이고 답안·개인정보·자격 증명·결제정보를 수집하거나 저장하지 않는다.

**INVEST 메모**

- **Independent**: 문제은행과 워크시트는 정적 산출물로 별도 검토 가능하다.
- **Negotiable**: 문제의 표현과 도메인별 추가 배분은 기준선 등록 후 검토로 조정한다.
- **Valuable**: 학습자가 전 범위 판단을 연습하고 준비도 참고 지표를 얻는다.
- **Estimable**: 최소 문항 수, 필수 필드, 점수 산식과 기록 규칙이 명확하다.
- **Small**: 문제 풀이와 정적 기록에 한정하고 답안 저장 시스템은 만들지 않는다.
- **Testable**: 문항 수·필드·매핑·산식·미응답·재시도·비수집 경계를 검증할 수 있다.

## US5.1 — 출처·범위·최신성·접근성을 확인하며 학습한다

**스토리**

> As a 비교 학습자(P2), I want 각 학습 자료의 공식 출처·확인 날짜·상태·범위 표지와 읽기 가능한 대체 설명을 확인하고 싶다, so that 기존 AWS 지식과 오래된 정보에만 의존하지 않고 믿을 수 있는 내용으로 학습할 수 있다.

**우선순위**: Must Have  
**요구사항 연결**: FR1.1~FR1.4, FR5.1~FR5.4, FR6.1~FR6.4, NFR1~NFR9  
**의존성**: US1.1, US2.1; 다른 스토리를 횡단 검증한다.  
**관계**: 모든 스토리 `quality constraint`, US4.2 `gates`  
**범위 분류**: 출처·품질·최신성 보장에 대한 학습자 가치. 내부 작성 절차 자체를 별도 사용자 기능으로 만들지 않는다.

### Acceptance criteria

- **AC5.1.1**  
  **Given** 학습 자료나 파생 복습·문항 자료가 외부 사실을 포함할 때  
  **When** 학습자가 자료를 확인하면  
  **Then** 공식 URL, 공식 문서 제목, 출처 유형·상위 주제·도메인, 확인 날짜, 접근 상태, 기준선 `revision_title`과 연결 문서를 확인할 수 있고, `sources/aws-sidebar-index.md`의 전체 링크와 `sources/source-registry.yaml`의 모든 사용 URL이 서로 대조되어 누락이 없으며 문서 front matter의 `source_urls`, `source_checked`, `status`가 허용된 값으로 표시된다.

- **AC5.1.2**  
  **Given** 공식 시험 범위와 실무 확장이 한 자료에 함께 존재할 때  
  **When** 학습자가 섹션·문항·카드·퀴즈·Anki 행을 확인하면  
  **Then** 항목 수준의 `시험 범위` 또는 관련 공식 기준선 ID를 앞세운 `실무 확장` 표지가 있으며, 원문을 통째로 재배포하지 않고 한국어로 재구성했음과 필요한 짧은 인용의 공식 링크를 확인할 수 있고 공식 출제 범위로 단정하지 않는다.

- **AC5.1.3**  
  **Given** 출처가 차단되었거나 동적 내용으로 확인되지 않을 때  
  **When** 해당 사실이 자료에 필요하면  
  **Then** `blocked` 또는 `확인 필요` 상태, 차단 사유, 영향받는 자료와 후속 확인 대상이 기록되고 미확인 내용은 `verified`로 표시되지 않는다.

- **AC5.1.4**  
  **Given** 문서·문항·복습 자료가 검토될 때  
  **When** 품질 검사 결과를 확인하면  
  **Then** 초보자 관점, 개념 단위, 민감정보, 공식 항목 누락, 링크·제목, 문항 메타데이터, 범위 구분 검사가 각각 `통과|실패|보류`와 대상 범위·검사일·검사자 또는 도구·근거·수정/후속 조치·재검사 결과를 갖고, 학습자가 도메인 README 또는 시작 문서의 검증 보고서 링크와 `draft|review|verified`, `blocked|확인 필요` 상태 의미를 확인할 수 있다.

- **AC5.1.5**  
  **Given** Markdown, 이미지 또는 Mermaid가 자료에 포함될 때  
  **When** 학습자가 일반 Markdown 뷰어 또는 GitHub-Flavored Markdown 환경에서 읽으면  
  **Then** 논리적 제목 계층·대상 문서를 설명하는 링크 문구·한국어 alt text·캡션 또는 인접한 텍스트 대체 경로로 핵심 내용을 이해할 수 있고, 외부 렌더러·색상·이미지·도형에만 의존하지 않으며 모바일에서 핵심 판단 정보가 가로 표에만 남지 않는다.

- **AC5.1.6**  
  **Given** 예시·로그·출처 메타데이터·CSV·변경 파일을 점검할 때  
  **When** 민감정보 검사를 수행하면  
  **Then** 실제 계정 식별자·토큰·자격 증명·개인정보가 없음을 확인하고, 발견 시 제거·치환·보류와 재검사 결과를 기록한다.

**INVEST 메모**

- **Independent**: 하나의 콘텐츠 묶음에 대한 신뢰성·접근성 검토로 독립적으로 확인할 수 있다.
- **Negotiable**: 검토 기록의 배치와 도구는 협의 가능하나 출처·상태·범위·접근성 증거는 필수다.
- **Valuable**: P1과 P2 모두 오래되거나 범위를 벗어난 내용을 공식 지식으로 오해하지 않는다.

## Delivery Planning 인계와 구현 단위

사용자 스토리 ID는 학습자 가치 경계로 유지하고, 다음 단계에서 아래 구현·검증 단위로 분해한다.

- **기준선 선행 단위**: D1 집필 전에 공식 시험 안내서의 revision/title, 5개 도메인, 비율, 작업·기술 행, `AIF-C01-D<n>-T<n>` ID를 등록하고 `sources/aws-sidebar-index.md`·`sources/source-registry.yaml`의 URL·제목·유형·상위 주제·도메인·확인일·접근 상태·연결 문서를 완성한다.
- **D1~D5 단위**: 각 도메인마다 README, 개념 문서, 용어 inventory, 기준선 양방향 매핑, 카드·퀴즈·Anki, 도메인 문항과 초보자·링크·접근성 검사를 함께 검증한다. 작성 순서는 D1→D2→D3→D4→D5다.

- **문제은행 단위**: D1~D5 또는 기준선 행 묶음별로 문항을 작성하고, 전체 수량은 `N >= max(100, 확인된 기준선 행 수)`로 계산한다. 최종 일괄 검토는 정답·오답 타당성·난이도·중복을 각각 판정한다.
