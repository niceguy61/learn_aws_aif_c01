# 사용자 페르소나 통합 초안

> 상태: `draft`  
> 통합 확인: `Looks correct` (2026-09-04)  
> 목적: 승인된 요구사항과 User Stories의 사용자 관점을 정의한다. 이 파일은 콘텐츠 작성자·유지관리자를 별도 최종 사용자 페르소나로 만들지 않는다.

## 페르소나 우선순위

| 우선순위 | ID | 이름 | 역할 | 사용 맥락 |
|---|---|---|---|---|
| 1 | P1 | 처음 시작하는 AIF-C01 학습자 | AI/ML과 AWS를 처음 접하는 수험생 | 4주 상대 일정으로 한국어 학습 자료를 읽고 문제를 푼다 |
| 2 | P2 | AWS 경험이 있는 비교 학습자 | AWS 핵심 서비스 경험은 있지만 AI/ML·GenAI가 익숙하지 않은 수험생 | 이미 아는 AWS 개념과 AIF-C01 개념의 차이를 빠르게 비교하고 빈틈을 찾는다 |

## P1 — 처음 시작하는 AIF-C01 학습자

- **역할**: AI/ML, 생성형 AI, 파운데이션 모델, AWS를 처음 배우는 완전 초보 수험생
- **목표**
  - 공식 AIF-C01 5개 도메인의 범위와 학습 순서를 이해한다.
  - 쉬운 설명과 예시를 통해 핵심 개념을 이해하고, AWS 서비스 선택 단서와 시나리오 판단으로 연결한다.
  - 카드·용어 사전·퀴즈·문제은행으로 복습하고 자신의 준비 상태를 정적으로 점검한다.
- **문제점**
  - 비슷한 AI/ML 용어와 AWS 서비스의 차이를 처음부터 스스로 정리하기 어렵다.
  - 공식 시험 범위와 실무에서 유용하지만 시험 범위가 아닐 수 있는 내용을 구분하기 어렵다.
  - 코드 실습이나 유료 AWS 계정 없이도 시험형 판단을 연습할 자료가 부족하다.
- **기술 친숙도**: 낮음
- **사용 빈도**: 4주 동안 주 4~6회, 짧은 학습 세션과 복습 세션을 반복한다.
- **성공 신호**
  - 현재 학습 위치와 다음 문서를 스스로 선택할 수 있다.
  - 문제의 단서를 보고 개념, 서비스, 책임 있는 AI, 보안·거버넌스 중 무엇을 판단해야 하는지 설명할 수 있다.
  - 전체 문제은행의 첫 풀이 정답률을 정적 워크시트에 기록하고 80% 지표의 의미와 한계를 이해한다.

## P2 — AWS 경험이 있는 비교 학습자

- **역할**: AWS 핵심 서비스를 사용해 본 경험이 있으나 AIF-C01 전 범위와 AI/ML 개념은 완전히 익히지 않은 수험생
- **목표**
  - 기존 AWS 지식과 AI/ML·GenAI 개념을 연결하고, 시험에서 요구하는 구분 기준을 빠르게 확인한다.
  - 공식 범위, 실무 확장, 최신성 상태를 구분해 불필요한 학습과 오래된 기억에 의존하는 판단을 줄인다.
  - 자신의 약한 도메인과 혼동하기 쉬운 서비스 선택을 문제·카드·퀴즈로 반복한다.
- **문제점**
  - AWS 서비스 경험이 있어도 시험 문맥의 모델·책임 있는 AI·거버넌스 판단은 별도 정리가 필요하다.
  - 이미 아는 서비스 설명과 AIF-C01에서 요구하는 초보자용 선택 단서의 차이를 놓칠 수 있다.
  - 서비스 기능과 모델명처럼 변할 수 있는 사실을 예전 지식으로 단정할 위험이 있다.
- **기술 친숙도**: 중간
- **사용 빈도**: 시험 준비 기간에 주 2~4회, 비교 학습과 약점 보완 중심으로 사용한다.
- **성공 신호**
  - P1용 설명을 건너뛰지 않고 필요한 부분만 선택해 D1→D5 범위의 빈틈을 찾을 수 있다.
  - AWS 서비스 선택 문제에서 목적, 제약, 비교 대상, 최신성 표시를 함께 확인한다.
  - 출처와 범위 표지를 확인한 뒤 공식 시험 범위와 실무 확장을 구분해 설명한다.

## 페르소나 관계와 적용 원칙

- P1이 모든 핵심 학습 여정과 Must Have 가치의 기준이다. 문서가 P1에게 이해되지 않으면 P2의 빠른 비교도 성공으로 보지 않는다.
- P2는 P1과 동등한 독립 학습 경로를 요구하는 페르소나가 아니다. AWS 배경지식이 있는 독자가 비교·약점 보완을 수행할 수 있는지 확인하는 보조 관점이며, P1의 쉬운 설명과 기본 경로를 생략하지 않는다.
- 제품 소유자, 콘텐츠 작성자, 출처 검토자의 운영 관심사는 별도 최종 사용자 페르소나로 정의하지 않는다. 필요한 경우 학습자에게 보이는 출처 신뢰성, 범위 구분, 접근성, 복습 가능성의 acceptance criteria와 검증 증거로만 표현한다.
- 두 페르소나 모두 코드 작성, 유료 AWS 실습, AWS 계정 생성, 프로덕션 시스템 구축, 학습자 데이터 저장을 요구하지 않는다.

## 페르소나 적용과 추적성 메모

- 모든 사용자 스토리는 P1 또는 P2 중 하나를 명시한다.
- 공식 시험 범위는 `시험 범위`로, 관련 실무 판단은 원래 공식 기준선 ID를 먼저 표시한 `실무 확장`으로 구분한다.
- 도메인 흐름은 D1→D2→D3→D4→D5 순서를 기본으로 하며, 문제·복습 자료의 탐색은 이 순서를 보완할 뿐 대체하지 않는다.
- 다음 단계의 `traceability.json`은 이 페르소나 ID와 `US`·`AC` ID를 요구사항 ID 및 후속 설계·단위·검증 산출물과 연결한다.
