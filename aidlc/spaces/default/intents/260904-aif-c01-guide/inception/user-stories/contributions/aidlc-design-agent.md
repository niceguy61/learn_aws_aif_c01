## Contribution

### 종합 판단

`personas.md`와 `stories.md`는 완전 초보자(P1)를 우선하고, AWS 경험이 있는 비교 학습자(P2)를 보조 관점으로 둔 점에서 요구사항과 잘 맞는다. US1.1에서 범위 확인을 시작하고 US1.2의 상대 일정, US2.1의 개념 학습, US3.1의 판단 연습, US4.1·US4.2의 복습·평가로 이어지는 흐름도 초보자의 학습 부담을 단계적으로 높이는 방향이다.

다만 이 제품은 실행형 학습 애플리케이션이 아니라 정적 Markdown·CSV 산출물이다. 따라서 `선택`, `이동`, `현재 위치`, `완료`, `상태 확인`을 실제 UI 기능처럼 해석하지 않도록 Markdown 링크·목차·체크리스트·상태 표지로 구체화해야 한다. 다음 단계에서 이 점을 반영하면 UX 관점에서 조건부 승인할 수 있다.

### 페르소나 충실도

- P1의 낮은 기술 친숙도, 짧은 반복 학습 세션, 코드·유료 AWS 실습 없이 학습하려는 목표가 명확하다. P1을 모든 핵심 여정의 기준으로 둔 원칙도 적절하다.
- P2를 별도 제품 흐름이 아니라 비교·약점 보완 관점으로 둔 결정은 Q1=C와 일치한다. P2 때문에 초보자 설명을 생략하거나 전문 용어 중심으로 바꾸지 않아야 한다.
- US4.1의 `P1, P2 관점` 표현은 P1이 주 페르소나이고 P2는 검토 관점이라는 점을 더 명시하는 편이 좋다. 그렇지 않으면 두 페르소나가 동등한 학습 경로를 요구하는 것으로 읽힐 수 있다.
- 제품 소유자·콘텐츠 작성자·품질 검토자를 최종 사용자 페르소나로 만들지 않은 것은 사용자 가치와 운영 작업을 분리한다는 점에서 타당하다. 다만 출처·접근성 검증의 결과는 학습자가 읽을 수 있는 상태 표지와 설명으로 노출되어야 한다.

### 초보자 학습 여정

- D1→D5 순서는 선수 지식을 쌓는 기본 경로로 적절하다. 그러나 초보자는 한 문서에서 멈추거나 이전 개념으로 돌아갈 수 있으므로 각 문서에 `현재 위치`, `이전 문서`, `다음 문서`, `이 문서를 건너뛰지 말아야 하는 선수 개념`을 일관된 형식으로 제공할 것을 권고한다.
- US1.1의 학습 지도와 US1.2의 4주 계획은 방향을 제시하지만, 학습자가 “지금 무엇을 해야 하는가”를 즉시 판단하는 완료 기준이 문서마다 동일하게 보이지 않는다. 각 주차와 개념 문서에 `읽기 → 스스로 답하기 → 관련 문제 풀기 → 다음으로 이동`의 짧은 행동 순서를 추가하는 것이 좋다.
- P2의 빠른 비교 요구를 지원하되 P1의 순차 경로를 깨지 않도록, 도메인 README에 `기본 경로`와 `빠른 복습 경로`를 분리해 표시하는 방안을 권고한다. 빠른 복습은 문서 생략이 아니라 핵심 정리·비교·확인 질문으로 이동하는 보조 링크여야 한다.
- 빈 학습 자료, 출처 확인 보류, 링크 오류 같은 비정상 상태도 학습 흐름의 일부다. 해당 문서가 없거나 `blocked`인 경우에는 이유, 학습자가 할 수 있는 다음 행동, 대체 문서 또는 재확인 필요를 보여 주어야 하며 빈 목록이나 막힌 링크만 남겨서는 안 된다.

### 가독성·접근성

- AC2.1.5와 AC5.1.5가 이미지·Mermaid의 텍스트 대체 경로를 요구하는 것은 적절하다. 다만 “핵심 의미를 이해할 수 있다”를 검증하려면 대체 설명이 그림 옆 또는 바로 아래에 항상 보이고, 외부 렌더러·색상·도형·범례를 보지 않아도 순서와 관계를 읽을 수 있어야 한다는 조건을 명시할 필요가 있다.
- 복잡한 도표나 흐름도는 짧은 `alt`만으로 충분하지 않을 수 있다. `alt`에는 목적을 간결하게 쓰고, 본문에 단계·분기·결론을 일반 텍스트로 별도 제공하도록 권고한다. Mermaid 소스 자체를 유일한 대체 경로로 취급하지 않는다.
- 제목은 `h1`에서 시작해 논리적으로 내려가고, 표·목록·링크의 의미가 마크업 구조에 보존되어야 한다. 링크 문구는 “여기”가 아니라 대상 문서 제목이나 학습 행동을 나타내야 한다.
- 범위 상태, 출처 상태, 정답·오답, 난이도를 색상만으로 구분하지 말고 `시험 범위`, `실무 확장`, `확인 필요`, `blocked`, `정답` 같은 텍스트와 필요 시 아이콘을 함께 사용해야 한다. 색상 대비와 키보드 포커스는 Markdown 뷰어가 제공하더라도, 작성자는 색상만을 의미 전달 수단으로 설계하지 않아야 한다.
- 모바일에서 표가 가로로 잘려 핵심 판단을 숨기지 않도록 열 수를 줄이고, 긴 비교표는 항목별 소제목·목록 또는 세로형 구조로 대체할 수 있어야 한다. 이는 NFR2의 일반 Markdown·GitHub-Flavored Markdown 호환성과도 일치한다.

### 사용자 가치 중심의 acceptance criteria 검토

- US1.1~US4.2의 기준 대부분은 학습자가 얻는 결과를 확인할 수 있어 강점이 있다. 특히 오답 해설, 첫 풀이와 재시도 분리, 비수집 경계는 실제 학습 경험을 보호한다.
- AC1.1.3의 “도메인 또는 학습 항목을 선택하면 이동”은 실행형 탐색을 암시한다. 정적 산출물에서는 “도메인 README와 항목별 링크/목차에서 안정 ID를 확인하고, 링크를 따라 연결된 문서·문제·복습 자료로 이동한다”로 표현하는 편이 사용자 가치와 구현 경계를 모두 명확히 한다.
- AC1.2.3의 정적 완료 체크는 유용하지만, 체크가 저장·동기화되지 않는다는 사실과 학습자가 체크를 지우거나 재시작할 수 있다는 사용 지침도 함께 제공해야 한다. 그렇지 않으면 초보자가 완료 상태가 자동 보존된다고 오해할 수 있다.
- AC4.1.2의 일반 CSV 파서 검사는 필요하지만 사용자 가치로는 충분하지 않다. Anki 가져오기 안내에 구분자, UTF-8, 앞면·뒷면 필드, 줄바꿈·쉼표가 들어간 카드의 보존, 가져오기 실패 시 확인 방법을 명시하고, 추적성 필드는 학습자가 읽을 수 있는 형태로 제공해야 한다.
- AC5.1.4는 품질 검사 결과를 정의하지만 내부 검토 기록에 머물 위험이 있다. 학습자에게 보이는 문서 상태, 출처 확인일, `verified|review|draft`, `blocked|확인 필요`의 의미와 학습 시 주의사항을 연결해야 acceptance가 사용자 신뢰 가치로 완성된다.
- AC3.1.1의 서비스 선택 설명은 단순히 “왜 선택하거나 제외하는지”에 더해, 문제를 읽을 때 먼저 확인할 단서의 순서를 제공하면 초보자에게 실질적인 판단 도구가 된다. 예: 목적 → 입력/출력 → 제약 → 비교 대상 → 답의 근거.

### Mermaid·이미지·텍스트 대체에 대한 구체적 입장

- Mermaid와 이미지는 선택 사항으로 유지해도 된다. 문서 이해에 반드시 필요한 관계나 순서는 먼저 일반 텍스트 또는 번호 목록으로 작성하고, 시각 자료는 그 내용을 보강하는 보조 수단으로만 사용해야 한다.
- 모든 비장식 이미지는 한국어 `alt`를 갖고, 복잡한 다이어그램은 인접한 장문 설명 또는 단계별 목록을 갖는다. 장식 이미지는 의미 없는 경우에만 빈 `alt`를 사용한다.
- Mermaid를 사용할 때는 동일 파일 안에 다이어그램의 목적, 노드·분기 관계, 최종 결론을 텍스트로 설명한다. 렌더링 실패 시 원본 코드만 보이는 상태를 성공으로 판정하지 않는다.
- AWS 공식 이미지와 가이드 작성 도표는 표지와 출처를 분리한다. 공식 이미지는 공식 출처 링크를, 작성 도표는 `가이드 작성 도표` 표지를 갖고 동일한 텍스트 설명을 제공해야 한다.
- 색상, 화살표 방향, 아이콘 모양만으로 정답·상태·순서를 전달하지 않는다. 텍스트 레이블과 문서의 제목 계층이 동일한 정보를 전달해야 한다.

### 권고하는 후속 확인 항목

1. US1.1·US1.2·US2.1의 acceptance criteria에 정적 Markdown 기준의 `이전/현재/다음` 탐색, 완료 체크의 로컬·비동기 특성, 출처 보류 시 대체 행동을 추가한다.
2. US4.1의 페르소나 표기를 `P1 주 사용 경로, P2 비교 검토 관점`으로 정리한다.
3. AC1.1.3을 링크·목차 기반의 정적 탐색으로 구체화하고, AC5.1.4에 학습자에게 보이는 상태 설명을 추가한다.
4. AC2.1.5·AC5.1.5에 제목 계층, 링크 문구, 색상 비의존, 복잡한 도표의 인접 장문 설명, Mermaid 렌더링 실패 시 텍스트 경로를 명시한다.
5. 문항·카드·Anki 자료의 긴 텍스트와 모바일 표 레이아웃을 검토 항목에 포함한다. 핵심 판단 정보가 가로 스크롤이나 색상 구분에만 의존하지 않아야 한다.

## Positions

- **Persona fidelity:** `조건부 승인`. P1 우선·P2 보조 구조는 승인한다. US4.1에서 P2가 독립적인 동일 경로로 오해되지 않도록 역할 문구를 보완해야 한다.
- **Beginner journey:** `조건부 승인`. D1→D5 및 4주 상대 일정은 적절하다. 문서 간 이전/현재/다음 탐색, 주차별 행동 순서, 보류·빈 상태의 회복 경로를 acceptance criteria에 추가해야 한다.
- **Readability/accessibility:** `조건부 승인`. 한국어·개념 단위·alt text·텍스트 대체 요구는 적절하다. 제목 계층, 링크 문구, 색상 비의존, 모바일 표, 복잡한 도표의 장문 설명을 명시해야 한다.
- **User-visible acceptance criteria:** `조건부 승인`. 대부분 사용자 가치에 연결되지만 AC1.1.3, AC4.1.2, AC5.1.4에 정적 산출물 경계와 학습자에게 보이는 결과를 더 구체화해야 한다.
- **Mermaid/image/text fallback:** `승인(조건부 명확화)`. 외부 렌더러 의존을 피하는 방향은 적절하다. 텍스트가 선행·인접하고, Mermaid·이미지가 정보의 유일한 전달 수단이 아니며, 공식 이미지와 가이드 작성 도표가 구분된다는 조건을 acceptance criteria에 명시할 것을 권고한다.
- **Overall design position:** `조건부 승인 — 위 5개 후속 확인 항목 반영 권고`.
