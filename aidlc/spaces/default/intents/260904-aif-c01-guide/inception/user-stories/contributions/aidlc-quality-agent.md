### 품질 판정 요약

현재 초안은 사용자 가치, Given/When/Then 형식, 안정 ID, MoSCoW, 요구사항 연결, 학습자 데이터 비수집 경계를 전반적으로 잘 정의했다. 특히 각 스토리의 acceptance criteria가 정적 Markdown·CSV와 링크·메타데이터 검사로 검증될 수 있도록 작성된 점은 적절하다.

다만 `READY`로 보기 전에 다음 네 가지를 보완해야 한다.

1. 공식 사이드바 전체 링크와 출처 등록부의 완전성은 현재 acceptance criteria에서 명시적으로 검증되지 않는다.
2. FR4.4의 문항별 정답·오답 선택지·난이도·중복 일괄검토가 문항 메타데이터 검사로 축약되어 있어, 필수 품질 증거가 약하다.
3. FR5.4의 원문 재배포 방지와 FR6.3의 변경 출처·검토 기록 보존이 사용자 스토리의 검증 조건으로 충분히 드러나지 않는다.
4. 공식 시험 안내서의 revision/title·확인일과 source access status를 자료별로 연결하는 방식, 그리고 문항·복습 자료의 허용 필드가 고정되어 있지 않아 자동 검사가 구현 단계에서 해석에 의존할 수 있다.

위 항목은 범위나 페르소나를 다시 정하는 반대 의견이 아니라, 추적 가능한 품질 게이트를 만들기 위한 보완 요구다.

### FR/NFR 커버리지 검사

`stories.md`의 상위 요구사항 매핑은 FR1~FR6 및 NFR1~NFR9를 모두 한 번 이상 연결하고 있어 고아 상위 요구사항은 발견되지 않았다. 그러나 아래 세부 요구사항은 현재 매핑 표에 이름은 있으나 acceptance criteria가 직접 증명하지 못한다.

- **FR1.4**: `sources/aws-sidebar-index.md`에 사이드바 링크를 누락 없이 등록하고, `source-registry.yaml`에 제목·유형·상위 주제·도메인·확인일·접근 상태·연결 문서를 등록하는 양방향 완전성 검사가 필요하다.
- **FR3.2**: 각 도메인의 카드 및 용어 퀴즈 최소 매핑과 각 확인된 기준선 행의 복습 연결을 명시해야 한다. 현재 AC4.1.1은 핵심 용어 설명·연결을 말하지만 최소 커버리지 조건이 직접적이지 않다.
- **FR4.4**: 최종 일괄 검토가 반드시 `정답`, `오답 선택지 타당성`, `난이도`, `중복 여부` 각각의 판정과 수정 상태를 남겨야 한다. “문항 메타데이터”만으로는 이 네 검사를 통과했다고 판정할 수 없다.
- **FR5.4**: 원문 전체 복사 금지, 한국어 재구성, 필요한 짧은 인용과 인용 링크의 존재를 출처 검토 증거로 추가해야 한다.
- **FR6.3**: 도메인 완료 기록에 변경된 문서, 변경된 출처, 추적성 변경, 검사 결과, 날짜가 남는다는 조건이 필요하다.
- **FR6.4**: AC5.1.4가 세 가지 필수 검사(초보자 관점·개념 단위·민감정보)를 언급하므로 방향은 맞다. 각 검사에 대상 범위·검사일·판정·근거·조치·재검사 상태가 있음을 필드 수준에서 고정해야 한다.

NFR1~NFR9는 스토리 전반에 연결되어 있으나, NFR2와 NFR6의 자동 검증 세부가 추가로 필요하다. NFR2에는 제목 계층, 내부 링크 대상, 한국어 alt text, 이미지 없이 의미를 전달하는 텍스트 대체 경로의 검사 방법과 수동 표본 검토를 정의한다. NFR6에는 UTF-8 판별, CSV 일반 파서 성공, 헤더·열 수·quoting 검사를 고정한다.

### 출처·버전·접근성 증거

- 기준선의 `revision_title`, 공식 시험 안내서 URL, 확인일, 상태를 하나의 기준선 manifest에서 고정하고, 모든 문항·문서·카드·퀴즈·Anki 행이 기준선 ID를 통해 해당 revision으로 역추적되게 해야 한다. 날짜만 있으면 페이지 개정 여부를 재현하기 어렵다.
- `source-registry.yaml`의 접근 상태(`discovered`, `downloaded`, `summarized`, `reviewed`, `verified`, `blocked`)와 문서 front matter의 상태(`draft`, `review`, `verified`)는 서로 다른 상태라는 점을 schema와 검사 규칙에 명시해야 한다. `verified` 문서가 `blocked` 출처의 미확인 주장에 의존하지 않는다는 cross-file 검사가 필요하다.
- 동적 페이지 또는 접근 차단 출처는 차단 사유·영향 자료·대체 공식 출처·재확인 대상을 갖고, 해당 자료는 `verified`로 승격되지 않아야 한다. AC5.1.3은 이 방향을 포함하므로 영향 매핑의 필수 필드를 추가한다.
- 접근성은 일반 Markdown/GFM 호환으로 한정한다는 요구사항과 일치한다. 자동 링크/heading 검사만으로 충분하다고 보지 말고, 각 도메인의 대표 문서와 이미지/도표 포함 문서에 대해 alt text, 캡션 또는 텍스트 대체 경로를 수동 표본 확인한다. 색상이나 외부 렌더러만으로 의미가 전달되는 자료는 실패다.

### 사용자 가시 품질과 데이터 비수집 검증

각 스토리는 학습자 데이터 없이 정적 산출물로 검증할 수 있다.

- **US1.1, US2.1, US3.1, US4.1, US5.1**: 파일·front matter·링크·CSV·추적표·검토 보고서의 정적 검사로 검증한다.
- **US1.2**: 4주 표와 완료 체크의 존재 및 계정/수집 코드 부재를 검사한다.
- **US4.2**: 문제은행 schema와 워크시트의 산식을 계산하고, 제출 endpoint·답안 저장·개인정보 필드가 없음을 정적 검색한다.

따라서 런타임 learner data collection을 acceptance criterion으로 요구할 필요는 없다. 대신 모든 스토리의 Definition of Done에 다음 공통 검사를 추가하는 것을 권고한다: 저장소 내 제출 endpoint·분석 SDK·계정/토큰 입력·개인정보 필드가 없음, 예시·로그·CSV·출처 메타데이터에 실제 식별자/credential이 없음, 민감정보 검사 결과와 재검사 증거가 있음. 이 검사는 개인정보가 없다는 주장 자체를 검사 가능한 증거로 바꾼다.

품질 결과는 내부 기록에만 남기지 말고, 각 도메인 README 또는 시작 문서에서 관련 검증 보고서와 문서 상태를 링크해야 한다. 학습자는 `verified`, `review`, `blocked`, `확인 필요`의 의미와 마지막 확인일을 실제로 볼 수 있어야 한다.

### 권고하는 최소 보완 acceptance criteria

스토리 본문을 재작성하지 않는 조건에서 다음 조건을 해당 스토리의 AC에 추가하거나 기존 AC를 확장한다.

1. **출처 인벤토리 완전성**: 기준선·학습 문서·문항·복습 자료에 사용된 모든 외부 URL이 사이드바 인덱스 및 source registry에 존재하고, 제목·유형·도메인·확인일·접근 상태·연결 문서가 채워진다.
2. **문항 최종 검토**: 모든 문항에 대해 정답, 각 오답 선택지의 타당성, 난이도, 중복 여부를 `통과|실패|보류`로 판정하고 실패 항목의 수정·재검사 결과를 기록한다.
3. **원문 변환 검토**: 출처 원문의 장문 복사가 없고, 한국어 재구성·필요한 짧은 인용·공식 링크가 확인된다.
4. **버전 고정**: 기준선과 변동 가능한 AWS 사실은 공식 URL·제목·revision 또는 확인일·접근 상태에 연결되며, 차단/미확인 의존 자료는 `verified`가 될 수 없다.
5. **검증 보고서 재현성**: 각 품질 검사는 대상 범위, 검사일, 도구 또는 검사자, 판정, 근거, 조치, 재검사 결과를 기록하고 학습자가 접근할 수 있는 링크를 제공한다.
6. **정적 비수집 검사**: 정적 자료에 learner data 수집 경로, 계정·답안·진도 저장, credential·PII·실제 계정 식별자가 없음을 검사하고 결과를 남긴다.

### 결론

`US1.1`, `US1.2`, `US3.1`, `US4.1`, `US4.2`는 보완 후 검증 가능한 범위다. `US2.1`은 학습 여정으로는 타당하지만 D1~D5 전체를 한 스토리로 유지할 경우 도메인별 하위 검증 단위가 필요하다. `US5.1`은 필수 횡단 품질 기준이지만 내부 검토 절차와 학습자 가시 증거를 분리해야 한다.

현재 권고 판정은 **조건부 진행(Changes Required)** 이다. 위 최소 보완 중 특히 FR1.4, FR4.4, FR5.4, FR6.3의 acceptance evidence와 기준선/source schema를 확정한 뒤에야 User Stories 단계 품질 게이트를 통과시키는 것이 안전하다.

## Positions

- **AC 검증성**: Given/When/Then의 방향은 적절하나 주관적 표현과 미고정 schema가 일부 남아 있어 자동·수동 판정 기준을 보완해야 한다.
- **INVEST**: 대부분 독립적이고 가치가 있으나 US2.1은 범위가 크고, US5.1은 사용자 가치와 내부 운영 증거가 혼합되어 있다. 도메인별 검증 묶음과 사용자 가시 보고서로 보완한다.
- **추적성**: 상위 FR/NFR 고아는 없지만 FR1.4, FR3.2, FR4.4, FR5.4, FR6.3은 현재 AC에서 직접 증명되지 않아 세부 갭으로 기록한다.
- **출처·최신성**: 공식 URL과 확인일은 충분한 출발점이나 revision/title/access status와 blocked 의존성 검사가 필요하다.
- **접근성**: GFM·일반 Markdown·텍스트 대체 요구는 적절하다. heading/link/alt text 자동 검사와 대표 문서 수동 표본 검토를 모두 요구한다.
- **데이터 최소화**: 모든 스토리는 learner data 없이 정적 검증 가능하다. 저장·제출 경로와 민감정보 패턴의 저장소 검사를 공통 DoD로 고정한다.
- **게이트 권고**: 위 보완을 반영하기 전에는 `READY`가 아니라 `Changes Required`; 반영 후 FR/NFR·source registry·검토 증거의 cross-file 검사를 통과하면 승인 가능하다.
