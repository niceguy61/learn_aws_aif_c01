# Bolt 실행 계획

> 상태: `draft`
> 목적: 승인된 Unit 의존성 DAG를 바탕으로 Construction에서 진행할 문서 작업 묶음의 경제적 순서와 완료 조건을 정한다.

## 독립 용어 정의

- **Bolt**: Construction에서 한 번에 만들고 완료 조건까지 확인하는 하나의 작업 묶음이다. 이 문서의 Bolt는 실행형 애플리케이션이나 배포 단위가 아니라 정적 Markdown·CSV 제작 흐름의 계획 단위다.
- **Walking skeleton**: 첫 Bolt에서 기준선 연결, 학습 문서, 문서 품질 검사까지 최소한의 완결된 흐름을 끝까지 통과시켜 전체 제작 방식이 작동하는지 확인하는 방식이다.
- **Confidence hypothesis**: 해당 Bolt를 완료하면 무엇이 확인되거나 반증되는지를 적은 검증 가능한 가설이다.

핵심 제약은 다음과 같다.

- U1은 기준선·출처 계약의 선행 Unit이다.
- U2~U6은 U1에 의존하고 서로 직접 의존하지 않지만, 제품 결정에 따라 D1→D5 순서로 진행한다.
- U7은 U1과 U2~U6의 문서·용어를 참조한다.
- U8은 모든 산출물의 품질 증거를 통합한다.
- 한 작성자가 순차적으로 집필하며, 문서 작성 후 품질 검사를 실행한다.
- 외부 API·데이터·배포·AWS 계정은 만들지 않는다.

## 전체 순서

| 순서 | Bolt | 포함 Unit | Walking skeleton | 계획상 선행 조건 | 핵심 결과 |
|---:|---|---|---|---|---|
| 1 | B1 | U1 + U2 | 예 | 없음 | 기준선에서 D1 학습 문서와 품질 증거까지 이어지는 최소 완결 흐름 |
| 2 | B2 | U3 | 아니오 | B1의 기준선 계약과 문서 구조 | D2 GenAI 학습 묶음 |
| 3 | B3 | U4 | 아니오 | B2까지의 D1→D2 흐름 | D3 파운데이션 모델 적용 학습 묶음 |
| 4 | B4 | U5 | 아니오 | B3까지의 D1→D3 흐름 | D4 책임 있는 AI 학습 묶음 |
| 5 | B5 | U6 | 아니오 | B4까지의 D1→D4 흐름 | D5 보안·규정 준수·거버넌스 학습 묶음 |
| 6 | B6 | U7 | 아니오 | B1~B5의 기준선·문서·용어 | 문제은행·복습·Anki·점수 워크시트 |

## Bolt 상세 계획

### B1 — 기준선·출처와 D1 Walking skeleton

- **Unit**: U1 `u1-baseline-and-source-registry`, U2 `u2-d1-ai-ml-foundations`
- **Walking skeleton 표시**: `예`
- **완료 조건(Definition of Done)**:
  - 공식 AIF-C01 시험 안내서의 확인 가능한 revision·도메인·작업·기술 항목과 `AIF-C01-D<n>-T<n>` ID를 기록한다.
  - `sources/aws-sidebar-index.md`, `sources/source-registry.yaml`, `sources/content-traceability.yaml`의 기준선·출처 연결을 만든다.
  - D1 README와 개념 단위 문서를 작성하고 필수 학습 흐름, 범위 표지, 상대 링크를 적용한다.
  - 대표 D1 자료에 대해 출처·추적성·초보자·링크·형식 검사를 실행한다.
  - 확인되지 않거나 차단된 출처와 그 영향은 `확인 필요` 또는 `blocked`로 남기며 `verified`로 승격하지 않는다.
- **Confidence hypothesis**: 공식 기준선과 출처에서 시작해 초보자용 D1 문서, 상대 링크, 품질 증거까지 하나의 정적 제작 흐름으로 연결할 수 있다.
- **예상 데모**: D1 시작 문서에서 기준선 항목, D1 개념 문서, 품질 검사 기록으로 이동하고 각 자료에서 원래 기준선으로 돌아오는 링크를 보여 준다.
- **담당**: 단일 작성자, 전달 역할, 아키텍처 역할; 필요 시 공식 출처·품질 검토 역할.

### B2 — D2 GenAI의 기초

- **Unit**: U3 `u3-d2-generative-ai`
- **Walking skeleton 표시**: `아니오`
- **완료 조건(Definition of Done)**:
  - D2 README, 개념 단위 문서, 용어 inventory, 기준선·출처 연결을 작성한다.
  - D1을 선수 지식으로 연결하고 D3으로 이어지는 현재·다음 문서 링크를 제공한다.
  - 모델·서비스처럼 변할 수 있는 사실은 공식 출처와 확인 상태를 연결한다.
  - D2 문서의 초보자·범위·링크·형식 검사를 실행하고 결과를 기록한다.
- **Confidence hypothesis**: B1에서 확립한 설명·출처·검토 구조를 GenAI 개념에 일관되게 확장할 수 있다.
- **예상 데모**: D2 README에서 D1 선수 지식, D2 문서 순서, D3 다음 문서와 품질 기록으로 이동한다.
- **담당**: 단일 작성자; 필요 시 공식 출처·품질 검토 역할.

### B3 — D3 파운데이션 모델의 적용

- **Unit**: U4 `u4-d3-foundation-models`
- **Walking skeleton 표시**: `아니오`
- **완료 조건(Definition of Done)**:
  - D3 README, 개념 문서, 용어, AWS 선택 단서와 기준선·출처 연결을 작성한다.
  - 모델명·기능·요금·리전·할당량처럼 변할 수 있는 사실은 확인일과 접근 상태를 기록한다.
  - 시험 범위와 기준선에 연결된 `실무 확장`을 문서 섹션 수준에서 구분한다.
  - D3 문서의 초보자·범위·링크·출처 검사를 실행한다.
- **Confidence hypothesis**: 파운데이션 모델 적용 개념을 서비스 선택 단서와 연결하면서도 공식 시험 범위와 실무 확장을 혼동하지 않게 설명할 수 있다.
- **예상 데모**: D3 문서에서 목적·제약·선택·제외 근거와 해당 기준선·공식 출처를 함께 보여 준다.
- **담당**: 단일 작성자; 필요 시 아키텍처·공식 출처·품질 검토 역할.

### B4 — D4 책임 있는 AI

- **Unit**: U5 `u5-d4-responsible-ai`
- **Walking skeleton 표시**: `아니오`
- **완료 조건(Definition of Done)**:
  - D4 README, 개념 문서, 용어, 기준선·출처·다음 문서 연결을 작성한다.
  - 책임 있는 AI 원칙·위험·편향·투명성 설명과 학습자용 예시를 구분한다.
  - 공식 범위 밖 정책·규정 사례는 관련 기준선 ID를 앞세운 `실무 확장`으로 표시한다.
  - 초보자 관점, 개념 단위, 범위 표지, 출처와 링크 검사를 실행한다.
- **Confidence hypothesis**: 책임 있는 AI의 시험 개념과 예시를 초보자에게 설명하면서 공식 출제 범위를 과장하지 않을 수 있다.
- **예상 데모**: D4 문서에서 시험 범위 설명, 실무 확장 예시, 오해 교정, 확인 질문을 구분해 보여 준다.
- **담당**: 단일 작성자; 필요 시 공식 출처·규정 준수·품질 검토 역할.

### B5 — D5 보안·규정 준수·거버넌스

- **Unit**: U6 `u6-d5-security-compliance-governance`
- **Walking skeleton 표시**: `아니오`
- **완료 조건(Definition of Done)**:
  - D5 README, 개념 문서, 용어, AWS 관점과 기준선·출처 연결을 작성한다.
  - 보안, 규정 준수, 거버넌스의 차이와 시험 판단 단서를 초보자 수준으로 설명한다.
  - 법률 자문이나 배포·운영 구축으로 범위를 확장하지 않고, 불확실한 규정 세부사항은 `확인 필요`로 남긴다.
  - D5의 초보자·출처·링크·범위·민감정보 검사를 실행한다.
- **Confidence hypothesis**: D1~D4에서 이어진 학습 흐름을 D5의 보안·규정 준수·거버넌스 판단으로 연결할 수 있다.
- **예상 데모**: D5 README에서 세 개념의 구분, AWS 관점의 기본 단서, B6 평가 자료로 가는 링크를 보여 준다.
- **담당**: 단일 작성자; 필요 시 공식 출처·규정 준수·품질 검토 역할.

### B6 — 평가·복습 자료

- **Unit**: U7 `u7-assessment-and-review`
- **Walking skeleton 표시**: `아니오`
- **완료 조건(Definition of Done)**:
  - 확인된 기준선 항목별 최소 문항을 포함해 100문항 이상 문제은행을 작성한다.
  - 문항별 정답·오답 해설·난이도·출처·범위 분류와 원본 문서 연결을 기록한다.
  - 카드, 용어 퀴즈, UTF-8 Anki CSV, 가져오기 안내, 정적 점수 워크시트를 만든다.
  - 기준선→문서→문항·복습 자료의 양방향 추적과 CSV·중복·문항 품질 검사를 실행한다.
- **Confidence hypothesis**: D1~D5의 문서·용어를 평가·복습 자료로 파생해도 기준선·출처·범위 표지가 유지된다.
- **예상 데모**: 대표 기준선 하나에서 관련 문서, 문제, 카드, 용어 퀴즈, Anki 행으로 이동하고 역방향으로 돌아오는 경로를 보여 준다.
- **담당**: 단일 작성자; 품질·공식 출처·구조·추적성 검토 역할.

### B7 — 품질 증거

- **Unit**: U8 `u8-quality-evidence`
- **Walking skeleton 표시**: `아니오`
- **완료 조건(Definition of Done)**:
  - U1~U7의 산출물 목록과 안정 ID·workspace-relative 경로를 기준으로 검사 대상을 정리한다.
  - 공식 범위·출처·추적성·초보자·개념 단위·링크·접근성·문항·CSV·민감정보 검사를 기록한다.
  - 각 `QualityCheckRecord`에 대상, 검사일, 판정, 근거, 조치와 재검사 결과를 남긴다.
  - 미해결 `GAP`, `ORPHAN`, 잘못된 대상, 차단 출처와 보류 사항을 통합 목록으로 남긴다.
- **Confidence hypothesis**: 전체 정적 가이드가 승인된 요구사항·스토리·Unit 계약을 충족하며, 근거 없이 `verified`로 표시되지 않는다.
- **예상 데모**: 도메인 README에서 품질 보고서로 이동하고, 대표 문서·문항·출처의 검사 기록을 원본으로 추적한다.
- **담당**: 단일 작성자; 품질·공식 출처·아키텍처·전달 검토 역할.

## DAG와 실행 순서의 관계

U2~U6이 U1에만 의존하고 서로 직접 의존하지 않으므로 DAG만 보면 병렬 실행이 가능하다. 그러나 이 계획은 다음 이유로 의도적으로 직렬 순서를 선택한다.

1. 승인된 제품 범위가 D1→D5 집필 순서를 요구한다.
2. 단일 작성자가 문서 구조와 한국어 설명의 일관성을 유지한다.
3. B1에서 확인한 구조·출처·검토 방식을 다음 도메인의 기준선으로 사용한다.
4. 병렬 집필로 생길 수 있는 용어·범위 표지·링크 불일치를 줄인다.

따라서 이 문서의 Bolt 순서는 DAG를 위반하지 않는다. U3~U6은 DAG상 U1 완료 뒤 가능하지만, 계획상 D1→D5 품질 인계를 위해 앞 Bolt의 통합 결과를 확인한 뒤 진행한다. U7과 U8은 각각의 DAG 선행 조건을 모두 충족한 뒤 시작한다.

## Construction 운영 선택

- **Iteration**: `stage-major` 기본값을 유지한다. 각 설계·검토 단계가 해당 범위의 Unit에 적용된 뒤 다음 단계로 이동한다.
- **Staffing**: 단일 작성자 중심으로 운영한다. 팀별 Unit ownership은 사용하지 않는다.
- **Gate rhythm**: 각 승인 지점에서 사용자가 확인한다. 팀 ownership을 사용하지 않으므로 별도 팀 gate rhythm은 적용하지 않는다.

## 전체 성공 기준

- B1에서 기준선→D1 문서→검사 증거의 최소 완결 흐름이 통과 또는 보류 사유 기록 상태가 된다.
- B2~B5가 D1→D5 순서를 유지하고 각 도메인 문서와 기준선·출처·다음 문서를 연결한다.
- B6가 100문항 이상 문제은행과 모든 복습 자료를 정적 UTF-8 형식으로 제공한다.
- B7가 전체 추적성·초보자·출처·접근성·문항·민감정보 검사 결과를 통합한다.
- 각 Bolt의 완료 조건, confidence hypothesis, 예상 데모와 남은 위험이 기록된다.

## Assumptions & Open Questions

- 공식 시험 안내서의 실제 revision과 작업·기술 행 수는 U1 집필 시 확인한다.
- WSJF-style 점수는 정량적 약속이나 자동 실행 규칙이 아니라 상대 비교 근거다.
- 각 Bolt의 문서 품질 검사는 작성 후 실행하며, 확인되지 않은 주장은 보류한다.
- Construction에서 새로운 외부 서비스·API·데이터·배포 환경은 만들지 않는다.
