# Bolt 팀·역할 배정

> 상태: `draft`
> 목적: 승인된 Team Formation을 바탕으로 각 Bolt의 작성·검토 책임과 협업 경계를 정한다.

## 독립 용어 정의

- **Bolt**: Construction에서 하나 이상의 Unit을 묶어 작성·검토하고 완료 조건을 확인하는 계획 단위다. 이 프로젝트에서는 정적 문서 작업 묶음이다.
- **Mob**: 여러 역할이 같은 논점을 함께 검토하고 한 작성자가 결과를 통합하는 짧은 협업 방식이다. 이 프로젝트의 기본 운영은 상시 mob이 아니라 단일 작성자와 필요 시 역할별 검토다.
- **Program Board**: 여러 팀의 작업 흐름과 의존성을 한 화면에서 관리하는 계획 보드다. 이 프로젝트는 단일 작성자 중심이므로 별도 Program Board를 운영하지 않는다.
- **단일 작성자**: 문서와 평가 자료의 초안을 일관되게 작성하고, 지원 역할의 검토 의견을 반영하는 중심 작성 주체다. 이는 여러 명의 허구적 팀을 만든다는 뜻이 아니다.

## 팀 구성 기준

Team Formation에서 확정된 구성은 다음과 같다.

- **Product Owner / 최종 승인자**: 사용자. 범위·우선순위·공식 범위 해석·보류·최종 승인에 대한 최종 결정권을 가진다.
- **단일 작성자**: D1~D5 문서, 문제은행, 카드·퀴즈·진도표·Anki의 초안을 작성하고 안정 ID·출처 연결을 유지한다.
- **전달 역할**: Unit·Bolt 순서, 의존성, 완료 증거와 단계 인계를 관리한다.
- **아키텍처·구조 역할**: 안정 ID, 파일 구조, Unit 계약과 추적성의 구조적 일관성을 확인한다.
- **공식 출처·규정 준수 역할**: AWS Certification 공식 범위, AWS 공식 문서, 최신성·차단 상태와 시험/실무 구분을 확인한다.
- **품질·디자인 역할**: 초보자 이해도, 문서 구조, 링크·Markdown·문항·CSV와 접근성을 검토한다.
- **개발·형식 역할**: 실행형 애플리케이션을 만들지 않는 범위에서 정적 파일 구조와 형식 검사를 지원한다.

외부 작성자, AWS Professional Services, 별도 개발팀, 별도 운영팀은 배정하지 않는다.

## 책임과 승인 경계

| 활동 | 사용자 / Product Owner | 단일 작성자 | 전달 역할 | 출처·규정 준수 | 품질·디자인 | 아키텍처·구조 |
|---|---|---|---|---|---|---|
| 범위·순서 변경 | A | R | C | C | I | C |
| 문서·평가 자료 초안 | A | R | C | C | C | C |
| 공식 범위·출처 확인 | A | R | C | R | C | C |
| 초보자·접근성 검토 | A | R | C | C | R | C |
| 추적성·파일 구조 검토 | A | R | C | C | C | R |
| Bolt 완료 판단 | A | R | R | C | R | R |
| 단계 승인 | A | C | C | C | C | C |

`R`은 실행 책임, `A`는 최종 책임·승인, `C`는 협의, `I`는 결과 공유를 뜻한다. 각 활동의 최종 `A`는 사용자 / Product Owner로 고정한다.

## 협업 방식

- 기본 작업은 단일 작성자가 한 Bolt씩 수행한다.
- 불확실한 공식 해석, 출처 차단, 추적성 불일치, 초보자 이해도 문제처럼 위험이 높은 논점에만 짧은 역할별 검토를 요청한다.
- 검토 역할은 근거와 수정 의견을 제공하지만 범위·공식 해석·최종 출시는 확정하지 않는다.
- 서로 다른 역할의 의견이 충돌하면 공식 출처와 승인된 범위를 우선해 보류·수정안을 정리하고 사용자에게 제시한다.
- 각 Bolt는 문서 작성 후 관련 품질 검사를 수행하고, 다음 Bolt로 넘어가기 전에 남은 위험과 보류 상태를 기록한다.

## 인계 계약

각 Bolt의 인계에는 다음 항목이 포함된다.

1. 완료한 Unit과 안정 ID
2. 변경·추가된 정적 파일의 workspace-relative 경로
3. 사용하거나 보류한 출처와 확인일·접근 상태
4. 기준선·문서·문항·복습 자료의 추적성 변경
5. 실행한 품질 검사와 `통과|실패|보류` 결과
6. 다음 Bolt를 막는 미해결 질문 또는 외부 의존성
7. 사용자의 승인 상태

## Assumptions & Open Questions

- 현재는 한 명의 작성자와 사용자의 최종 승인 구조를 유지한다.
- 여러 팀을 도입하지 않으므로 Program Board, 팀별 Unit ownership, 팀별 독립 승인 gate는 사용하지 않는다.
- 외부 파트너와 AWS Professional Services는 계획에 포함하지 않는다.
- 검토 역할의 이름은 책임을 나타내며 별도의 실제 인원이나 외부 계약을 의미하지 않는다.
