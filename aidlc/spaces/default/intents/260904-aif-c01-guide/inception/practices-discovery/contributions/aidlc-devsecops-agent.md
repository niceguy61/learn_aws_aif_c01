## Contribution

리드 초안의 방향은 정적 한국어 문서 저장소에 적합하다. 다만 현재는 대부분이 제안 상태이므로, 보안·공급망·검증 기준을 사용자 인터뷰에서 명시적으로 확정해야 한다.

### 출처와 링크 무결성

- `discovered-rules.md`의 공식 출처 URL과 확인 날짜 기록 요구는 적절하다. 그러나 어떤 URL을 공식 범위의 기준으로 인정할지, AWS 문서·Certification 페이지·공식 블로그를 어떻게 구분할지는 아직 운영 규칙으로 충분히 구체화되지 않았다.
- 모든 링크를 `sources/` 인벤토리에 등록하고, URL·문서 제목·상위 주제·관련 도메인·확인 날짜·접근 상태·연결된 학습 문서를 기록해야 한다.
- 링크가 차단되거나 내용이 변경되면 추측으로 대체하지 말고 `blocked` 또는 재검토 상태로 남겨야 한다. 링크 검사 성공만으로 출처의 사실 정확성이 보장되지는 않으므로, 출처 내용과 문서 설명을 사람이 대조하는 별도 검토가 필요하다.
- 상대 경로 링크와 외부 HTTPS 링크를 구분하고, 리디렉션·인증 필요·지역별 페이지 차이를 검사 결과에 기록하는 것이 좋다.

### 비밀·개인정보 회피

- 현재 리드 초안에는 비밀, 개인정보, 토큰, 계정 식별자, 실제 학습자 정보가 문서와 검사 결과에 들어가지 않도록 하는 규칙이 없다. 문서 예시와 테스트 고정값에는 실제 이메일, 전화번호, AWS 계정 ID, 액세스 키, ARN, 로그 원문을 사용하지 않아야 한다.
- 예시는 명백한 플레이스홀더와 가상의 값만 사용하고, 자격 증명·세션 토큰·서명된 URL·내부 저장소 경로를 커밋하지 않는 규칙을 추가해야 한다.
- 커밋 전 비밀 탐지와 개인정보 패턴 검사를 실행하고, 탐지된 값은 단순 삭제가 아니라 노출 범위에 따라 폐기·교체 여부를 확인해야 한다.
- 공식 문서에서 가져온 예시에 식별자가 포함되어 있더라도 그대로 복사하지 말고, 학습에 필요한 구조만 남겨 비식별화한다.

### 문서 저장소의 의존성·공급망

- 애플리케이션 의존성이 없어도 Markdown 린터, 링크 검사기, front matter 검사기, 자동화 실행기, GitHub Actions와 같은 개발 의존성은 공급망 위험을 가진다.
- 도구와 GitHub Actions는 가능한 경우 정확한 버전 또는 커밋으로 고정하고, 패키지 잠금 파일을 버전 관리해야 한다. 자동 업데이트 봇이 제안한 변경도 사람이 검토한 뒤 통합해야 한다.
- 외부 스크립트를 문서 빌드 과정에서 즉시 내려받아 실행하지 말고, 허용된 도구 목록과 실행 출처를 정한다. 검사 도구가 원격 페이지의 내용을 실행하거나 저장소의 비밀을 외부 서비스로 전송하지 않는지 확인해야 한다.
- 의존성 취약점 검사와 GitHub Actions의 권한 최소화가 필요하다. 문서 저장소라 하더라도 풀 리퀘스트에서 임의의 문서 내용을 스크립트 인자로 전달하거나 권한 있는 토큰으로 처리하지 않아야 한다.
- 출처 원문을 자동 다운로드해 저장할 때는 라이선스·재배포 범위와 악성 문서 가능성을 함께 검토하고, 필요한 메타데이터와 링크 중심으로 보존한다.

### 검증 게이트

문서 단위의 완료 조건에는 다음 검사를 포함하는 것을 제안한다.

1. UTF-8, 파일명 규칙, YAML front matter와 필수 섹션 검사를 통과한다.
2. Markdown 린트와 내부 링크 검사를 통과한다.
3. 외부 링크의 HTTPS·접근 가능성·리디렉션을 확인하고, `sources/` 인벤토리의 URL·제목·확인 날짜·상태와 일치시킨다.
4. AIF-C01의 D1~D5 및 작업·기술 항목 추적표에서 문서 연결과 누락 여부를 확인한다.
5. 비밀·개인정보 탐지와 의존성 취약점 검사를 통과한다.
6. 공식 사실과 작성자의 초보자용 해설이 구분되는지, 확인되지 않은 내용이 `verified`로 표시되지 않았는지 검토한다.
7. 최소 한 명의 초보자 관점 검토와 변경 출처의 독립 확인을 완료한다.

풀 리퀘스트 검사는 병합 전에 자동으로 실패하게 하되, 링크가 일시적으로 차단된 경우에는 예외 사유·담당자·재검증 기한을 기록하는 승인된 예외 절차를 둬야 한다. `main` 통합은 모든 필수 게이트가 통과된 경우에만 허용하는 편이 안전하다.

## Positions

- **출처 무결성:** 공식 시험 범위의 기준 출처와 일반 학습 출처를 구분하고, 모든 URL을 인벤토리와 문서에 연결하는 규칙을 필수로 한다.
- **비밀·개인정보:** 현재 초안에 없는 명시적 금지 규칙을 추가한다. 실제 식별자와 자격 증명은 예시·로그·검사 산출물 어디에도 넣지 않는다.
- **공급망:** 문서 프로젝트에도 도구·액션·패키지 고정, 잠금 파일, 취약점 검사, 최소 권한, 원격 콘텐츠 비실행을 적용한다.
- **검증:** 정적 검사만이 아니라 출처 대조, 범위 추적, 비밀 탐지, 의존성 검사, 초보자 검토를 병합 게이트로 묶는다.
- **사용자 인터뷰에서 확정할 사항:** 공식 출처 우선순위와 링크 차단 처리, 실제 사용할 검사 도구와 버전 고정 방식, 비밀·개인정보 예시의 허용 범위, 의존성 업데이트 담당과 주기, 예외 승인자와 재검증 기한, `main` 병합의 필수 게이트 및 문서 공개 기준을 확인해야 한다.
