## Contribution

리드 초안의 테스트 자세는 정적 Markdown 학습 가이드에 적절한 방향을 제시한다. 코드 단위 테스트 대신 문서 구조, front matter, 링크, 출처, 문서 간 연결, 공식 시험 범위 누락 여부를 검사 대상으로 삼은 점은 프로젝트 위험에 맞다. `test-after` 방식으로 문서 작성 후 검증한다는 제안도 실행 순서가 명확하다. 다만 검사 실패의 심각도, 통과 기준, 담당자, 기록 위치가 아직 정의되지 않아 품질 게이트로 바로 적용하기에는 부족하다.

문서 검증 범위에는 다음 항목을 필수 검사로 고정할 필요가 있다.

- 모든 도메인·작업·기술 항목이 문서 또는 명시적인 해당 없음·확장 기록에 연결되는지 확인한다.
- 문서의 YAML front matter가 필수 필드와 허용된 상태값을 따르는지 확인한다.
- 외부 링크의 URL, 제목, 도메인, 확인 날짜, 접근 상태가 출처 인벤토리와 일치하는지 확인한다.
- 문서 본문의 출처 주장과 학습자에게 제공하는 해설·예시가 구분되는지 확인한다.
- 끊긴 링크, 접근 차단, 최신성 확인 필요 항목이 추측으로 대체되지 않고 기록되는지 확인한다.
- 문서 내부 링크, 다음 문서 연결, 용어 사전 연결이 실제 파일과 일치하는지 확인한다.
- 파일명·디렉터리명, UTF-8 인코딩, 제목 계층, 코드 표기와 Markdown 기본 형식을 검사한다.

출처와 링크 검사는 단순히 HTTP 응답 성공 여부만 확인해서는 안 된다. AWS 공식 시험 안내서가 공식 범위의 근거인지, 서비스 문서·Skill Builder·공식 블로그가 학습 설명의 보조 근거인지 성격을 구분해야 한다. 동적 페이지나 지역·로그인에 따라 내용이 달라지는 페이지는 접근 성공만으로 검증 완료 처리하지 말고 제목, 핵심 목록, 확인 날짜, 접근 상태를 함께 기록해야 한다. 요금, 모델명, 리전, 할당량처럼 변하는 정보에는 작성 기준일과 재확인 필요 여부가 있어야 한다.

초보자 품질 게이트는 문법 검사를 넘어 학습 가능성을 확인해야 한다. 각 문서는 선수 지식과 한 줄 요약으로 시작하고, 핵심 개념을 쉬운 말과 짧은 예시로 설명해야 한다. AWS 서비스 설명에는 무엇인지, 언제 쓰는지, 무엇과 구분하는지, 시험에서 어떤 단서로 선택하는지를 포함해야 한다. 비교표·실무형 시나리오·오개념 교정·확인 질문·미니 퀴즈가 설명 내용과 실제로 연결되는지 확인해야 하며, 용어가 최초 등장 시 영어 원어와 함께 설명되는지도 검사해야 한다. 초보자 검토자는 배경 지식 없이 문서를 읽고 막히는 용어와 논리적 비약을 기록해야 한다.

종합 전략은 D1부터 D5까지 순서대로 작성하되, 먼저 하나의 작은 문서를 출처 수집부터 검토까지 완성하는 수직 슬라이스가 유효하다. 첫 슬라이스에서 검사 규칙, 출처 추적, 문서 연결, 초보자 검토 절차를 고정한 뒤 나머지 도메인에 반복 적용해야 한다. 최종 검증에서는 도메인 가중치만 확인하지 말고 공식 시험 안내서의 모든 작업과 기술 항목을 추적표에서 양방향으로 확인해야 한다. 즉, 범위 항목에서 문서로 가는 연결과 문서에서 시험 범위 또는 실무 확장으로 가는 연결을 모두 점검해야 한다. 시험 범위와 선택적 실무 확장이 섞이지 않도록 각 문서에 경계를 표시하는 것도 종합 품질의 필수 조건이다.

현재 초안의 주요 공백은 다음과 같다. 정적 검사 도구와 실행 명령이 정해지지 않았고, 링크 확인이 오프라인 또는 접근 제한 환경에서 어떻게 처리되는지 정의되지 않았다. 출처 상태의 `discovered`부터 `verified`까지 각 전이 조건과 사람 검토의 증거도 구체화되지 않았다. 초보자 검토의 표본 수, 검토 질문, 합격 기준, 재검토 시점이 없으며, 문서 간 연결 누락과 공식 범위 누락을 누가 최종 승인할지도 정해야 한다. 또한 변경된 AWS 정보의 재검증 주기, 이미 `verified`인 문서가 변경될 때 상태를 되돌리는 규칙, 미확인 출처를 사용하는 문서의 공개 제한도 결정이 필요하다.

## Positions

- 테스트 자세: `test-after`를 채택하되, 문서 작성 전에 최소 구조·출처·추적성 체크리스트를 템플릿으로 제공한다. 각 검증은 재현 가능한 명령 또는 체크 절차와 결과 기록을 가져야 한다.
- 문서 검증 범위: Markdown 문법만이 아니라 front matter, 제목 구조, 문서 내부 링크, 용어 연결, 필수 섹션, 코드·표의 가독성, 시험 범위 추적성을 함께 품질 게이트로 삼는다.
- 출처·링크 검사: URL 접근성, 공식 출처의 성격, 페이지 제목과 핵심 내용의 일치, 확인 날짜, 최신성 위험, 차단·실패 상태를 모두 기록한다. 접근하지 못한 출처는 `verified`로 승격하지 않는다.
- 초보자 품질 게이트: 초보자 검토를 필수로 하고, 선수 지식 없는 독자가 개념·서비스 선택·시험 판단 단서를 따라갈 수 있는지 확인한다. 막히는 용어, 설명 생략, 혼동 가능한 비교를 결함으로 기록한다.
- 종합 전략: D1~D5의 모든 공식 작업·기술 항목에 문서 또는 명시적 제외·확장 기록을 연결하고, 범위 항목과 문서 양쪽에서 추적성을 검사한다. 첫 문서 수직 슬라이스를 통과 기준의 기준선으로 사용한다.
- 인터뷰에서 결정할 사항: 사용할 Markdown·링크 검사 도구와 오프라인 처리 방식, 각 품질 게이트의 필수·권고 구분, 초보자 검토자와 표본 수, 미니 퀴즈·코드 실습의 범위, 출처 재검증 주기, `verified` 승인권자, 누락이나 접근 차단 발생 시 공개 기준을 사람에게 확인해야 한다.
- 승인 조건: 위 결정이 기록되고, 실패 시 수정·재검토·상태 변경 절차가 정해진 뒤에만 테스트 자세와 품질 게이트를 확정한다. 현재 리드 초안은 방향성은 충분하지만 실행 가능한 검증 기준이 확정되지 않은 제안 상태다.
