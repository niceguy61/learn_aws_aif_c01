# AIF-C01 한국어 학습 가이드 요구사항

- **기준 상태**: 승인된 요구사항 분석 요약(`Looks correct`)을 반영한 요구사항 baseline
- **대상 학습자**: AI/ML과 AWS를 처음 접하는 완전 초보자
- **범위 깊이**: Comprehensive
- **추적 기준**: 승인된 의도·범위·질문 답변과 공식 AIF-C01 시험 안내서

## 1. Intent analysis

### 1.1 목표

이 프로젝트의 목표는 AIF-C01을 준비하는 완전 초보자가 AI/ML, 생성형 AI, 파운데이션 모델, 책임 있는 AI, 보안·규정 준수·거버넌스의 핵심 개념을 한국어로 이해하고, 개념을 AWS 서비스 선택과 기본 시나리오 판단 및 시험 문제 풀이로 연결하도록 돕는 것이다. 이는 단순한 용어 모음이 아니라 `개념 이해 → 선택 기준 → 시나리오 판단 → 복습·평가`의 학습 흐름을 제공하려는 목적이다. [intent]

시험 합격이 우선 목표이며, 준비 기간은 특정 시험일을 발명하지 않고 1개월 이내의 4주 상대 일정으로 표현한다. 장기적인 AI/ML·AWS 입문 활용은 시험 핵심을 흐리지 않는 실무 확장으로 별도 표시한다. [intent][scope][Q1]

### 1.2 기대 결과

완료된 가이드는 다음 결과를 제공해야 한다.

- AIF-C01 공식 5개 도메인과 모든 확인된 작업·기술 항목을 빠짐없이 추적한다.
- 확인된 시험 핵심 사실을 초보자가 읽을 수 있는 작은 Markdown 문서로 재구성한다.
- AWS 서비스의 역할, 선택 시점, 유사 서비스와의 구분, 기본 시나리오 판단 단서를 시험 범위와 분리해 제공한다.
- 4주 학습 경로, 카드 요약, 용어 퀴즈, 용어 사전, UTF-8 Anki 자료, 100문항 이상의 문제은행을 제공한다.
- 문제은행 전체 풀이의 평균 정답률 80% 이상을 합격 준비 지표로 사용할 수 있게 한다. 이 지표는 문항의 사실 정확성 검토를 대신하지 않는다. [intent][scope][Q2]

## 2. Functional requirements

### FR1. 공식 시험 범위 기준과 추적성

**목적**: 시험 범위를 임의로 확장하거나 누락하지 않고 모든 학습 산출물을 공식 기준과 연결한다. [scope][Q4]

- **FR1.1 공식 기준 등록**: D1 집필을 시작하기 전에 공식 AIF-C01 시험 안내서의 5개 도메인, 채점 비율, 작업·기술 항목을 기준 목록으로 등록해야 한다. 기준 목록의 안정적인 행 ID는 `AIF-C01-D<n>-T<n>` 형식을 사용한다. `D<n>`은 공식 도메인 번호이고 `T<n>`은 해당 도메인 안에서 공식 안내서에 나타나는 작업·기술 행의 순번이다. 실제 순번과 공식 표현은 공식 안내서에서 부여하며, 항목을 발명하거나 재번호화하지 않는다. 각 행은 다음 필드를 필수로 가진다: `baseline_id`, `revision_title`, `domain`, `task`, `technology`, `official_source_url`, `official_source_title`, `checked_date`, `status`, `learning_document_ids`, `question_ids`, `card_ids`, `quiz_ids`, `anki_ids`, `notes`. `status`는 적용 가능한 단계에 따라 `discovered|downloaded|summarized|reviewed|verified|blocked` 중 하나를 사용한다. 등록 전 확인되지 않은 항목은 `확인 필요`로 표시해야 한다. **검증 방법**: 기준 목록이 `sources/`의 공식 시험 출처를 가리키고, 모든 행의 필수 필드·안정 ID·상태가 유효하며, D1 문서의 생성 시점이 기준 목록 등록 이후인지 확인한다. 확인된 행은 최소 하나의 학습 문서 ID와 하나의 문제 ID를 가져야 하며, 행 매핑 검사에서 고아 행 0건이어야 한다. 미확인·차단 행은 `verified`가 될 수 없고, `notes`에 사유와 후속 확인 대상을 기록한다.
- **FR1.2 도메인 완전성**: 기준 목록의 다음 5개 도메인을 각각 추적해야 한다: D1 AI 및 ML의 기초(20%), D2 GenAI의 기초(24%), D3 파운데이션 모델의 적용(28%), D4 책임 있는 AI에 대한 가이드라인(14%), D5 AI 솔루션의 보안·규정 준수 및 거버넌스(14%). **검증 방법**: 다섯 도메인이 도메인 README, 추적표, 최종 점검 기록에 모두 존재하는지 확인한다.
- **FR1.3 항목 양방향 연결**: 각 공식 작업·기술 기준선 행은 `AIF-C01-D<n>-T<n>` ID를 사용하고, 최소 하나의 학습 문서, 문제, 카드, 퀴즈 또는 Anki 항목으로 연결되어야 한다. 확인된 행은 반드시 최소 하나의 학습 문서 ID와 최소 하나의 문제 ID를 가져야 한다. 각 학습 문서·문제·카드·퀴즈·Anki 항목은 하나 이상의 공식 항목 또는 명시적인 `해당 없음/실무 확장` 근거를 가져야 한다. **검증 방법**: 공식 항목에서 문서·평가 자료로, 각 자료에서 공식 항목으로 이동할 수 있는 추적표를 검사하고, 확인된 기준선 행의 학습 문서·문제 매핑 누락과 고아 행을 각각 0건으로 판정한다. `blocked` 또는 미확인 행은 비검증 상태와 사유를 유지한다.
- **FR1.4 출처 링크 인벤토리**: 조사한 공식 사이드바 링크를 `sources/aws-sidebar-index.md`에 누락 없이 등록하고, 사용한 URL은 `sources/source-registry.yaml`에서 제목, 출처 유형, 상위 주제, 도메인 매핑, 확인일, 접근 상태, 연결 문서와 함께 관리해야 한다. 기준선 행에도 공식 URL·제목·확인일·상태를 기록하고, `blocked`인 경우 차단 사유와 영향받는 문서·문항·카드·퀴즈·Anki 항목을 `notes` 또는 연결 필드로 남긴다. **검증 방법**: 문서에 사용된 외부 URL의 집합이 출처 등록부에 포함되는지 비교하고, 기준선 행마다 출처 메타데이터와 상태·후속 조치가 있는지 검사한다.

### FR2. 도메인별 초보자 학습 문서

**목적**: 학습자가 선수 지식 없이 핵심 개념을 이해하고 다음 판단으로 이동하도록 한다. [intent][scope]

- **FR2.1 작성 순서와 구조**: D1에서 D5 순서로 도메인을 작성하고, 각 도메인 디렉터리에 목표·공식 시험 항목·선수 지식·읽기 순서를 설명하는 `README.md`를 제공해야 한다. **검증 방법**: 도메인 디렉터리와 README의 존재, 읽기 순서, 도메인 ID를 검사한다.
- **FR2.2 개념 단위 분해**: 한 학습 Markdown 문서는 하나의 핵심 개념 또는 밀접하게 연결된 작은 개념 묶음만 다뤄야 하며, 문서 간 선수 지식과 다음 문서 연결을 명시해야 한다. **검증 방법**: 각 문서의 목표와 연결 문서가 존재하고 서로 다른 핵심 주제가 과도하게 혼합되지 않았는지 초보자 검토 기록으로 확인한다.
- **FR2.3 필수 학습 흐름**: 각 핵심 문서는 `이 문서에서 배울 것`, 선수 지식과 한 줄 요약, 쉬운 핵심 설명, AWS 관점과 관련 서비스, 비교, 실무형 시나리오, 시험 판단 단서, 오해, 핵심 정리, 확인 질문, 다음 문서 연결의 순서를 따른다. **검증 방법**: 필수 제목과 비어 있지 않은 내용을 자동·수동 검사한다.
- **FR2.4 초보자 설명**: 핵심 영어 용어는 최초 등장 시 한국어 설명과 영어 원문을 함께 제공하고, 코드·수학·통계·모델 개발 경험 없이도 이해할 수 있는 쉬운 말과 예시를 포함해야 한다. **검증 방법**: 초보자 관점 검토 체크리스트에서 선수 지식, 예시, 용어 설명 누락이 없는지 확인한다.
- **FR2.5 AWS 판단 연결**: AWS 서비스 설명을 포함하는 문서는 서비스가 무엇인지, 언제 쓰는지, 무엇과 구분하는지, 시험에서 어떤 단서로 고르는지를 설명해야 한다. 기능·모델명·요금·리전·할당량처럼 변할 수 있는 사실은 확인된 공식 출처에 연결하거나 `확인 필요`로 남겨야 한다. **검증 방법**: 문서의 판단 단서와 출처 상태를 검사한다.
- **FR2.6 시험 범위와 실무 확장 구분**: 공식 시험 범위 내용에는 항목·문항·카드·퀴즈·Anki 행 또는 문서 섹션 수준에서 `시험 범위` 표지를 붙이고, 서비스 선택·비교·기본 시나리오와 같은 확장 내용에는 같은 수준의 `실무 확장` 표지를 붙여야 한다. 혼합 문서는 전체 문서에 하나의 포괄 표지만 붙이지 않고 각 섹션·항목·파생 자료에 적용 범위를 표시한다. 실무 확장은 반드시 관련 원래 공식 기준선 ID(`AIF-C01-D<n>-T<n>`)를 선행 표기하거나 인용해야 하며 공식 출제 범위로 표시하지 않는다. 가이드가 새로 만든 도표·그림은 `가이드 작성 도표`로 표시하고 AWS 공식 이미지는 `AWS 공식 이미지`와 공식 출처를 함께 표시하여 구분한다. 기능·모델명·요금·리전·할당량처럼 변할 수 있는 정보는 확인된 공식 출처에 연결하거나 `확인 필요`로 남겨야 한다. **검증 방법**: 문서·문항·카드·퀴즈·Anki의 섹션/항목 수준 분류 표지, 실무 확장의 기준선 ID, 도표·이미지 출처 표시와 출처 상태를 검사한다.

### FR3. 학습 지원 자료와 4주 경로

**목적**: 1개월 이내 학습자가 핵심을 반복하고 약점을 확인할 수 있게 한다. [intent][scope][Q1]

- **FR3.1 4주 진도표**: 특정 시험일을 사용하지 않고 1주차부터 4주차까지 D1~D5, 통합 복습, 문제 풀이와 최종 점검을 배치한 진도표를 제공해야 한다. **검증 방법**: 네 주차가 모두 존재하고 각 주차에 학습·복습·평가 활동과 완료 체크 항목이 있는지 확인한다.
- **FR3.2 카드와 용어 퀴즈**: 각 도메인의 핵심 용어와 혼동하기 쉬운 선택 기준을 카드 요약과 용어 퀴즈로 제공해야 하며, 각 항목은 원본 문서 또는 공식 항목 ID로 추적되어야 한다. 모든 확인된 기준선 행은 최소 하나의 학습 문서와 문제로 연결되고, 각 도메인은 최소 하나의 카드 매핑과 하나의 용어 퀴즈 매핑을 가져야 한다. 각 매핑에는 기준선 ID와 자료 ID를 명시한다. 모든 매핑된 학습 문서의 핵심 용어는 `glossary.md`, 카드 또는 용어 퀴즈 중 하나 이상에 연결되어야 한다. **검증 방법**: 기준선 행·도메인·학습 문서 핵심 용어별 매핑 누락을 검사하고, 확인된 행·도메인·핵심 용어의 누락을 각각 0건으로 판정한다.
- **FR3.3 용어 사전**: 누적 `docs/glossary.md`에 핵심 용어의 한국어 설명, 영어 원문, 관련 문서 링크를 기록해야 한다. **검증 방법**: 문서에서 연결된 용어가 사전에 존재하고 사전 항목이 실제 문서를 가리키는지 확인한다.
- **FR3.4 Anki 자료**: 앞면·뒷면 필드를 갖춘 UTF-8 CSV와 가져오기 안내를 제공해야 하며, 각 행은 원본 문서 또는 출처와 연결되어야 한다. **검증 방법**: CSV 인코딩·헤더·행 파싱과 원본 연결을 검사한다.

### FR4. 문제은행과 학습 성과 지표

**목적**: 학습자가 전 범위를 시나리오 문제로 연습하고 합격 준비 상태를 확인하게 한다. [intent][scope][Q2][Q6]

- **FR4.1 문제 수**: 자체 제작 문제은행은 100문항 이상이어야 한다. **검증 방법**: 고유 문항 ID의 개수를 세어 100 이상인지 확인한다.
- **FR4.2 문항 추적 필드**: 모든 문항은 문항 ID, 도메인, 기준선 공식 작업·기술 항목 ID, 질문, 선택지, 정답, 해설, 공식 출처 URL, 난이도, 범위 분류를 가져야 한다. 문항의 기준선 ID는 확인된 공식 행에 연결되어야 하며, 각 확인된 행은 최소 하나의 문항으로 매핑되어야 한다. 총 문항 수가 100문항을 초과하는 경우 추가 문항의 분포는 먼저 확인된 각 기준선 행에 1문항을 배정하는 항목별 최소 바닥 수를 충족한 뒤, 공식 도메인 가중치(20%, 24%, 28%, 14%, 14%)를 우선 따른다. 공식 안내서에 없는 작업·기술 세부사항을 임의로 만들어 문항을 배정하지 않는다. **검증 방법**: 필수 필드 누락, 확인된 기준선 행별 문제 매핑 누락, 도메인별 문제 매핑 누락, 범위 분류 누락을 검사하고 0건이어야 한다. 배분 검사는 항목별 최소 바닥 수 충족 후 가중치에 따른 추가 분포인지 확인한다.
- **FR4.3 작성 시점 검증**: 문항을 작성할 때 범위 연결, 정답, 해설, 공식 URL을 확인해야 한다. 확인되지 않은 서비스 세부사항에 의존하는 문항은 공식 확인 전까지 보류해야 한다. **검증 방법**: 문항별 작성 체크 또는 추적 기록과 출처 상태를 대조한다.
- **FR4.4 최종 일괄 검토**: 최종 검토 단계에서 모든 문항의 오답 선택지 타당성, 난이도, 중복 여부를 일괄 점검하고 발견된 문제를 수정해야 한다. **검증 방법**: 문항별 또는 일괄 검토 결과에 세 항목의 판정과 수정 상태가 기록되어야 한다. [Q6]
- **FR4.5 준비 지표와 정적 점수 워크시트**: 학습자가 문제은행 전체를 처음부터 끝까지 한 번 완료한 시도의 평균 정답률 80% 이상을 합격 준비 지표로 기록할 수 있도록 정적 Markdown 점수 워크시트와 작성 안내를 제공해야 한다. 데이터 저장·계정·답안 수집은 하지 않고 학습자가 로컬에서 수기로 기록한다. 첫 전체 풀이의 분모는 해당 패스에서 풀이 대상으로 삼은 전체 문제은행 문항 수이며, 미응답도 그 전체 문항에 포함하여 오답으로 계산한다. `정답률 = 정답 문항 수 / 전체 문항 수 × 100`으로 계산하고 소수 첫째 자리까지 반올림한다. 재시도 점수는 별도 행에 기록하며 첫 시도 지표를 대체하지 않는다. `80% 이상`은 준비도 참고 지표일 뿐 합격 보장이 아니다. 문항의 정답·해설·공식 URL 품질은 별도 사실 정확성 게이트로 관리한다. **검증 방법**: 워크시트에 전체 문항 수, 첫 시도 정답 수, 미응답 수, 계산식, 소수 첫째 자리 반올림, 재시도 별도 기록, 80% 해석과 비수집 경계가 명시되어 있는지 확인하고, 문항 사실 정확성 검토 기록이 점수 기록과 분리되어 있는지 검사한다.

### FR5. 출처 최신성, 보류와 검증 상태

**목적**: 변하는 AWS 사실을 추측하지 않고 확인 가능한 지식과 보류 항목을 구분한다. [scope][Q4][Q5]

- **FR5.1 문서 출처 메타데이터**: 도메인별 문서는 YAML front matter의 `source_urls`, `source_checked`, `status`를 포함하고, 문서 끝에 공식 문서 제목·URL·확인 날짜를 기록해야 한다. `status`는 검증 수준에 따라 `draft`, `review`, `verified` 중 하나여야 한다. **검증 방법**: front matter와 문서 끝 출처 섹션을 파싱하고 허용 값과 날짜 형식을 검사한다.
- **FR5.2 시험 핵심과 서비스 세부사항의 차등 처리**: 공식적으로 확인된 시험 범위 핵심 사실은 유지하되, 확인되지 않은 서비스 세부사항에 의존하는 파생 문서·문항·카드·Anki 항목은 공식 확인 전까지 보류해야 한다. **검증 방법**: 보류 출처를 참조하는 파생 항목이 최종 확정 상태로 표시되지 않았는지 검사한다. [Q5]
- **FR5.3 차단 출처 기록**: 열리지 않거나 내용이 확인되지 않는 URL은 `blocked` 또는 `확인 필요` 상태와 차단 사유, 영향받는 문서·문항·후속 확인 대상을 기록해야 한다. **검증 방법**: 차단 링크마다 사유와 영향 매핑이 있는지 확인한다.
- **FR5.4 원문 재배포 방지**: 출처 원문을 통째로 복사하지 않고, 학습 목적에 맞춘 한국어 재구성과 짧은 필요 인용 및 링크만 사용해야 한다. **검증 방법**: 출처 검토에서 장문 원문 복사와 인용 링크 누락을 확인한다.

### FR6. 문서 품질·범위·완료 점검

**목적**: 학습 자료가 읽히고, 추적되며, 공식 범위와 확장을 혼동하지 않도록 한다. [scope][Q3][Q6]

- **FR6.1 필수 최종 검사**: 최종 검토에서 초보자 관점, 공식 도메인·항목 누락, 출처 누락·상태, 문제은행 문항 수·필수 메타데이터, 시험 범위·실무 확장 구분을 모두 점검하고 결과를 기록해야 한다. **검증 방법**: 다섯 검사 각각에 통과·실패·보류 상태와 근거가 있는지 확인한다.
- **FR6.2 링크와 제목 검사**: 내부 링크, 다음 문서 링크, 용어 사전 링크와 Markdown 제목 계층이 실제 대상 및 논리적 순서와 일치해야 한다. **검증 방법**: 링크 대상 존재 검사와 제목 계층 검사를 수행한다.
- **FR6.3 변경 범위 기록**: 문서를 작은 단위로 작성·검토하고, 변경된 출처·추적성·검토 결과를 해당 단계 기록에 남겨야 한다. **검증 방법**: 각 도메인 완료 기록에서 대상 문서와 변경 출처·점검 결과를 확인한다.
- **FR6.4 품질 검사 증거와 판정 기준**: 최종 검사 기록에는 다음 세 검사의 대상 범위, 검사일, 판정(`통과|실패|보류`), 근거, 발견 항목, 수정 또는 후속 조치를 남겨야 한다. (1) **초보자 관점 검사**: 선수 지식과 학습 목표가 명확하고, 쉬운 말 설명·예시·해당하는 경우 AWS 서비스 선택 단서·오개념 교정·확인 질문·다음 문서 링크가 모두 있는지 확인한다. (2) **개념 단위 검사**: 문서마다 하나의 주된 학습 목표를 선언하고, 그 목표를 직접 지원하는 하나의 핵심 개념 또는 밀접한 작은 묶음만 다루는지 확인한다. 임의의 줄 수 제한은 사용하지 않으며, 관련 없는 개념이 섞였으면 실패로 판정하고 문서를 분리하거나 연결 문서를 추가한다. (3) **민감정보 검사**: 검사 대상은 학습 자료, 예시, 로그, 출처 메타데이터, CSV와 변경된 파일이며, 실제 계정 식별자·토큰·자격 증명·개인정보 패턴을 검사한다. 발견 시 제거·치환·보류 조치와 재검사 결과를 기록한다. **검증 방법**: 세 검사 모두 `통과`이거나, 실패·보류 항목에 재검사 계획과 책임 시점을 남겨야 하며, 근거 없는 통과 판정은 허용하지 않는다.

## 3. Non-functional requirements

### NFR1. 초보자 접근성·가독성

모든 학습 자료와 검토 자료의 설명은 한국어를 기본으로 하며, 핵심 AWS 서비스명·API명·CLI 명령·URL·공식 문서 제목은 원문 표기를 보존해야 한다. 문서는 짧은 문단, 명확한 제목, 하나의 핵심 주장 중심으로 작성되어야 한다. **검증 방법**: 초보자 검토에서 선수 지식 없는 독자가 핵심 용어·예시·다음 학습 경로를 이해하는지 확인한다. [intent][scope]

### NFR2. Markdown 열람 호환성과 접근성

자료는 GitHub-Flavored Markdown과 일반 Markdown 뷰어에서 읽을 수 있어야 한다. 논리적 제목 계층, 키보드로 이동 가능한 Markdown 링크, 의미 있는 한국어 이미지 대체 텍스트, 이미지가 없어도 핵심을 이해할 수 있는 텍스트 대체 경로를 사용해야 한다. 이 요구사항은 정식 WCAG 적합성을 주장하지 않는다. **검증 방법**: 두 열람 환경에서 제목·링크·alt text·텍스트 대체 경로를 점검한다. [Q3]

### NFR3. 추적성 완전성과 ID 안정성

FR·NFR ID와 공식 기준선 행 ID(`AIF-C01-D<n>-T<n>`)는 문서가 개정되어도 재사용·중복·임의 변경하지 않는 영구 키로 관리해야 한다. 요구사항, 공식 항목, 학습 문서, 문제, 카드·퀴즈·Anki와 출처 사이의 정방향·역방향 연결을 재구성할 수 있어야 한다. **검증 방법**: ID 형식·고유성 검사와 추적성 표의 양방향 누락 검사를 수행하고, 확인된 기준선 행의 학습 문서·문제 매핑이 모두 존재하는지 확인한다.

### NFR4. 출처 신뢰성과 최신성 표시

외부 사실을 사용하는 자료는 공식 URL, 문서 제목, 확인 날짜와 접근 상태를 표시해야 하며, 확인되지 않은 내용은 `verified`로 표시하지 않아야 한다. 기능·모델명·요금·리전·할당량 등 변동 가능한 정보는 작성일 기준과 재확인 필요성을 명시해야 한다. **검증 방법**: 모든 외부 사실의 출처 메타데이터와 문서 상태를 대조한다.

### NFR5. 유지보수 가능한 문서 구조

파일명과 디렉터리명은 영문 소문자·숫자·하이픈만 사용하고, 문서는 개념 단위로 작게 유지하며, 도메인 README가 문서 읽기 순서를 제공해야 한다. **검증 방법**: 경로 규칙, 문서 크기·주제 범위, README 연결을 검사한다. [scope]

### NFR6. 인코딩·교환 형식 안정성

모든 Markdown은 UTF-8이어야 하며, Anki CSV는 UTF-8로 저장되고 앞면·뒷면 필드를 보존한 채 일반적인 CSV 파서로 읽혀야 한다. **검증 방법**: 인코딩 판별, CSV 구문 분석, 필드 수와 헤더 검사를 수행한다.

### NFR7. 개인정보·보안 최소화

학습자 계정, 답안·진도 저장, 개인정보, 결제정보, 건강정보, 자격 증명, 토큰 또는 실제 계정 식별자를 수집·저장·배포하지 않아야 한다. 정적 점수 워크시트는 학습자가 로컬에서 수기로 사용하는 안내 자료일 뿐 데이터를 전송하거나 저장하는 기능이 아니다. **검증 방법**: 산출물과 예시·로그에 민감정보 패턴과 실제 식별자가 없는지 검사하고, 민감정보 검사 범위·검사일·결과·수정 조치를 품질 기록에 남긴다. [scope]

### NFR8. 시험 범위와 실무 확장의 명확성

시험 범위, 실무 확장, 학습자용 해설·예시는 문서 전체가 아니라 섹션·항목·파생 자료 행 수준의 시각적 표지와 문장으로 구분되어야 한다. 공식 시험 항목을 설명하는 실무 확장은 원래 공식 기준선 ID를 먼저 표시하고 `실무 확장`으로만 분류한다. 가이드 작성 도표와 AWS 공식 이미지는 출처 표지와 텍스트 대체 설명으로 구분한다. 확인되지 않은 서비스 사실을 공식 시험 출제 범위로 표현하지 않아야 한다. **검증 방법**: 문서·문항·카드·Anki에 항목별 분류 표지, 기준선 ID, 도표·이미지 출처 및 텍스트 대체 경로가 있는지 일괄 검사한다. [scope][Q5]

### NFR9. 상대 일정의 실행 가능성

진도표는 특정 시험 날짜 없이 4주 단위로 제공되어야 하며, 각 주차의 목표·완료 기준·복습 및 문제 풀이를 학습자가 체크할 수 있어야 한다. **검증 방법**: 주차 수, 활동 배치, 완료 체크 항목을 검사한다. [Q1]

## 4. Constraints

### 4.1 범위·우선순위 제약

- 공식 AIF-C01 시험 안내서의 5개 도메인과 모든 작업·기술 항목을 기준으로 한다. 공식 안내서에 없는 내용은 시험 출제 범위라고 단정하지 않는다. [scope]
- 시험 합격을 최우선으로 하며, D1→D2→D3→D4→D5 순서로 작성한다. [intent][scope]
- 시험 핵심은 Must Have로 우선하고, 카드·퀴즈·진도표·Anki·용어 사전은 승인된 지원 산출물로 관리한다. [scope]

### 4.2 콘텐츠·언어 제약

- 대상은 코딩·수학·통계·모델 개발 경험이 없는 완전 초보자다.
- 사용자 질문, 설명, 검토 자료와 학습 문서는 한국어를 기본으로 한다. AWS 고유명사와 기술 식별자는 원문 표기를 보존한다.
- AWS 공식 문서를 1차 출처로 사용하며, 원문 전체를 복사하지 않는다.
- 시험 범위와 실무 확장을 문서·문항·카드·Anki에서 명시적으로 분리한다.

### 4.3 산출물·기술 제약

- 산출물은 정적 UTF-8 Markdown과 UTF-8 CSV다.
- 파일·디렉터리 이름은 영문 소문자·숫자·하이픈 규칙을 따른다.
- 외부 렌더러 없이도 핵심 내용을 이해할 수 있어야 하며, Mermaid나 이미지는 선택 사항이고 텍스트 설명을 함께 제공해야 한다.
- 실행형 학습 애플리케이션, API, 데이터베이스, 인프라와 장기 실행 환경은 만들지 않는다.

### 4.4 최신성·검증 제약

- 공식 범위 기준 목록을 등록한 뒤 D1 집필을 시작한다. 확인되지 않은 항목은 `확인 필요`로 남긴다. [Q4]
- 확인된 시험 범위 핵심 사실은 유지할 수 있지만, 확인되지 않은 AWS 서비스 세부사항에 의존하는 파생 자료는 공식 확인 전까지 보류한다. [Q5]
- 문항 작성 시 범위·정답·해설·공식 URL을 확인하고, 오답 선택지·난이도·중복은 최종 검토에서 일괄 점검한다. [Q6]

### 4.5 비용·개인정보 제약

- 유료 AWS 실습, AWS 계정 생성, 실습 비용을 요구하지 않는다.
- 학습자 개인정보·답안·진도·결제정보·건강정보를 수집하거나 저장하지 않는다.

## 7. Open questions

현재 승인된 제품 범위와 요구사항에 대한 추가 사용자 질문은 없다. 다음 항목은 범위를 다시 묻는 질문이 아니라 후속 단계에서 근거를 확정해야 하는 운영상 미해결 사항이다.

- **OQ1 — 공식 기준선 revision·행 확정**: D1 집필 전 AWS Certification 공식 AIF-C01 시험 안내서의 실제 URL, 문서 제목, revision·확인일과 세부 작업·기술 행을 `sources/`에 등록하고 `AIF-C01-D<n>-T<n>` ID를 부여해야 한다. 확인 전에는 관련 행을 `확인 필요` 또는 `blocked`로 유지한다. **영향**: 기준선 매핑과 D1 시작 조건.
- **OQ2 — 실제 문항 수와 배분**: 항목별 최소 커버리지를 먼저 충족하고 이후 공식 도메인 가중치를 따르는 규칙은 확정되었지만, 기준선 행 수에 따른 실제 도메인·작업/기술 항목별 문항 수는 공식 기준선 등록과 D1 시범 문항 검토 후 계산한다. **영향**: 문제은행 구성과 최종 누락 검사.
- **OQ3 — Anki 부가 필드**: 앞면·뒷면 필드와 기준선/출처 추적은 확정되었지만, 태그·출처·도메인 같은 추가 CSV 필드를 포함할지는 자료 생성 단계에서 호환성 검토 후 결정한다. **영향**: Anki 가져오기 안내와 추적성.
- **OQ4 — 차단된 공식 출처의 대체 경로**: 특정 공식 페이지가 동적·차단 상태일 경우 어떤 다른 공식 출처로 대체할지는 실제 차단 URL과 내용에 따라 결정하며, 확인 전에는 해당 주장을 확정하지 않는다. **영향**: 관련 문서·문항·카드·퀴즈·Anki의 보류 범위.
- **OQ5 — 품질 기록 파일 위치**: 초보자·개념 단위·민감정보 검사 증거의 최종 저장 파일과 도메인별 분할 방식은 집필 단계의 산출물 구조에서 정하되, 각 기록에는 대상·검사일·판정·근거·조치 필드를 반드시 보존한다. **영향**: FR6.1과 FR6.4의 완료 증거 연결.
