# 요구사항 분석 질문지

## 분석 개요

- **명확성**: 목적, 대상, 공식 범위, 작성 순서, 주요 산출물과 제외 범위가 명확하다. 세부 요구사항으로 변환하려면 학습 일정 표현, 정적 문서의 호환성·접근성 기준, 문제은행 품질 목표의 측정 방법을 정해야 한다.
- **유형**: 신규 정적 학습 콘텐츠·추적성 문서·평가 자료 작성 프로젝트다. 애플리케이션 개발이나 기존 시스템 변경은 아니다.
- **범위**: 저장소 전체에 걸친 다중 도메인 문서 프로젝트이며 D1부터 D5까지 순차적으로 작성한다.
- **복잡도**: 공식 시험 범위 추적, 최신성 통제, 100문항 이상 문제은행과 여러 파생 산출물이 필요하므로 `Comprehensive`로 본다.
- **모순·긴장 관계**: 1개월 이내 합격 우선과 장기 교재 활용, 완전 초보자용 상세 설명과 제한된 학습 시간 사이에 우선순위 조정이 필요하다. 현재 승인된 결정에 따르면 시험 핵심을 우선하고 실무 확장은 별도 표지로 제한한다.

## Q1. “1개월 이내” 진도표를 어떤 형태로 제공할까요?

정확한 시험 날짜는 사용하지 않기로 했으므로, 상대 일정 안에서 학습자가 실제로 따라갈 수 있는 기본 경로와 건너뛰기 기준을 정해야 합니다.

- A. 4주를 1주차~4주차로 나누고 D1~D5·복습·문제 풀이를 기본 배치한다.
- B. 주차를 고정하지 않고 `시작 전`, `핵심 학습`, `통합 복습`, `최종 점검` 단계로 제공한다.
- C. A를 기본으로 하되, 주차를 바꿔도 되는 체크리스트를 함께 제공한다.
- D. 시험 합격 핵심 경로만 먼저 제시하고 실무 확장·추가 읽을거리는 선택 경로로 분리한다.
- E. 아직 정하지 않음
- X. Other (please specify)

[Answer]: A

## Q2. 문제은행의 “전체 정답률 80% 이상” 목표를 어떻게 측정할까요?

상위 결정에는 80% 목표가 있지만, 이것이 학습자의 문제 풀이 성과인지 문항 사실 정확성인지 해석될 수 있습니다. 요구사항과 최종 점검의 증거를 일치시키기 위해 측정 대상을 확인합니다.

- A. 학습자가 문제은행 전체를 풀었을 때의 평균 정답률 80% 이상을 합격 준비 지표로 삼는다.
- B. 문항별 정답·해설의 사실 정확성을 독립 검토로 확인하고, 학습자 평균 정답률 80% 이상은 별도의 학습 지표로 둔다.
- C. A와 B를 모두 적용하되, 문항 사실 검토 결과와 학습자 풀이 결과를 별도 기록한다.
- D. 수치 목표는 학습자 평균 정답률 80%만 유지하고 문항 사실 검토는 정성 체크리스트로 관리한다.
- E. 두 의미가 섞여 있으므로 시범 문항 검토 후 측정 방식을 정한다.
- X. Other (please specify)

## Q3. 정적 Markdown 가이드의 기본 열람 환경과 접근성 기준을 어디까지 요구할까요?

실행형 웹 애플리케이션은 만들지 않으므로, 문서 품질 검증이 대상으로 삼을 Markdown 뷰어와 접근성 수준을 정해야 합니다. 이미 확정된 모바일 가독성, 논리적 제목, 명확한 링크, 색상 비의존 표지, 이미지 대체 경로 원칙은 유지합니다.

- A. GitHub-Flavored Markdown과 일반 Markdown 뷰어를 기본으로 하고, 논리적 제목·키보드로 이동 가능한 링크·의미 있는 한국어 alt text·텍스트 대체 경로를 검사하며 정식 WCAG 적합성은 주장하지 않는다.
- B. GitHub에서의 읽기 호환성을 우선하고, Mermaid·이미지 없이도 핵심 내용을 읽을 수 있는지와 링크·제목·alt text만 검사한다.
- C. 특정 뷰어에 종속하지 않고 일반 Markdown 문법·제목 계층·링크·alt text·모바일 가독성을 검사한다.
- D. 정적 문서에도 WCAG 2.1 AA 수준의 별도 접근성 점검을 요구한다.
- E. 기본 열람 환경과 정식 접근성 수준은 집필 전에 별도로 정한다.
- X. Other (please specify)

[Answer]: A

## Q4. 공식 시험 범위 기준 목록을 확보하기 전의 문서 작성 규칙을 어떻게 적용할까요?

현재 상위 결정은 AIF-C01 공식 안내서의 5개 도메인·모든 작업·기술 항목을 기준으로 삼도록 했지만, 이 단계에서 공식 원문 세부 항목을 새로 추측해서는 안 됩니다. 기준 목록 확보 전 집필 가능한 범위를 정해야 합니다.

- A. 공식 기준 목록을 먼저 등록한 뒤 D1 집필을 시작하며, 확인되지 않은 항목은 문서와 추적표에 `확인 필요`로 남긴다.
- B. 기준 목록이 확인된 도메인만 집필하고, 미확인 도메인은 공식 확인 후 순서대로 시작한다.
- C. 시험 범위 설명은 기준 목록 확보 전에는 작성하지 않고, 초보자용 AWS 기초 설명처럼 시험 범위와 분리된 내용만 초안으로 준비한다.
- D. 공식 안내서의 세부 항목은 확인 전에도 상위 승인 문서에 적힌 표현만 사용해 초안을 만들고, 확인 전 상태를 명시한다.
- E. 기준 목록 확보 방식과 집필 시작 조건을 추후 정한다.
- X. Other (please specify)

[Answer]: A

## Q5. 확인되지 않은 최신 AWS 서비스 사실이 문제·카드·Anki 자료에 미치는 영향을 어떻게 처리할까요?

서비스 기능·모델명·요금·리전·할당량은 변할 수 있고, 확인되지 않은 주장은 확정하지 않기로 했습니다. 원본 개념 문서와 그 문서에서 파생되는 평가 자료의 일관된 보류 규칙이 필요합니다.

- A. 관련 문서·문항·카드·Anki 항목을 모두 `확인 필요`로 표시하고, 공식 확인 전에는 정답 근거로 사용하지 않는다.
- B. 시험 범위 핵심 사실만 확인될 때까지 유지하고, 서비스 세부사항에 의존하는 파생 자료만 보류한다.
- C. 확인되지 않은 항목은 해당 버전에서 제외하고, 확인된 항목만으로 문서·문항·카드·Anki를 만든다.
- D. 원래 주장과 확인 날짜를 기록한 뒤 초안에는 포함하되, 최종 `verified` 상태와 최종 문제은행에서는 제외한다.
- E. 항목 유형별 보류 규칙을 집필 중에 정한다.
- X. Other (please specify)

[Answer]: B

## Q6. 100문항 이상 문제은행의 문항 검토 완료 기준을 어떻게 운영할까요?

문항마다 도메인·작업/기술 항목·정답·해설·공식 URL을 기록하는 것은 이미 확정되었습니다. 추가로 문항의 시나리오 적합성, 오답 선택지의 타당성, 초보자 난이도와 중복을 어느 수준에서 확인할지 정해야 합니다.

- A. 모든 문항에 대해 범위 추적·정답·해설·공식 URL·오답 선택지·초보자 이해 가능성을 체크하고, 발견된 문제를 수정한 뒤 문항을 확정한다.
- B. 모든 문항은 범위·정답·해설·공식 URL을 필수 검토하고, 오답 선택지·난이도·중복은 도메인별 표본 검토로 확인한다.
- C. 모든 문항을 독립적으로 재검토하되, 오답 선택지와 난이도는 문제은행 전체 요약 점검으로 관리한다.
- D. 문항을 만들 때는 범위·정답·해설·URL만 확인하고, 오답 선택지·난이도·중복은 최종 검토 단계에서 한 번에 확인한다.
- E. 문항 검토 기준을 D1 시범 문항 작성 후 확정한다.
- X. Other (please specify)

[Answer]: D
