# 협업 구성

## 운영 모델

이 프로젝트는 상시 다인 mob이 아니라 **단일 작성자 중심의 문서 스트림**으로 운영한다. 사용자는 Product Owner이자 최종 승인자이고, Kiro/AIDLC 에이전트는 필요한 시점에 짧은 역할별 검토 mob으로 참여한다. 이는 승인된 `TF-06` 결정과 단일 작성자 용량 가정에 따른다.

- 단일 작성자는 초안의 일관성과 순차 집필을 책임진다.
- 논점이 불확실하거나 위험한 경우에만 제품, 전달, 출처·규정 준수, 품질·디자인 역할을 함께 검토한다.
- Kiro/AIDLC 역할은 협업과 검토를 제공하지만 범위·공식 해석·출시를 독자적으로 확정하지 않는다.
- 외부 파트너와 AWS Professional Services는 구성에 포함하지 않는다.

## 역할 구성

| 역할 | 사람·지원 주체 | 주된 책임 | 참여 방식 |
|---|---|---|---|
| Product Owner / 최종 승인자 | 사용자 | 범위·우선순위, 공식 시험 범위 해석, 보류·변경, 최종 출시 승인 | 각 승인 게이트와 주요 쟁점에서 결정 |
| 작성 리드 | 단일 작성자 | D1~D5 문서, 문제은행, 카드·퀴즈·진도표·Anki 초안 | 순차 집필과 수정 |
| 제품·범위 내비게이터 | Kiro/AIDLC 제품 역할 | 학습자 가치, 범위 경계, 시험/실무 구분 | 착수·범위 변경·도메인 검토 |
| 전달·인계 내비게이터 | Kiro/AIDLC 전달 역할 | `PU` 순서, 의존성, 완료 증거, 다음 단계 인계 | 각 문서 묶음과 산출물 전환 시점 |
| 출처 검증 내비게이터 | Kiro/AIDLC 공식 출처·규정 준수 역할 | 공식 시험 안내서·AWS 출처·최신성·차단 상태 | 작성 전·작성 후·최종 검토 |
| 초보자·형식 검토 내비게이터 | Kiro/AIDLC 품질·디자인 역할 | 한국어 이해도, 문서 구조, 문제·CSV·링크 QA | 도메인별 검토와 최종 점검 |
| 구조·추적성 지원 역할 | Kiro/AIDLC 아키텍처·개발 역할 | 안정 ID, 문서 간 연결, 형식 일관성 | 추적표·문항·지원 자료 파생 시 |

## 생명주기별 구성

| 생명주기 | 주도 역할 | 지원 역할 | 사용자 승인 지점 |
|---|---|---|---|
| Ideation | 사용자, 제품 역할, 전달 역할 | 출처·품질 역할의 위험 의견 | 범위, 단일 작성자 방식, 역할 구성, 통합 요약 |
| Inception | 전달 역할, 요구사항·아키텍처 역할 | 출처·규정 준수 역할, 제품 역할 | 공식 항목별 추적 계획과 인계 조건 |
| Construction 수준의 집필·검증 | 단일 작성자 | 품질·디자인, 출처·규정 준수, 개발·아키텍처 역할 | 도메인 문서 묶음과 지원 자료의 완료 |
| 최종 검토·출시 | 사용자 / Product Owner | 전달, 출처·규정 준수, 품질·디자인 역할 | `PU-12` 최종 평가와 최종 출시 |

여기서 Construction 수준의 집필·검증은 소프트웨어 구현을 뜻하지 않는다. 문서·문항·CSV를 작은 단위로 작성하고 검증하는 작업을 의미하며, 코드·인프라·실행형 학습 애플리케이션은 범위 밖이다.

## 검토와 승인 의존성

1. `PU-00` 공식 시험 범위·출처 기준선이 먼저 확인되어야 한다.
2. `PU-01`부터 `PU-05`까지 D1→D5 순서로 작성하며, 각 도메인은 출처 확인과 초보자 관점 검토 후 다음 도메인으로 인계한다.
3. `PU-06` 추적표의 고아 항목이 0개이고 출처 상태가 확인되어야 `PU-07` 문제은행을 만든다.
4. 문제은행의 문항별 필수 메타데이터와 출처가 확인되어야 `PU-08`~`PU-11` 지원 자료를 파생한다.
5. `PU-12`에서는 도메인 누락, 출처·링크, 문항 메타데이터, 초보자 관점, 시험/실무 구분, 산출물 형식의 6개 점검을 수행한다.
6. 모든 미확인 내용은 `확인 필요`로 유지하며, 사용자가 최종 출시를 승인하기 전에는 `verified` 또는 완료로 단정하지 않는다.

## 역할 간 소통 규칙

- 범위나 공식 해석이 충돌하면 출처·규정 준수 역할의 근거를 먼저 정리하고 사용자에게 선택지를 보고한다.
- 설명이 초보자에게 어렵다는 검토가 나오면 단일 작성자가 문서를 수정하고 품질 역할이 재검토한다.
- 추적표·문항·지원 자료의 불일치는 전달 역할이 원본 문서와 `PU` 의존성을 기준으로 정리한다.
- 질문 파일과 승인된 결정은 변경하지 않고, 변경이 필요하면 별도 사용자 승인과 영향 분석을 거친다.

## 추적성

이 구성은 `scope-document.md`의 가치 흐름과 의존성, `intent-backlog.md`의 생산 순서, `feasibility-assessment.md`의 실행 통제와 `TF-01`~`TF-07` 결정에 근거한다. 단일 작성자 구조는 `PU-01`~`PU-05`의 순차 집필을, 검토 역할은 `PU-06`~`PU-12`의 추적·품질 완료 증거를 지원한다.
