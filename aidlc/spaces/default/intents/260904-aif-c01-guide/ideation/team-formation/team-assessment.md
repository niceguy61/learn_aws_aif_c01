# 팀 평가

## 목적과 계획 수준

이 문서는 AIF-C01 한국어 학습 가이드의 집필·검토를 수행할 역량, 가용성, 의사결정 권한과 위험 완화 방식을 정의한다. 구현 아키텍처나 실행 코드를 결정하지 않으며, Ideation 단계의 전달 계획으로만 사용한다.

## 기준과 추적성

- `scope-document.md`: 5개 도메인 D1~D5, 완전 초보자 대상, D1→D5 순서, 100문항 이상과 지원 자료, 시험 범위와 실무 확장의 분리.
- `intent-backlog.md`: `PU-00` 공식 기준선, `PU-01`~`PU-05` 도메인 문서, `PU-06` 추적표, `PU-07` 문제은행, `PU-08`~`PU-11` 지원 자료, `PU-12` 최종 점검, `PU-13` 범위 밖 기록.
- `feasibility-assessment.md`: 조건부 실행 가능 판정, 출처 최신성·접근 차단·문항 추적성·Anki 형식·데이터 경계 통제.
- 수용 기준: `AC-SCOPE-01`~`AC-SCOPE-09`를 팀의 완료 판단 기준으로 사용한다.

## 용량과 가용성 가정

- **작성 구조**: 단일 작성자가 순차적으로 집필하고, 사용자가 제품 소유자(Product Owner) 겸 최종 승인자가 된다.
- **가용성**: 이 프로젝트에 필요한 작성·검토 용량을 단일 작성자 기준으로 계획한다. 여러 작성자의 병렬 용량, 시간대, 경쟁 이니셔티브와 외부 계약자의 가용성은 별도로 산정하지 않는다.
- **작업 방식**: D1부터 D5까지 작은 문서 단위로 작성하고, 각 도메인에서 출처 확인과 초보자 관점 검토를 거친다. 불확실한 내용은 확정하지 않고 `확인 필요`로 남긴다.
- **외부 의존성**: 외부 파트너와 AWS Professional Services는 사용하지 않는다. 공식 출처 확인과 교육 품질 검토는 저장소 안에서 Kiro/AIDLC 지원 역할로 수행한다.

## 역할 및 책임

| 역할 | 담당 범위 | 권한과 산출물 |
|---|---|---|
| 사용자 / Product Owner | 범위, 우선순위, 공식 범위 해석, 보류·변경, 최종 출시 | 최종 결정과 승인. 근거 없는 범위 확장과 확인되지 않은 사실을 거부할 권한을 가진다. |
| 단일 작성자 | 도메인 문서, 문제은행, 카드·퀴즈·진도표·Anki 작성 | 승인된 범위 안에서 초안을 만들고 안정 ID와 출처 연결을 유지한다. |
| Kiro/AIDLC 제품 역할 | 학습자 가치, 범위 경계, 우선순위 검토 | 제안과 검토 의견을 제공하며 사용자 승인 없이 확정하지 않는다. |
| Kiro/AIDLC 전달 역할 | 순서, 의존성, 체크리스트, 인계와 완료 증거 | `PU` 단위의 작업 순서와 검토 의존성을 관리한다. |
| Kiro/AIDLC 공식 출처·규정 준수 역할 | 공식 시험 범위, AWS 링크, 최신성, 시험/실무 구분 | 출처 검증 결과와 보류 사유를 제공한다. |
| Kiro/AIDLC 품질·디자인 역할 | 초보자 이해도, 문서 구조, 문제·CSV·링크 QA | 누락·오해·형식 오류를 찾아 수정 의견을 제공한다. |
| Kiro/AIDLC 개발·아키텍처 역할 | 문서 구조의 일관성, 안정 ID, 산출물 간 연결과 형식 점검 | 코드나 인프라를 만들지 않고 문서 산출물의 구조적 완결성을 지원한다. |

## RACI와 결정권

`R`은 실행 책임, `A`는 최종 책임·승인, `C`는 협의, `I`는 결과 공유를 뜻한다. 한 작업의 `A`는 사용자 / Product Owner로 고정한다.

| 결정·작업 | 사용자 / PO | 단일 작성자 | 제품·전달 역할 | 출처·규정 준수 역할 | 품질·디자인 역할 |
|---|---:|---:|---:|---:|---:|
| 범위·우선순위와 변경 | A | R | C | C | I |
| 공식 시험 범위 해석 | A | R | C | R | C |
| 공식 출처 조사·검증 | A | C | C | R | C |
| 초보자 교육 품질 검토 | A | R | C | C | R |
| D1~D5 도메인 문서 작성 | A | R | C | C | C |
| 100문항 이상 문제은행 | A | R | C | C | R |
| 카드·퀴즈·진도표·Anki 등 지원 자료 | A | R | C | C | R |
| 최종 출시 및 공개 가능 판정 | A | R | C | C | R |

사용자는 최종 승인자이며, Kiro/AIDLC 역할은 근거·초안·검토 의견을 제공한다. 역할 간 의견이 다르면 공식 출처와 승인된 범위를 우선해 사용자에게 보류 또는 선택지를 보고한다.

## 주요 위험과 통제

| 위험 | 가능성·영향 | 통제와 완료 증거 |
|---|---|---|
| 공식 출처가 변경되거나 접근되지 않음 | 중간·높음 | 도메인 작성 직전과 최종 검토에서 재확인하고 `source_checked`, 상태, URL, 차단 사유를 기록한다. 확인되지 않은 주장은 `확인 필요`로 보류한다. (`PU-00`, `PU-06`, `AC-SCOPE-05`) |
| 한국어 설명이 초보자에게 어렵거나 영어 용어가 고립됨 | 중간·높음 | 최초 등장 시 영어 병기, 선수 지식, 쉬운 예시, 비교, 오해와 확인 질문을 포함하고 품질 역할이 초보자 관점으로 검토한다. (`PU-01`~`PU-05`, `AC-SCOPE-02`) |
| AIF-C01 작업·기술 항목이 누락됨 | 중간·높음 | 공식 기준선과 도메인별 추적표를 먼저 만들고 각 항목을 문서 또는 `해당 없음/확장` 기록에 연결한다. (`PU-00`, `PU-06`, `AC-SCOPE-01`) |
| 문제·카드·문서의 원천 연결이 끊어짐 | 중간·높음 | 안정 ID, 도메인, 작업·기술 항목, 원문 출처 URL을 필수 필드로 확인한 후 파생 자료를 만든다. (`PU-06`~`PU-11`, `AC-SCOPE-03`, `AC-SCOPE-06`) |
| 문서·문항의 품질 검토가 집필보다 늦어짐 | 중간·중간 | 도메인 단위로 작성 직후 출처·초보자·시험/실무 구분 검토를 수행하고, 최종에 6개 점검을 반복한다. (`PU-12`, `AC-SCOPE-07`) |
| CSV 인코딩·필드·Markdown 링크 오류 | 중간·중간 | UTF-8, 앞면·뒷면 필드, 행 수와 빈 값, 링크·front matter·문서 간 링크를 기계적·수동으로 함께 점검한다. (`PU-11`, `AC-SCOPE-05`, `AC-SCOPE-06`) |

## Team Formation 완료 기준

- 단일 작성자 용량과 사용자 최종 승인권이 기록되어 있다.
- 필수 역량·현재 지원 방식·간극·완화책이 `skill-matrix.md`와 연결되어 있다.
- 범위, 출처, 문항, 지원 자료, 최종 출시의 RACI가 정의되어 있다.
- 외부 파트너와 AWS Professional Services가 계획에서 제외되어 있다.
- 생명주기별 역할 구성과 검토·승인 의존성이 `mob-composition.md`에 기록되어 있다.
- 사용자 승인 질문 파일에는 통합 요약 승인인 `[Answer]: Looks correct`가 정확히 한 번 존재한다.
