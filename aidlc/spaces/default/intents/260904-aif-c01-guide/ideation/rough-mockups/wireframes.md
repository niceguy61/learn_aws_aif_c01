# 정적 Markdown 학습 가이드 문서 와이어프레임

## 문서 상태와 설계 범위

- 상태: 초안
- 설계 대상: 애플리케이션 화면이 아닌 정적 한국어 Markdown 문서의 탐색 구조
- 핵심 사용자: AI·ML과 AWS를 처음 접하는 학습자
- 시작점: `docs/00-start-here/`
- 주 학습 순서: D1 → D2 → D3 → D4 → D5
- 연결 백로그: PU-00~PU-13
- 관련 수용 기준: AC-SCOPE-01~AC-SCOPE-09
- 최종 점검 문서: `docs/06-exam-strategy/quality-check.md` (PU-12)

이 와이어프레임은 브라우저나 Markdown 뷰어에서 문서가 어떻게 읽히고 연결되는지를 설명한다. 로그인, 사용자 데이터 저장, 자동 진도 저장, 검색 애플리케이션, 모달과 화면 전환은 설계하지 않는다.

## 설계 원칙

1. 문서의 제목과 현재 학습 목적을 가장 먼저 보여 준다.
2. 한 문서는 하나의 핵심 개념을 중심으로 짧게 구성한다.
3. `시험 범위`와 `실무 확장`을 제목과 텍스트 표지로 분리한다.
4. 모든 문서는 이전 문서, 용어 사전, 다음 문서와 연결한다.
5. 공식 출처와 확인일은 문서 안에서 바로 찾을 수 있어야 한다.
6. 색상이나 아이콘만으로 상태를 표현하지 않는다.
7. 모바일에서 먼저 읽을 수 있도록 긴 표와 긴 문단을 피한다.

## 문서 공통 머리 영역

각 README와 개념 문서는 아래 순서로 시작한다.

```text
┌────────────────────────────────────────────────────────┐
│ [h1] 문서 제목                                         │
│ 도메인: D1 | 수준: 초보자 | 상태: draft                │
│ 시험 항목: D1-T01, D1-T02                              │
│ 학습 목표: 이 문서를 읽고 할 수 있는 판단              │
├────────────────────────────────────────────────────────┤
│ 선수 지식: 먼저 읽을 문서  →  용어 사전                │
│ 한 줄 요약: 핵심 개념을 한 문장으로                    │
├────────────────────────────────────────────────────────┤
│ [학습 진단 분기]                                      │
│ - AI·AWS 용어가 낯섦 → 선수 지식 → D1 시작             │
│ - 기본 용어는 앎 → D1 진단 질문 → 필요한 D1 문서       │
│ - D1 복습 필요 → D1 README의 복습 경로                │
├────────────────────────────────────────────────────────┤
│ [본문으로 건너뛰기]                                    │
│ [h2] 핵심 개념                                         │
└────────────────────────────────────────────────────────┘
```

실제 Markdown에서는 박스 문자를 구현 요소로 요구하지 않는다. 위 구조를 제목, 짧은 문단, 목록, 링크로 재현한다. `본문으로 건너뛰기`는 사용자 정의 HTML 앵커를 지원하는 뷰어에서만 선택적으로 제공한다. 순수 Markdown 뷰어에서는 문서 목차와 논리적인 `h1`·`h2` 제목을 실제 대체 경로로 사용하며, 핵심 내용이 skip link에 의존하지 않도록 한다.

### 텍스트 대체 설명

첫 문서에는 가이드의 목적, 대상, D1~D5 순서, 지원 자료와 범위 표지를 짧은 목록으로 제공한다. 학습자는 계정이나 설정 없이 첫 학습 문서로 이동할 수 있다.

### 문서 상태 변형

- 정상: 모든 도메인 README와 지원 자료 링크가 보인다.
- 링크 확인 필요: 링크 옆에 `확인 필요`와 원인 또는 대체 경로를 텍스트로 표시한다.
- 긴 화면: 도메인 링크를 한 열의 목록으로 쌓고 한 행에 여러 링크를 넣지 않는다.

### 텍스트 대체 설명

도메인 README는 도메인의 학습 허브다. 먼저 공식 시험 비중과 학습 목표를 보여 주고, 그 다음 공식 항목별 개념 문서와 복습 자료를 순서 있는 목록으로 연결한다. 마지막에는 문서·출처·상태를 확인할 수 있는 추적성 표와 다음 도메인 링크를 둔다.

### 모바일 배치

데스크톱에서 학습 지도는 짧은 흐름으로 보일 수 있지만, 모바일에서는 각 개념을 순서 있는 목록으로 먼저 제시한다. 넓은 추적성 표는 `시험 항목`, `문서`, `상태` 정도의 세 열로 제한하고, 출처 URL과 세부 설명은 각 문서 링크 또는 아래 목록으로 분리한다.

```text
- 추적 ID: 문서 ID, 시험 항목 ID, 출처 ID
```

### 텍스트 대체 설명

개념 문서는 제목과 선수 지식부터 시작해 쉬운 설명, AWS 관점, 비교, 시나리오, 시험 단서, 오해, 확인 질문의 순서로 읽힌다. `시험 범위`와 `실무 확장`은 별도 제목 또는 인용 블록으로 표시하며, 두 구획을 같은 문단에 섞지 않는다.

### 문서 상태 변형

- 초안: `status: draft`와 미확정 내용을 `확인 필요`로 표시한다.
- 검토 중: `status: review`와 검토 대상 출처를 표시한다.
- 검증 완료: 모든 사실 출처와 확인일을 확인한 뒤에만 `status: verified`로 바꾼다.
- 출처 차단: 내용을 추측하지 않고 URL, 차단 상태, 후속 확인 대상을 남긴다.

### 텍스트 대체 설명

복습 자료는 별도 실행 기능이 아니라 링크된 Markdown·CSV 자료다. 오답을 원 개념으로 되돌리는 회귀 링크를 모든 자료에 제공한다. 문제와 카드는 새 사실을 독자적으로 만들지 않고 확정된 도메인 문서와 출처에서 파생한다.

## 표지와 링크 규칙

| 의미 | 항상 표시할 텍스트 | 색상 의존 금지 대안 |
|---|---|---|
| 공식 범위 | `시험 범위` | 공식 항목 ID와 설명 |
| 실무 보강 | `실무 확장` | 시험 범위가 아님을 설명하는 문장 |
| 미확인 | `확인 필요` | 원인·URL·후속 조치 |
| 검증 완료 | `검증 완료` | 확인일과 출처 상태 |
| 다음 이동 | `다음 문서` | 목적이 드러나는 링크 텍스트 |

링크 텍스트는 `여기` 대신 `D2 GenAI의 기초 읽기`처럼 목적을 포함한다. 같은 문서로 돌아가는 링크는 `D1 개념 문서: 지도학습과 비지도학습`처럼 원인을 설명한다.

## 접근성 및 가독성 주석

- 문서마다 하나의 `h1`만 사용하고 `h2`와 `h3`를 건너뛰지 않는다.
- 목록은 목록 문법, 비교는 작은 표, 절차는 순서 있는 목록으로 표현한다.
- 표에 넣기 어려운 정보는 표 아래에 같은 의미의 짧은 목록으로 다시 설명한다.
- 일반 본문은 충분한 대비를 갖는 기본 텍스트를 사용하며 색상만으로 의미를 전달하지 않는다.
- 링크는 키보드로 이동할 수 있는 기본 Markdown 링크로 작성하고 링크 목적을 명확히 한다.
- ASCII 다이어그램은 장식이 아니라 구조 설명이며, 반드시 바로 뒤에 텍스트 대체 설명을 둔다.
- 코드 블록이나 명령은 학습에 필요한 경우에만 사용하고, 코드의 의미를 문장으로도 설명한다.
- 특수문자에 의존하는 상태 표시는 `시험 범위`, `실무 확장`, `확인 필요` 같은 텍스트 표지와 함께 사용한다.
- 긴 URL은 본문 표에 그대로 반복하지 않고 설명 링크와 출처 목록으로 분리한다.
- 접기나 탭을 사용하는 Markdown 뷰어에서는 키보드로 열고 닫을 수 있어야 하며, 기본 상태에서도 핵심 내용이 읽혀야 한다.
- 글자 크기를 확대하거나 화면 폭이 좁아져도 문장이 잘리지 않도록 고정 폭 레이아웃과 가로 스크롤을 요구하지 않는다.
