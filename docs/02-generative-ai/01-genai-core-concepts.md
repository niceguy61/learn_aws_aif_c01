# GenAI 핵심 개념

## 이 문서에서 배울 것

이 문서는 생성형 AI를 처음 접하는 학습자를 위해 토큰·토큰화·청킹·임베딩·벡터·프롬프트를 설명합니다. 그 다음 Transformer·LLM·파운데이션 모델·멀티모달 모델·확산 모델을 구분하고, GenAI 애플리케이션과 에이전트가 어떤 역할을 하는지 연결합니다.

## 선수 지식과 한 줄 요약

- 선수 지식: D1에서 AI·ML·딥 러닝·추론의 차이를 학습하면 좋습니다.
- 한 줄 요약: **GenAI는 입력을 작은 단위로 처리하고, 컨텍스트를 바탕으로 새로운 결과를 생성하는 모델을 애플리케이션에 연결하는 기술입니다.**

## GenAI와 기존 예측·분류형 ML 비교

기존 ML 모델은 “이 입력이 어느 범주인가?” 또는 “숫자 값은 얼마인가?”처럼 정해진 형태의 결과를 예측하는 경우가 많습니다. GenAI는 질문에 대한 답변, 요약, 이미지, 음성처럼 새로운 콘텐츠를 만들 수 있습니다.

GenAI가 새로운 것을 만든다는 말은 아무 근거 없이 창작한다는 뜻이 아닙니다. 모델은 학습한 패턴과 주어진 입력·컨텍스트를 바탕으로 결과를 생성합니다. 따라서 결과가 사실인지, 요청에 맞는지, 안전한지 별도로 확인해야 합니다.

## 토큰과 토큰화

### 토큰이란?

토큰(token)은 모델이 입력과 출력을 처리하기 위해 사용하는 텍스트 단위입니다. 토큰은 항상 단어 하나와 같지는 않습니다. 짧은 단어는 하나의 토큰이 될 수도 있고, 긴 단어나 기호·공백은 여러 토큰으로 나뉠 수 있습니다.

토큰을 이해해야 하는 이유는 세 가지입니다.

- 모델이 읽고 생성할 수 있는 컨텍스트 크기와 관련됩니다.
- 토큰 수가 입력·출력 처리량과 연결됩니다.
- 토큰 기반 가격 모델에서는 사용량과 비용에 영향을 줄 수 있습니다.

### 토큰화는 무엇인가요?

토큰화(tokenization)는 문장이나 문서를 모델이 처리할 토큰 단위로 나누는 과정입니다. 같은 글이라도 언어, 기호, 공백, 숫자 구성에 따라 토큰 수가 달라질 수 있습니다.

시험에서는 토큰을 “모델이 텍스트를 처리하는 단위”로 이해하고, 토큰 수가 컨텍스트·지연 시간·비용과 연결될 수 있다는 점을 기억합니다.

## 청킹

청킹(chunking)은 긴 문서나 데이터를 작은 조각으로 나누는 과정입니다. 한 번에 다루기 어려운 책을 필요한 주제별 쪽지로 나누는 것에 비유할 수 있습니다.

청크가 너무 크면 검색 결과에 불필요한 내용이 많이 섞일 수 있고, 너무 작으면 문맥이 끊길 수 있습니다. 따라서 청킹은 검색·질문 응답·문서 처리 애플리케이션에서 컨텍스트 품질에 영향을 줍니다.

청킹은 단순히 문서 크기를 줄이는 작업이 아닙니다. 제목·문단·표·문서 구조와 의미가 가능한 한 유지되도록 나누는 것이 목적입니다.

## 임베딩과 벡터

### 임베딩

임베딩(embedding)은 텍스트·이미지 같은 데이터를 모델이 비교할 수 있는 수치 표현으로 변환한 것입니다. 문장의 의미를 숫자 공간의 위치로 표현한다고 생각하면 됩니다.

의미가 비슷한 문장이라면 임베딩 공간에서 서로 가까운 위치에 놓일 수 있습니다. 이것은 단어가 똑같은지보다 의미가 비슷한지를 비교하는 데 도움을 줄 수 있습니다.

### 벡터

벡터(vector)는 여러 숫자로 이루어진 값입니다. 임베딩 결과는 벡터로 표현될 수 있으며, 벡터 간 유사도를 계산해 관련 문서나 비슷한 항목을 찾을 수 있습니다.

임베딩은 “의미를 숫자로 바꾸는 변환”이고 벡터는 “그 결과를 표현하는 숫자 묶음”이라는 차이로 기억합니다.

## 프롬프트 엔지니어링

프롬프트(prompt)는 모델에 전달하는 지시·질문·컨텍스트입니다. 프롬프트 엔지니어링은 원하는 결과를 얻기 위해 지시, 배경 정보, 예시, 출력 형식을 설계하고 개선하는 과정입니다.

좋은 프롬프트는 단순히 길기만 한 프롬프트가 아닙니다. 다음 요소가 분명해야 합니다.

- 모델이 해야 할 작업
- 작업의 목적과 필요한 컨텍스트
- 결과의 형식과 제한 조건
- 필요한 경우 참고할 예시

프롬프트를 바꿔도 모델의 지식이 자동으로 새 데이터로 영구 변경되는 것은 아닙니다. 프롬프트는 요청 시점의 입력을 설계하는 방법이고, 모델을 수정하는 훈련·미세 조정과는 다릅니다.

## Transformer와 LLM

### Transformer

Transformer는 입력의 여러 부분 사이 관계를 살펴 문맥을 처리하는 신경망 아키텍처입니다. 문장에서 멀리 떨어진 단어 사이의 관계를 처리하는 데 강점을 보이며, 현대 언어 모델의 중요한 기반으로 사용됩니다.

### 대규모 언어 모델(LLM)

LLM(Large Language Model)은 많은 텍스트 패턴을 학습하고 언어를 이해·생성하도록 설계된 대규모 모델입니다. 질문에 답하거나 문장을 요약·변환·생성할 수 있습니다.

Transformer는 모델을 만드는 아키텍처이고 LLM은 언어 작업을 수행하는 대규모 모델이라는 점을 구분합니다.

## 파운데이션 모델과 멀티모달 모델

### 파운데이션 모델

파운데이션 모델(FM)은 다양한 작업의 기반으로 활용할 수 있도록 대규모 데이터에서 사전 훈련된 모델입니다. 하나의 특정 업무만 수행하도록 처음부터 만든 모델과 달리, 프롬프트·추가 학습·검색 연결 등을 통해 여러 애플리케이션에 적용할 수 있습니다.

파운데이션 모델이 모든 문제를 자동으로 해결한다는 뜻은 아닙니다. 모델의 모달리티, 성능, 비용, 지연 시간, 안전성, 라이선스와 사용 조건을 함께 평가해야 합니다.

### 멀티모달 모델

멀티모달 모델은 텍스트만이 아니라 이미지·오디오·비디오 같은 여러 형태의 입력이나 출력을 다룰 수 있는 모델입니다. “사진을 보고 설명하기”처럼 서로 다른 데이터 형태를 함께 처리하는 작업에 연결할 수 있습니다.

모델이 멀티모달이라고 해서 모든 모달리티의 입력과 출력을 모두 지원한다고 단정하면 안 됩니다. 실제 지원 범위는 모델별 공식 문서를 확인해야 합니다.

## 확산 모델

확산 모델(diffusion model)은 이미지·오디오·비디오 같은 콘텐츠 생성에 사용되는 모델 유형 중 하나입니다. 잡음이 있는 표현에서 시작해 반복적으로 품질을 높이는 방식으로 새로운 콘텐츠를 생성하는 직관으로 이해할 수 있습니다.

시험에서는 세부 수학보다 “확산 모델이 생성형 이미지·오디오·비디오 작업과 연결될 수 있다”는 관계가 중요합니다.

## GenAI 사용 사례와 에이전트

GenAI는 다음과 같은 작업에 사용될 수 있습니다.

- 요약과 번역
- 질문 응답과 대화형 어시스턴트
- 콘텐츠·코드 생성
- 검색·추천 결과를 이해하기 쉬운 답변으로 변환
- 고객 서비스 지원

에이전트 AI(agentic AI)는 모델이 단순히 한 번 답변하는 것을 넘어, 목표를 달성하기 위해 여러 단계의 작업을 계획하고 도구나 외부 시스템을 사용할 수 있게 구성한 애플리케이션 패턴입니다.

에이전트 애플리케이션에는 다음 요소가 연결될 수 있습니다.

- **도구 사용**: 검색, 데이터 조회, 업무 시스템 호출
- **메모리**: 이전 상호 작용이나 작업 상태 활용
- **오케스트레이션**: 여러 단계와 도구 실행 순서 관리
- **다중 에이전트**: 역할을 나눈 여러 에이전트의 협력

이 문서에서는 에이전트의 기본 구성만 다룹니다. 구체적인 AWS AgentCore 기능과 보안은 후속 문서에서 별도로 구분합니다.

## 비교표

| 개념 | 무엇을 설명하나요? | 대표 단서 |
|---|---|---|
| 토큰 | 모델이 텍스트를 처리하는 단위 | 입력·출력 길이, 사용량 |
| 청킹 | 긴 자료를 작은 조각으로 나누는 과정 | 문서 검색, 컨텍스트 분할 |
| 임베딩 | 데이터를 의미를 반영하는 수치 표현으로 바꾸는 과정 | 의미 유사도, 검색 |
| 벡터 | 여러 숫자로 이루어진 표현 | 거리·유사도 비교 |
| 프롬프트 | 모델에 전달하는 지시와 입력 | 명령, 예시, 출력 형식 |
| Transformer | 문맥 관계를 처리하는 모델 아키텍처 | 언어 모델의 기반 |
| LLM | 언어를 이해·생성하는 대규모 모델 | 텍스트 질문·생성 |
| FM | 여러 애플리케이션의 기반이 되는 사전 훈련 모델 | 재사용, 사용자 지정 |
| 멀티모달 모델 | 여러 데이터 모달리티를 다루는 모델 | 텍스트·이미지·오디오 |
| 확산 모델 | 콘텐츠 생성에 사용되는 모델 유형 | 이미지·오디오·비디오 생성 |

## 시험에서 판단하는 단서

- “입력을 작은 단위로 쪼갠다” → 토큰화 또는 청킹인지 구분합니다. 모델 처리 단위면 토큰화, 긴 문서 조각이면 청킹입니다.
- “의미가 비슷한 자료를 수치로 비교한다” → 임베딩과 벡터를 연결합니다.
- “모델에 지시·예시·출력 형식을 전달한다” → 프롬프트 엔지니어링입니다.
- “여러 작업의 기반이 되는 사전 훈련 모델” → 파운데이션 모델입니다.
- “텍스트와 이미지를 함께 입력하거나 처리한다” → 멀티모달 모델입니다.
- “새로운 이미지나 오디오를 생성한다” → 확산 모델 같은 생성 모델 유형을 고려합니다.
- “외부 시스템을 호출하고 여러 단계를 수행한다” → 도구 사용과 에이전트 오케스트레이션을 연결합니다.

## 자주 하는 오해

### 오해 1: 토큰은 항상 단어 하나다

토큰은 모델이 처리하는 텍스트 단위이며 단어와 정확히 일치하지 않을 수 있습니다.

### 오해 2: 청킹과 토큰화는 같은 작업이다

토큰화는 모델이 입력을 처리할 단위로 나누는 것이고, 청킹은 긴 문서나 데이터를 검색·처리하기 좋은 조각으로 나누는 것입니다.

### 오해 3: 임베딩과 벡터는 완전히 별개의 결과다

임베딩은 의미 정보를 수치로 변환하는 과정이고, 벡터는 그 수치 표현입니다. 학습에서는 두 용어가 함께 등장할 수 있습니다.

### 오해 4: 프롬프트를 바꾸면 모델 자체가 영구적으로 학습된다

프롬프트는 요청 시 입력을 설계하는 방법입니다. 모델 파라미터를 바꾸는 훈련·미세 조정과는 다릅니다.

### 오해 5: 파운데이션 모델은 모든 업무에 가장 적합하다

FM 선택에는 성능뿐 아니라 모달리티, 비용, 지연 시간, 안전성, 라이선스, 데이터 요구 사항이 영향을 줍니다.

## 핵심 정리

- 토큰은 모델이 처리하는 입력·출력 단위입니다.
- 청킹은 긴 자료를 의미 있는 작은 조각으로 나누는 과정입니다.
- 임베딩은 데이터를 수치 표현으로 바꾸고, 벡터는 그 표현을 비교하는 데 사용됩니다.
- 프롬프트는 모델에게 주는 지시와 컨텍스트입니다.
- Transformer는 아키텍처, LLM은 언어 모델, FM은 여러 애플리케이션의 기반 모델입니다.
- 멀티모달은 여러 데이터 형태를 다루고, 확산 모델은 여러 콘텐츠 생성 작업에 연결됩니다.
- 에이전트는 도구·메모리·오케스트레이션을 이용해 여러 단계를 수행하도록 구성할 수 있습니다.

**한 문장 암기 포인트:** `토큰으로 처리하고, 청킹으로 나누고, 임베딩·벡터로 비교하고, 프롬프트로 지시하며, FM으로 생성한다`입니다.

## 스스로 답하는 확인 질문

1. 긴 PDF를 검색에 사용하기 전에 작은 의미 단위로 나누는 작업은 토큰화와 청킹 중 무엇인가요?
2. 의미가 비슷한 두 문장을 숫자 공간에서 비교하려면 어떤 개념을 사용하나요?
