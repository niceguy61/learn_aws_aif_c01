# GenAI의 기능·한계와 비즈니스 문제 해결

## 이 문서에서 배울 것

GenAI는 대화·요약·생성처럼 다양한 업무를 도울 수 있지만, 항상 정확하거나 일관된 결과를 보장하지는 않습니다. 이 문서에서는 GenAI가 잘할 수 있는 일과 주의해야 할 한계를 구분하고, 비즈니스 문제·모델 선택·사람 검토·성과 지표를 연결합니다.

## 선수 지식과 한 줄 요약

- 선수 지식: D2의 토큰·프롬프트·파운데이션 모델 개념을 알고 있으면 좋습니다.
- 한 줄 요약: **GenAI를 선택할 때는 “무엇을 만들 수 있는가?”와 함께 “틀리면 어떤 위험이 있는가?”를 평가하고, 모델·사람·업무 프로세스를 함께 설계합니다.**

## GenAI가 제공할 수 있는 기능

### 콘텐츠 생성

GenAI는 새로운 텍스트·이미지·오디오·비디오·코드 등을 생성하는 데 사용될 수 있습니다. 초안 작성, 아이디어 생성, 설명문 작성처럼 사람이 시작하는 데 시간이 걸리는 작업을 보조할 수 있습니다.

### 대화와 반응성

사용자의 질문을 이해하고 대화 형식으로 답변할 수 있습니다. 한 번의 고정된 입력·출력보다 후속 질문과 컨텍스트를 고려하는 상호 작용에 적합할 수 있습니다.

### 요약·변환·번역

긴 문서의 핵심을 줄이거나, 문체를 바꾸거나, 다른 언어로 변환하는 작업을 도울 수 있습니다. 다만 요약 결과가 원문의 중요한 조건을 빠뜨리지 않았는지 확인해야 합니다.

### 검색·추천·고객 서비스 보조

검색 결과를 자연어로 설명하거나, 사용자의 질문에 맞는 정보를 정리하거나, 상담원이 사용할 답변 초안을 만드는 데 활용할 수 있습니다. 외부 지식이나 업무 시스템을 연결하는 경우에는 권한, 최신성, 출처와 출력 검증을 함께 설계해야 합니다.

## GenAI의 주요 한계

### 환각과 부정확성

환각(hallucination)은 모델이 사실이 아닌 내용을 그럴듯한 표현으로 생성하는 현상입니다. 모델이 문장을 자연스럽게 만든다는 사실은 그 내용이 사실이라는 증거가 아닙니다.

환각 위험을 줄이기 위해 사용할 수 있는 방법은 문제에 따라 달라집니다.

- 신뢰할 수 있는 자료를 컨텍스트로 제공하기
- 답변에 출처나 근거를 요구하기
- 결과를 업무 규칙이나 데이터와 대조하기
- 위험이 큰 업무에서는 사람 검토를 거치기
- 확신할 수 없을 때 모른다고 답하도록 설계하기

### 비결정성

같은 질문이라도 모델 설정, 컨텍스트, 시스템 상태에 따라 결과가 달라질 수 있습니다. 따라서 전통적인 규칙 기반 프로그램처럼 같은 입력이 언제나 문자 그대로 같은 문장을 낸다고 가정하면 안 됩니다.

비결정성이 허용되는 창의적 초안 업무와, 반드시 같은 형식·정확한 결과가 필요한 업무는 요구사항이 다릅니다.

### 해석 가능성과 설명의 한계

모델이 왜 특정 표현이나 결론을 만들었는지 사람이 완전히 설명하기 어려울 수 있습니다. 결과를 그대로 자동 승인하는 대신, 업무 위험도와 사용자에게 필요한 설명 수준을 고려해야 합니다.

### 지식의 최신성·범위 한계

모델이 가진 지식이나 제공된 컨텍스트가 최신 업무 정보를 충분히 포함하지 않을 수 있습니다. “모델이 알고 있을 것”이라는 가정만으로 최신 가격·정책·재고·규정 같은 정보를 판단하지 않습니다.

### 비용·지연 시간·확장성

더 큰 모델이나 더 긴 입력은 성능에 도움을 줄 수 있지만 비용과 응답 시간이 증가할 수 있습니다. 사용자가 기다릴 수 있는 시간, 요청량, 예상 비용, 품질 요구를 함께 비교해야 합니다.

## 비즈니스 문제에 GenAI를 적용하는 순서

### 1. 업무 목표 정의

“챗봇을 만들자”보다 “상담원의 반복 답변 작성 시간을 줄이고, 최종 답변은 상담원이 승인한다”처럼 업무 결과와 사람의 역할을 정의합니다.

### 2. 생성이 필요한지 확인

결과가 정해진 범주의 분류인지, 숫자 예측인지, 새로운 콘텐츠 작성인지 구분합니다. 모든 문제를 GenAI로 해결하려 하지 않고 더 단순한 방법이 충분한지도 확인합니다.

### 3. 위험과 품질 기준 정의

틀린 답변의 비용, 개인정보·보안 요구, 설명 필요성, 사람 검토 여부, 허용 가능한 지연 시간과 비용을 정합니다.

### 4. 모델과 애플리케이션 방식 선택

모델의 모달리티, 성능, 기능, 언어 지원, 컨텍스트 처리, 비용, 지연 시간, 규정 준수 조건을 비교합니다. 하나의 모델이 모든 조건에서 가장 좋은 것은 아닙니다.

### 5. 평가와 운영 계획 수립

모델의 답변 품질뿐 아니라 실제 업무 성과를 측정할 방법을 정합니다. 출시 후에도 사용자 피드백과 오류를 모아 개선합니다.

## 모델 선택 기준

| 기준 | 확인할 질문 |
|---|---|
| 작업 적합성 | 요약·분류·대화·코드·생성 중 어떤 작업인가요? |
| 모달리티 | 텍스트만 필요한가요, 이미지·오디오·비디오도 필요한가요? |
| 성능과 품질 | 업무에서 허용할 오류 수준은 어느 정도인가요? |
| 언어와 범위 | 필요한 언어와 도메인 지식을 지원하나요? |
| 비용 | 요청 수와 입력·출력 길이에 맞는 비용인가요? |
| 지연 시간 | 사용자가 기다릴 수 있는 시간 안에 응답하나요? |
| 보안·규정 준수 | 데이터와 결과를 업무 정책에 맞게 처리할 수 있나요? |
| 운영 | 평가·모니터링·업데이트를 지속할 수 있나요? |

## 파운데이션 모델 수명 주기

파운데이션 모델을 애플리케이션에 적용하는 흐름은 다음처럼 볼 수 있습니다.

```text
데이터 선택 → 모델 선택 → 사전 훈련 → 평가
       ↓             ↓
  사용자 지정·미세 조정 ← 피드백
       ↓
배포·모니터링 → 개선·반복
```

모든 팀이 사전 훈련을 직접 수행해야 하는 것은 아닙니다. 이미 사전 훈련된 FM을 선택하고 프롬프트·검색 연결·미세 조정 중 필요한 방법을 고를 수 있습니다. 어떤 방법이 적절한지는 데이터·품질·비용·시간·운영 요구에 따라 달라집니다.

## 사람 검토가 필요한 상황

다음과 같은 경우에는 자동화를 최종 결정으로 사용하기보다 사람이 결과를 검토하도록 설계하는 것이 안전할 수 있습니다.

- 의료·금융·법률·채용처럼 틀린 결과의 영향이 큰 업무
- 고객의 권리·자격·금전 처리에 영향을 주는 결정
- 모델이 출처를 제시하지 못하거나 근거가 불분명한 답변
- 개인정보나 기밀 정보가 포함된 입력·출력
- 예외 상황이 많고 업무 규칙이 자주 바뀌는 경우

사람 검토는 모델을 전혀 사용하지 않는다는 뜻이 아닙니다. 모델은 후보·초안·요약을 제공하고, 사람이 최종 판단과 책임을 맡도록 역할을 나눌 수 있습니다.

## 성과 지표

| 지표 관점 | 예시 질문 |
|---|---|
| 효율성 | 작업 시간이 줄었나요? 처리량이 늘었나요? |
| 품질 | 답변이 업무 기준을 충족하나요? 오류가 줄었나요? |
| 사용자 경험 | 만족도와 재사용이 좋아졌나요? |
| 비즈니스 | 전환율·평균 사용자 수익·고객 생애 가치 같은 목표가 개선되었나요? |
| 비용 | 상호 작용당 비용과 운영 비용이 허용 범위인가요? |

정확도 하나만으로 GenAI 애플리케이션의 성공을 판단하지 않습니다. 실제 목표에 맞는 모델 지표와 비즈니스 지표를 함께 선택합니다.

## 실무형 시나리오

보험 상담원이 고객 질문에 답하는 애플리케이션을 만든다고 가정합니다.

1. GenAI는 약관의 긴 내용을 요약하고 답변 초안을 만들 수 있습니다.
2. 최신 약관과 고객 계약 정보를 컨텍스트로 제공해야 합니다.
3. 답변에 근거 문서와 관련 조항을 포함하도록 설계합니다.
4. 보장 여부를 최종 확정하는 대신 상담원이 검토·승인하도록 합니다.
5. 측정 지표는 초안 작성 시간, 수정 횟수, 잘못된 안내 비율, 상담원 만족도 등이 될 수 있습니다.

이 시나리오의 핵심은 모델이 답변을 잘 생성하는지뿐 아니라, **업무 위험을 통제하면서 실제 상담 업무를 개선하는지**입니다.

## 시험에서 판단하는 단서

- “그럴듯하지만 사실이 아닌 내용” → 환각 또는 부정확성
- “같은 질문에 결과가 달라질 수 있음” → 비결정성
- “모델이 왜 그렇게 답했는지 설명하기 어려움” → 해석 가능성의 한계
- “모델을 고르라” → 작업·모달리티·품질·비용·지연 시간·규정 준수를 비교
- “최종 승인”, “고위험 결정”, “사람이 확인” → Human-in-the-loop
- “업무 성과” → 정확도 외에 효율성·전환율·만족도·비용 같은 비즈니스 지표

## 자주 하는 오해

### 오해 1: 유창한 답변은 정확한 답변이다

문장의 자연스러움과 사실의 정확성은 별개입니다. 중요한 결과는 근거 확인과 검증을 거쳐야 합니다.

### 오해 2: 사람 검토는 GenAI를 실패한 시스템으로 만든다

사람 검토는 위험이 큰 업무에서 책임과 품질을 통제하는 설계 방법입니다. 초안 생성과 최종 승인을 분리하면 생산성과 안전성을 함께 고려할 수 있습니다.

### 오해 3: 가장 큰 모델을 선택하면 모든 문제가 해결된다

큰 모델은 비용·지연 시간·운영 부담이 커질 수 있습니다. 업무 요구를 만족하는 모델을 비교해야 합니다.

### 오해 4: 한 번 평가가 좋으면 운영 중에도 계속 좋다

사용자 질문, 데이터, 정책과 업무가 변할 수 있으므로 출시 후 평가·모니터링과 피드백이 필요합니다.

## 핵심 정리

- GenAI는 생성·대화·요약·변환·검색 보조에 활용할 수 있습니다.
- 환각·비결정성·설명 한계·최신성 한계·비용을 고려해야 합니다.
- 모델 선택은 작업·모달리티·성능·비용·지연 시간·보안·규정 준수를 함께 비교합니다.
- 고위험 업무에서는 사람 검토와 최종 승인 단계를 설계합니다.
- 모델 지표와 비즈니스 지표를 함께 평가합니다.

**한 문장 암기 포인트:** `잘 생성하는가`와 `업무에 안전하고 가치 있는가`는 별도의 질문입니다.

## 스스로 답하는 확인 질문

1. 모델이 매우 유창하지만 존재하지 않는 정책 조항을 인용했다면 어떤 한계인가요?
2. 같은 프롬프트의 답변이 매번 달라질 수 있는 이유를 어떤 개념으로 설명하나요?
3. 고위험 업무에서 사람 검토가 필요한 이유는 무엇인가요?
4. 모델 선택 시 성능 외에 비교해야 할 조건을 네 가지 이상 말해 보세요.
5. 상담원 지원 애플리케이션의 비즈니스 지표를 두 가지 이상 제안해 보세요.
