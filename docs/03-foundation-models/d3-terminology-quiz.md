# D3 용어 퀴즈

## 풀기 전에

각 문항을 먼저 풀고 정답과 해설을 확인합니다. 이 퀴즈는 공식 시험 문항이 아니며, AIF-C01 D3 개념을 확인하기 위한 자체 제작 학습 자료입니다.

## 문제

1. 긴 정적 문서가 여러 요청에서 반복될 때 입력 처리 비용과 지연 시간을 줄이기 위해 검토할 기능은 무엇인가요?
   - A. 프롬프트 캐싱
   - B. 데이터 중독
   - C. 모델 증류만
   - D. 벤치마크

2. 온도(temperature)가 주로 영향을 주는 것은 무엇인가요?
   - A. 출력의 다양성과 무작위성
   - B. 벡터 데이터베이스의 저장 용량
   - C. IAM 사용자의 수
   - D. 평가 데이터의 레이블 수

3. 최신 사내 정책을 모델 재훈련 없이 답변에 활용하려면 무엇을 우선 검토하나요?
   - A. RAG
   - B. 처음부터 사전 훈련
   - C. 출력 길이만 증가
   - D. 모델 이름 변경

4. 다음 중 RAG의 구성 요소를 모두 고르세요.
   - A. 문서 조각화와 임베딩
   - B. 벡터 저장·검색
   - C. 검색 결과를 모델 컨텍스트에 제공
   - D. 반드시 모델 파라미터를 다시 훈련

5. 연결 관계와 지식 그래프 탐색이 핵심인 데이터에 적합한 AWS 서비스는 무엇인가요?
   - A. Amazon Neptune
   - B. Amazon Polly
   - C. Amazon CloudFront
   - D. Amazon QLDB만

6. 특정 출력 형식과 스타일을 많은 예시로 반복 학습시키려는 방법은 무엇인가요?
   - A. 미세 조정
   - B. RAG만
   - C. 벤치마크 삭제
   - D. 리전 변경

7. 큰 교사 모델의 능력을 작은 학생 모델로 전달하는 방법은 무엇인가요?
   - A. 모델 증류
   - B. zero-shot
   - C. 청킹
   - D. 프롬프트 노출

8. 모델이 자연어 명령을 따르는 능력을 개선하도록 조정하는 방법은 무엇인가요?
   - A. 명령 튜닝
   - B. 벡터 검색
   - C. 데이터 레지던시
   - D. 하이재킹

9. 다음 중 사용자 지정 데이터의 품질을 확인하는 항목을 모두 고르세요.
   - A. 중복·오류·모순
   - B. 출처·접근 권한·보존 정책
   - C. 실제 사용자와 예외 사례의 대표성
   - D. 모델의 로고 색상

10. 훈련·검증·평가 데이터를 나누는 주된 이유는 무엇인가요?
    - A. 보지 않은 데이터에 대한 일반화 성능을 공정하게 확인하기 위해
    - B. 모든 레이블을 제거하기 위해
    - C. 모델을 항상 더 크게 만들기 위해
    - D. RAG를 자동으로 구성하기 위해

11. 다음 중 사람 평가의 장점과 한계를 올바르게 설명한 것은 무엇인가요?
    - A. 업무 맥락을 판단할 수 있지만 비용·시간·평가자 차이가 발생할 수 있다.
    - B. 어떤 도메인에서도 자동으로 동일한 결과를 낸다.
    - C. 모델 지표가 필요 없게 만든다.
    - D. 평가 기준이 없어도 된다.

12. 생성 요약과 참조 요약 사이의 단어·구문 겹침을 비교하는 지표는 무엇인가요?
    - A. ROUGE
    - B. IAM
    - C. BLEU만
    - D. 작업 완료율

13. 번역 결과와 참조 문장의 n-그램 겹침을 비교하는 지표는 무엇인가요?
    - A. BLEU
    - B. BERTScore만
    - C. 지연 시간
    - D. 참여율

14. 임베딩 기반 의미 유사성을 평가하는 지표는 무엇인가요?
    - A. BERTScore
    - B. ROUGE만
    - C. 비용
    - D. 레이블 수

15. 다른 LLM이 생성 모델의 응답을 점수화하고 설명하는 방식은 무엇인가요?
    - A. LLM-as-a-judge
    - B. 지속적인 사전 훈련
    - C. 프롬프트 캐싱
    - D. 전이 학습만

16. 다음 중 에이전트 평가에 필요한 항목을 모두 고르세요.
    - A. 도구 선택과 도구 입력의 정확성
    - B. 위험한 행동 전 승인 여부
    - C. 실제 외부 시스템 작업 완료 여부
    - D. 최종 문장이 자연스럽다는 사실만

17. 다음 중 RAG 평가에서 분리해 확인할 항목을 모두 고르세요.
    - A. 검색 관련성과 완전성
    - B. 검색 자료의 최신성·권한
    - C. 최종 답변의 근거성과 품질
    - D. 모델의 파일명 길이

18. 다음 중 비즈니스 지표에 해당하는 것을 모두 고르세요.
    - A. 생산성
    - B. 사용자 참여
    - C. 작업 완료율과 만족도
    - D. 상호 작용당 비용

19. AWS 관리형 평가 작업과 가장 가까운 것은 무엇인가요?
    - A. Amazon Bedrock 모델 평가
    - B. Amazon Neptune
    - C. Amazon Bedrock Prompt Management만
    - D. Amazon S3 버킷 이름

20. LLM-as-a-judge 결과를 사람 평가와 함께 확인해야 하는 이유는 무엇인가요?
    - A. 평가자 모델의 편향·기준 이해·표현 선호가 결과에 영향을 줄 수 있기 때문
    - B. LLM은 항상 평가를 수행할 수 없기 때문
    - C. 자동 지표는 모두 무의미하기 때문
    - D. 사람은 비용이 들지 않기 때문

## 정답과 해설

1. **A** — 반복되는 정적 컨텍스트의 재사용을 통해 입력 처리 비용과 지연 시간 감소를 검토할 수 있습니다.
2. **A** — 온도는 출력의 다양성과 무작위성에 영향을 주며 사실성을 보장하지 않습니다.
3. **A** — RAG는 외부 자료를 추론 시점의 컨텍스트로 제공합니다.
4. **A, B, C** — RAG는 검색 파이프라인과 컨텍스트 제공이며, 반드시 모델 파라미터를 다시 훈련하는 방식은 아닙니다.
5. **A** — Amazon Neptune은 고도로 연결된 데이터와 그래프 관계 탐색에 적합한 서비스입니다.
6. **A** — 미세 조정은 특정 작업·형식·스타일의 반복 행동을 학습시키는 방식입니다.
7. **A** — 증류는 교사 모델의 능력을 학생 모델로 전달합니다.
8. **A** — 명령 튜닝은 자연어 지시를 따르는 능력 개선과 연결됩니다.
9. **A, B, C** — 데이터 품질·거버넌스·대표성을 함께 확인합니다.
10. **A** — 평가 데이터가 학습에 노출되지 않아야 일반화 성능을 공정하게 볼 수 있습니다.
11. **A** — 사람은 업무 맥락을 판단하지만 시간·비용과 평가자 일관성 문제가 있습니다.
12. **A** — ROUGE는 요약과 참조 텍스트의 겹침을 평가하는 계열입니다.
13. **A** — BLEU는 번역 등에서 참조 문장과 n-그램 겹침을 비교합니다.
14. **A** — BERTScore는 임베딩 기반 의미 유사성을 활용합니다.
15. **A** — 평가자 LLM이 다른 모델의 응답을 점수화·설명합니다.
16. **A, B, C** — 에이전트는 행동 선택·권한·실제 상태까지 평가해야 합니다.
17. **A, B, C** — 검색 품질·권한·최신성과 생성 답변을 분리해 평가합니다.
18. **A, B, C, D** — 실제 업무 가치를 판단하는 비즈니스 지표입니다.
19. **A** — Amazon Bedrock 모델 평가는 모델·생성형 AI 리소스를 평가하는 관리형 경로입니다.
20. **A** — 평가자 모델도 편향과 기준 오류가 있을 수 있어 사람 평가·표본 검토가 필요합니다.

## 복습 기준

- 17~20개 정답: D3 문제은행으로 복합 시나리오를 연습합니다.
- 13~16개 정답: 틀린 문항의 연결 문서를 읽고 카드를 반복합니다.
- 12개 이하 정답: [D3 복습 카드](d3-review-cards.md)와 네 개의 본문을 순서대로 다시 읽습니다.
