# FM 훈련·사용자 지정과 데이터 준비

## 이 문서에서 배울 것

파운데이션 모델(FM)을 그대로 사용해도 되지 않거나, 특정 작업·도메인·출력 형식에 맞춰야 할 때 사용자 지정 방법을 검토합니다. 이 문서에서는 사전 훈련·미세 조정·지속적인 사전 훈련·명령 튜닝·전이 학습·강화 학습·모델 증류를 구분하고, 사용자 지정 데이터의 큐레이션·거버넌스·크기·레이블·대표성을 설명합니다.

## 선수 지식과 한 줄 요약

- 선수 지식: D1의 훈련·평가·배포 수명 주기와 D2의 FM·RAG·비용 개념이 필요합니다.
- 한 줄 요약: **사용자 지정은 모델을 바꾸는 기술 선택이면서 데이터 품질·비용·평가·운영 책임을 함께 선택하는 일입니다.**

## FM 훈련의 기본 단계

### 사전 훈련(pre-training)

사전 훈련은 대규모 데이터에서 언어·이미지·오디오 등의 일반적인 패턴을 학습해 여러 작업의 기반이 되는 FM을 만드는 단계입니다. 데이터·컴퓨팅·시간·전문성이 매우 많이 필요하므로 일반 애플리케이션 팀이 처음부터 수행하는 방식은 아닙니다.

### 지속적인 사전 훈련(continued pre-training)

이미 사전 훈련된 모델에 추가적인 도메인 데이터로 학습을 이어 가는 방식입니다. 특정 분야의 용어와 표현을 더 잘 반영할 수 있지만, 대규모 고품질 데이터·컴퓨팅·평가가 필요하고 기존 능력을 잃는지 확인해야 합니다.

### 미세 조정(fine-tuning)

특정 작업의 입력·출력 예시를 사용해 모델 파라미터를 조정하는 사용자 지정 방식입니다. 분류·요약·특정 응답 형식·도메인 문체처럼 반복되는 행동을 학습시키는 데 검토할 수 있습니다.

미세 조정은 최신 문서를 매 요청에 검색해 제공하는 RAG와 목적이 다릅니다. 모델의 행동·형식·스타일을 바꾸는 데 유리할 수 있지만, 데이터 준비와 재훈련·재평가가 필요합니다.

### 명령 튜닝(instruction tuning)

모델이 자연어 명령을 이해하고 지시에 따라 답하도록 입력 명령과 기대 응답의 예시를 사용해 조정하는 방식입니다. “무엇을 해야 하는가”를 다양한 표현으로 보여 주어 작업 수행 능력을 높이는 데 활용됩니다.

### 전이 학습(transfer learning)

일반 데이터에서 학습한 모델의 지식과 표현을 새로운 작업·도메인에 재사용하는 접근입니다. 처음부터 모델을 학습하는 것보다 적은 데이터와 자원으로 시작할 수 있지만, 새 작업의 데이터 품질과 평가가 여전히 중요합니다.

### 사용자 피드백을 통한 강화 학습

강화 학습은 모델이 만든 결과에 대한 보상 또는 평가를 이용해 더 바람직한 행동을 학습하도록 하는 접근입니다. 생성형 AI에서는 사람이 선호도를 평가하거나, 업무 규칙·보상 함수를 사용해 결과를 평가할 수 있습니다.

피드백이 일관되지 않거나 특정 사용자 그룹을 대표하지 못하면 모델 행동이 편향될 수 있습니다. 보상 기준·평가자 지침·데이터 대표성·안전성을 함께 검토합니다.

### 모델 증류(distillation)

큰 교사 모델(teacher)의 결과·지식을 작은 학생 모델(student)에 전달해 특정 업무에서 더 빠르고 경제적인 모델을 만드는 방식입니다. 추론 비용·지연 시간을 줄일 수 있지만 교사 모델의 사용 비용, 증류·훈련 비용과 품질 손실 평가가 필요합니다.

[Amazon Bedrock의 모델 증류](https://docs.aws.amazon.com/bedrock/latest/userguide/model-distillation.html)는 교사 모델의 응답을 활용해 학생 모델을 사용자 지정하는 흐름을 제공합니다. 모델 목록과 지원 리전·요금은 변경될 수 있으므로 실제 사용 전 최신 공식 문서를 확인합니다.

## 사용자 지정 데이터 준비

### 데이터 큐레이션

데이터 큐레이션은 학습에 사용할 자료를 수집·선별·정제·구성하는 과정입니다. 중복·오탈자·모순된 답변·불필요한 형식·악성 내용을 확인하고, 업무 목표에 필요한 사례를 남깁니다.

좋은 데이터는 양만 많은 데이터가 아닙니다. 입력이 실제 사용 상황을 대표하고, 기대 출력이 명확하며, 서로 모순되지 않고, 실패·경계 사례도 포함해야 합니다.

### 데이터 거버넌스

사용자 지정 데이터에는 개인정보·기밀·저작권 자료가 포함될 수 있습니다. 수집 목적·사용 권한·보존 기간·접근 권한·삭제 절차·출처와 버전을 기록합니다.

훈련 데이터의 접근 권한과 모델 출력의 접근 권한도 분리해서 생각합니다. 모델을 사용할 수 있는 사람이 원본 데이터 전체를 볼 수 있어야 한다는 뜻은 아닙니다.

### 데이터 크기와 품질

데이터가 많으면 다양한 사례를 포함할 가능성이 커지지만, 오류·중복·편향도 함께 늘 수 있습니다. 작은 고품질 데이터로 시작해 평가 결과를 확인하고 필요한 사례를 추가하는 방식이 실용적일 수 있습니다.

데이터 수만으로 사용자 지정 성공을 예측하지 않습니다. 업무의 다양성·출력 일관성·레이블 품질·대표성·평가 결과를 함께 봅니다.

### 레이블

지도 미세 조정에서 레이블은 입력에 대해 모델이 내야 할 기대 출력 또는 정답을 나타냅니다. 요약·분류·질의응답 데이터에서는 무엇이 좋은 답인지 기준이 일관되어야 합니다.

레이블 작업자에게 명확한 지침과 예시를 제공하고, 일부 결과를 교차 검토해 품질을 확인합니다. 모호한 정답이 많다면 모델 문제이기 전에 업무 기준이 불명확한 것일 수 있습니다.

### 대표성

학습 데이터는 실제 사용자·언어·지역·업무 상황·예외 사례를 적절히 대표해야 합니다. 한 그룹의 표현만 포함하면 다른 그룹에서 성능이 떨어질 수 있고, 정상 사례만 포함하면 실패 상황을 다루지 못할 수 있습니다.

훈련 데이터와 평가 데이터의 분포를 비교하되, 평가 데이터를 훈련 데이터에 섞어 성능을 부풀리지 않습니다.

### 훈련·검증·평가 데이터 분리

사용자 지정 과정에서도 데이터 역할을 나눕니다.

- 훈련 데이터: 모델이 패턴을 학습하는 데 사용
- 검증 데이터: 학습 중 설정과 진행 상태를 비교하는 데 사용
- 평가 데이터: 최종 모델이 보지 않은 사례에서 일반화하는지 확인

같은 예시를 모든 단계에 사용하면 실제 성능을 과대평가할 수 있습니다.

## 어떤 사용자 지정 방법을 선택할까요?

| 문제의 핵심 | 먼저 검토할 접근 | 이유 |
|---|---|---|
| 최신 문서·정책을 답변에 반영 | RAG | 모델 가중치를 바꾸지 않고 자료를 검색해 제공 |
| 간단한 작업 지시와 출력 형식 개선 | 프롬프트·템플릿·few-shot | 가장 빠르게 실험하고 변경 가능 |
| 특정 스타일·형식·작업 행동을 반복 학습 | 미세 조정 | 예시를 통해 모델의 행동을 조정 |
| 전문 도메인 언어 패턴을 넓게 반영 | 지속적인 사전 훈련 | 추가 도메인 데이터로 사전 학습을 이어 감 |
| 큰 모델의 품질을 작은 모델에서 활용 | 증류 | 추론 비용·지연 시간 절감 가능 |
| 보상·선호 기준에 맞춘 행동 개선 | 강화 학습·강화 미세 조정 | 피드백 또는 보상 함수로 결과를 평가 |

이 표는 출발점이지 자동 결정 규칙이 아닙니다. 데이터의 최신성·규모·권한·비용·품질·운영 가능성을 함께 평가합니다.

## 비용과 운영 절충

사용자 지정 비용은 훈련 작업만으로 끝나지 않습니다.

- 데이터 수집·정제·레이블·검토 인력
- 훈련 데이터의 토큰 수와 반복 횟수
- 모델 훈련·저장·배포·추론
- 평가·실험·실패한 작업의 비용
- 모델 업데이트·롤백·모니터링과 운영 인력

Amazon Bedrock 모델 사용자 지정 공식 문서도 훈련 데이터 처리량과 반복 횟수, 사용자 지정 모델 저장과 관련한 비용 확인을 안내합니다. 실제 단가는 모델·리전·가격 방식에 따라 달라지므로 최신 가격표를 확인합니다.

사용자 지정 전에 다음 순서로 비용을 줄일 수 있는지 확인합니다.

```text
프롬프트 개선 → RAG·도구 연결 → 미세 조정
       ↓ 품질·비용 측정
지속적인 사전 훈련·증류·새 모델 선택 검토
```

## 실무형 시나리오

고객지원 팀이 모든 상담 답변을 회사 문체에 맞추고 싶어 한다고 가정합니다.

1. 먼저 좋은 답변의 기준과 금지 내용을 정하고, 대표적인 상담 예시를 큐레이션합니다.
2. 최신 환불 정책은 RAG로 연결하고, 문체·출력 구조의 일관성은 프롬프트 템플릿으로 시험합니다.
3. 충분한 예시와 평가 결과가 있고도 특정 형식이 반복해서 어긋나면 미세 조정을 비교합니다.
4. 훈련·검증·평가 데이터를 분리하고 여러 고객 유형·언어·예외 사례를 포함합니다.
5. 사용자 피드백을 수집하되, 한 그룹의 선호가 전체 업무 기준을 대표한다고 가정하지 않습니다.
6. 더 작은 모델로도 허용 품질을 달성할 수 있는지 증류와 추론 비용을 비교합니다.
7. 출시 후에도 업무 정책이 바뀌거나 답변 품질이 떨어지는지 모니터링하고 재평가합니다.

## 시험에서 판단하는 단서

- “대규모 일반 데이터로 기반 모델을 만듦” → 사전 훈련
- “도메인 데이터를 추가해 학습을 이어 감” → 지속적인 사전 훈련
- “레이블이 있는 입력·출력 예시로 특정 작업을 개선” → 지도 미세 조정
- “명령을 이해하고 따르는 능력 개선” → 명령 튜닝
- “기존 모델의 지식을 새 작업에 재사용” → 전이 학습
- “보상·선호도·사용자 피드백을 이용” → 강화 학습
- “큰 교사 모델의 능력을 작고 빠른 모델로 전달” → 모델 증류
- “훈련 데이터의 중복·오류·출처·대표성을 확인” → 데이터 큐레이션·거버넌스
- “최신 업무 문서를 답변에 반영” → RAG를 미세 조정과 비교
- “사용자 지정 비용” → 데이터·훈련·저장·배포·추론·평가 비용을 함께 계산

## 자주 하는 오해

### 오해 1: 데이터가 많으면 자동으로 좋은 사용자 지정 모델이 된다

오류·중복·편향·대표성 부족이 있는 데이터는 양이 많아도 품질을 보장하지 않습니다. 데이터 큐레이션과 평가가 중요합니다.

### 오해 2: 미세 조정은 최신 지식을 연결하는 가장 좋은 방법이다

자주 바뀌는 문서·정책은 RAG로 검색해 제공하는 편이 업데이트에 유리할 수 있습니다. 미세 조정은 행동·형식·스타일을 반복 학습시키는 목적과 비교합니다.

### 오해 3: 훈련 데이터와 평가 데이터를 섞어도 된다

평가 데이터가 학습에 노출되면 새로운 입력에 대한 일반화 성능을 공정하게 확인하기 어렵습니다.

### 오해 4: 모델 증류는 품질 손실이 없는 단순 압축이다

학생 모델은 더 작고 빠를 수 있지만 교사 모델의 모든 능력을 그대로 보장하지 않습니다. 업무별 품질·안전·비용을 평가해야 합니다.

## 핵심 정리

- 사전 훈련은 범용 패턴을 학습하는 기반 단계이고, 미세 조정은 특정 작업의 행동·형식을 조정합니다.
- 지속적인 사전 훈련은 도메인 데이터로 학습을 이어 가고, 명령 튜닝은 지시 따르기 능력을 개선합니다.
- 전이 학습은 기존 지식과 표현을 새 작업에 재사용하는 접근입니다.
- 강화 학습은 보상·선호·사용자 피드백을 활용하지만 피드백 품질과 대표성을 검토해야 합니다.
- 증류는 큰 교사 모델의 능력을 작은 학생 모델로 전달해 비용·지연 시간 절감을 노립니다.
- 사용자 지정 데이터는 큐레이션·거버넌스·크기·레이블·대표성을 함께 관리합니다.
- 최신 지식은 RAG, 반복되는 행동·형식은 미세 조정과 먼저 비교합니다.

**한 문장 암기 포인트:** `지식이 자주 바뀌면 RAG`, `행동·형식이 반복되면 미세 조정`, `작고 빠른 추론이 필요하면 증류`를 우선 비교합니다.
