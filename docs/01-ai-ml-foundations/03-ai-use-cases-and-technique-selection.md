# AI 사용 사례와 기법 선택

## 이 문서에서 배울 것

이 문서에서는 “AI를 사용할 수 있는가?”에서 시작해 “어떤 결과를 원하는가?”, “어떤 기법과 서비스를 연결할 것인가?”까지 판단하는 순서를 익힙니다. 시험에서는 서비스 이름을 단독으로 묻기보다, 문제의 입력·출력·제약 조건을 보고 적절한 접근 방식을 고르게 하는 시나리오가 중요합니다.

## 선수 지식과 한 줄 요약

- 선수 지식: 앞 문서의 분류·회귀·클러스터링과 정형·비정형 데이터 개념을 알고 있으면 좋습니다.
- 한 줄 요약: **문제를 먼저 정의하고, 원하는 출력 형태와 데이터 유형을 확인한 뒤, 가장 단순하면서 요구를 충족하는 기법과 서비스를 선택합니다.**

## 핵심 개념을 쉬운 말로 설명

### 1단계: 해결할 업무를 한 문장으로 바꾸기

“AI를 도입하고 싶다”는 목표가 너무 넓습니다. 다음처럼 업무 결과를 구체적으로 바꿔 봅니다.

- 고객 문의를 긴급 문의와 일반 문의로 구분한다.
- 다음 달 상품 판매량을 예측한다.
- 비슷한 구매 행동을 하는 고객 그룹을 찾는다.
- 이미지에서 불량품을 찾는다.
- 음성을 텍스트로 바꾼다.
- 여러 언어의 문장을 번역한다.
- 고객에게 보낼 답변 초안을 만든다.

이렇게 바꾸면 분류·예측·그룹화·인식·변환·생성 중 어떤 결과가 필요한지 보입니다.

### 2단계: AI가 정말 필요한지 확인하기

모든 문제에 ML이나 GenAI가 필요한 것은 아닙니다. 입력과 규칙이 매우 명확하고 변경도 적다면 단순한 규칙 기반 로직이 더 이해하기 쉽고 관리하기 쉬울 수 있습니다.

AI를 고려할 때는 다음을 확인합니다.

- 충분한 데이터 또는 적절한 지식이 있는가?
- 결과의 정확성이나 오류 비용을 평가할 수 있는가?
- 결과를 사람이 검토해야 하는가?
- 개인정보·보안·규정 준수 요구를 만족할 수 있는가?
- 모델 운영 비용과 관리 부담이 업무 가치보다 크지 않은가?

### 3단계: 원하는 출력 유형을 확인하기

| 원하는 결과 | 대표 문제 유형 | 간단한 예 |
|---|---|---|
| 정해진 범주 | 분류 | 사기/정상, 긴급/일반 |
| 숫자 값 | 회귀 | 판매량, 수요, 가격 |
| 비슷한 그룹 | 클러스터링 | 구매 행동별 고객 그룹 |
| 이미지에서 의미 추출 | 컴퓨터 비전 | 불량품, 객체, 문서 이미지 |
| 텍스트의 의미나 언어 처리 | NLP | 감정, 주제, 번역, 텍스트 분류 |
| 음성 입력·출력 처리 | 음성 AI | 음성 인식, 음성 합성 |
| 새로운 콘텐츠 | 생성형 AI | 답변 초안, 요약, 이미지 생성 |

### 4단계: 모델 개발과 관리형 AI 서비스 중 선택하기

문제에 따라 직접 모델을 만들고 관리할 수도 있고, 특정 기능을 제공하는 관리형 AI 서비스를 사용할 수도 있습니다. 초보자 관점에서는 다음 질문으로 선택을 시작합니다.

- 특정 작업만 필요하고 API 형태로 바로 사용하고 싶은가?
- 회사의 고유 데이터와 모델을 이용해 직접 개발·평가해야 하는가?
- 팀이 모델 훈련, 배포, 모니터링을 운영할 역량과 시간이 있는가?

정답은 항상 “가장 복잡한 모델”이 아닙니다. 요구한 결과와 운영 조건을 만족하는 선택이 더 적절합니다.

## AWS 관점과 관련 서비스

| 업무 | 연결할 수 있는 AWS 서비스 | 판단 기준 |
|---|---|---|
| 모델 개발·훈련·배포 수명 주기 | Amazon SageMaker AI | 고유 데이터와 모델 개발·운영 흐름을 관리해야 하는가 |
| 음성을 텍스트로 변환 | Amazon Transcribe | 음성 입력을 텍스트로 바꾸는가 |
| 텍스트를 다른 언어로 변환 | Amazon Translate | 번역 결과가 필요한가 |
| 텍스트 분석 | Amazon Comprehend | 텍스트의 의미·감정·주제 등을 분석하는가 |
| 대화형 봇 | Amazon Lex | 사용자의 입력을 이해하고 대화 흐름을 처리하는가 |
| 텍스트를 음성으로 변환 | Amazon Polly | 음성 출력을 만들어야 하는가 |

이 표는 공식 D1 범위에 언급된 AI 사용 사례와 AWS 서비스 연결을 위한 학습 요약입니다. 현재 기능, 리전, 지원 입력·출력, 요금은 시험 범위와 별도로 각 서비스의 공식 문서에서 확인해야 합니다. [AWS 공식 Domain 1](https://docs.aws.amazon.com/ko_kr/aws-certification/latest/ai-practitioner-01/ai-practitioner-01-domain1.html)

## 비슷한 개념·서비스 비교

### 분류와 클러스터링

- 분류는 학습 전에 정해진 범주와 레이블을 사용해 새 입력을 범주에 배치합니다.
- 클러스터링은 레이블 없이 비슷한 입력을 묶고, 결과 그룹의 의미는 사람이 해석할 수 있습니다.

### 예측과 생성

- 예측은 입력을 바탕으로 특정 값이나 범주를 추정합니다.
- 생성은 새로운 텍스트·이미지·오디오 등 콘텐츠를 만들어 냅니다.
- 답변 초안 생성은 내용의 사실성 검증과 사람 검토가 필요할 수 있습니다.

### 특정 AI API와 모델 개발 플랫폼

- 특정 변환·분석 작업만 필요하면 해당 관리형 AI 서비스를 우선 검토할 수 있습니다.
- 여러 단계의 데이터 준비·훈련·평가·배포·모니터링을 직접 관리해야 하면 Amazon SageMaker AI 같은 모델 개발 플랫폼을 검토할 수 있습니다.
- 실제 선택은 기능, 데이터, 보안, 비용, 지연 시간, 운영 역량을 함께 비교해야 합니다.

## 실무형 시나리오

한 제조 회사가 다음 네 가지 요청을 받았습니다.

1. 제품 사진에서 균열을 찾는다 → 컴퓨터 비전 문제입니다.
2. 고객 문의를 배송·환불·제품 문의로 나눈다 → 텍스트 분류 문제입니다.
3. 다음 분기의 부품 수요량을 추정한다 → 회귀 문제를 우선 검토합니다.
4. 상담원이 사용할 답변 초안을 만든다 → 생성형 AI를 고려하되, 근거 확인과 사람 검토를 설계합니다.

문제의 이름보다 **입력과 원하는 출력**을 먼저 읽으면 선택지를 빠르게 줄일 수 있습니다.

## 시험에서 판단하는 단서

- “예측할 숫자” → 회귀
- “정해진 범주 중 하나” → 분류
- “레이블 없이 비슷한 그룹” → 클러스터링
- “사진·영상 속 객체나 결함” → 컴퓨터 비전
- “문장·문서의 의미, 감정, 주제, 번역” → NLP 또는 언어 처리
- “음성을 글자로” → 음성 인식
- “글자를 음성으로” → 음성 합성
- “새로운 답변·요약·콘텐츠를 작성” → 생성형 AI
- 특정 AWS 서비스를 고를 때는 기능명보다 문제의 입력·출력과 관리 요구를 먼저 확인합니다.

## 자주 하는 오해

### 오해 1: AI를 사용하면 항상 더 좋은 결과가 나온다

AI는 데이터와 평가 방법이 적절할 때 업무를 도울 수 있습니다. 데이터가 부족하거나 오류 비용이 매우 큰 경우에는 AI 도입 자체가 적합한지 먼저 검토해야 합니다.

### 오해 2: 가장 최신이거나 큰 모델이 항상 정답이다

모델 선택에는 정확도 외에도 비용, 지연 시간, 데이터 보호, 운영 복잡성, 필요한 입력·출력 기능이 영향을 줍니다.

### 오해 3: 텍스트를 다루면 모두 생성형 AI다

텍스트 분류·감정 분석·번역·검색·요약·새로운 답변 생성은 서로 다른 작업일 수 있습니다. 문제에서 원하는 결과를 확인해야 합니다.

### 오해 4: 관리형 서비스는 아무런 책임이 없다

관리형 서비스를 사용해도 입력 데이터, 권한, 애플리케이션 로직, 출력 검증과 같은 사용자의 책임이 남을 수 있습니다. 보안과 책임 경계는 서비스 공식 문서에서 확인해야 합니다.

## 핵심 정리

- AI 문제는 업무 결과를 한 문장으로 구체화하는 것에서 시작합니다.
- 출력이 범주인지 숫자인지 그룹인지 콘텐츠인지에 따라 기법을 좁힙니다.
- 데이터·정확성·사람 검토·보안·비용·운영 부담을 함께 봅니다.
- 특정 작업을 바로 사용하려면 관리형 AI API를, 모델 개발 수명 주기를 관리하려면 모델 개발 플랫폼을 검토할 수 있습니다.

**한 문장 암기 포인트:** `업무 목표 → 입력 데이터 → 원하는 출력 → 학습 기법 → AWS 서비스 → 제약 조건` 순서로 판단합니다.

## 스스로 답하는 확인 질문

1. “고객 이탈 여부”와 “다음 달 매출”은 각각 어떤 출력 유형인가요?
2. 레이블 없이 고객 행동별 그룹을 찾는 문제에서 분류가 아닌 클러스터링을 고려하는 이유는 무엇인가요?
3. 음성을 텍스트로 바꾸는 작업과 텍스트로 답변을 생성하는 작업은 어떻게 다른가요?
4. 특정 AI 서비스를 바로 사용할지 모델 개발 플랫폼을 사용할지 판단할 때 고려할 운영 조건은 무엇인가요?
