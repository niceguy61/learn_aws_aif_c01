# ML 개발 수명 주기와 MLOps

## 이 문서에서 배울 것

ML 프로젝트는 모델을 한 번 훈련하는 것으로 끝나지 않습니다. 문제 정의, 데이터 준비, 훈련, 평가, 배포, 모니터링과 개선이 반복됩니다. 이 문서에서는 각 단계의 목적과 MLOps가 왜 필요한지 초보자 관점에서 설명합니다.

## 선수 지식과 한 줄 요약

- 선수 지식: 모델이 훈련과 추론을 거친다는 개념, 지도 학습과 평가의 기본 차이를 알고 있으면 좋습니다.
- 한 줄 요약: **ML 수명 주기는 문제를 정의하고 데이터를 준비해 모델을 평가·배포한 뒤, 실제 환경을 모니터링하며 반복 개선하는 흐름입니다.**

## ML 개발 수명 주기

### 1. 문제 정의

먼저 비즈니스 문제와 모델이 제공해야 할 결과를 정의합니다. “AI를 도입한다”가 아니라 “배송 지연 가능성이 높은 주문을 미리 찾아 대응한다”처럼 측정 가능한 업무 목표로 바꿉니다.

문제 정의가 불명확하면 정확도가 높은 모델을 만들어도 실제 업무에는 도움이 되지 않을 수 있습니다.

### 2. 데이터 수집과 이해

문제에 필요한 데이터를 모으고, 데이터의 출처·기간·형태·품질을 살핍니다. 누락, 중복, 잘못된 레이블, 대표성이 부족한 데이터가 있는지 확인합니다.

데이터가 실제 운영 환경의 입력을 충분히 나타내지 못하면 훈련 결과와 실제 결과 사이에 차이가 생길 수 있습니다.

### 3. 데이터 준비와 전처리

모델이 사용할 수 있는 형태로 데이터를 정리합니다. 필요에 따라 결측값 처리, 형식 통일, 특징 선택, 레이블 확인, 데이터 변환을 수행할 수 있습니다.

이 단계는 단순히 데이터를 예쁘게 만드는 작업이 아니라, 훈련 데이터와 실제 입력의 의미가 일관되도록 하는 작업입니다.

### 4. 데이터 분할

모델을 학습시키는 데이터와 성능을 확인하는 데이터를 구분합니다. 같은 데이터를 학습과 평가에 모두 사용하면 모델이 새로운 입력에도 잘 작동하는지 공정하게 판단하기 어렵습니다.

초보자에게 중요한 원칙은 **평가에 사용할 데이터를 모델이 미리 정답처럼 보지 않게 하는 것**입니다.

### 5. 모델 훈련

준비한 훈련 데이터로 모델이 패턴을 학습합니다. 훈련은 모델이 과거 예시의 규칙을 내부적으로 조정하는 과정입니다.

훈련 데이터에 지나치게 맞으면 새로운 데이터에 약해질 수 있고, 반대로 패턴을 충분히 배우지 못할 수도 있습니다. 이 문제는 과적합과 과소적합이라는 개념으로 연결됩니다.

### 6. 모델 평가

평가 데이터로 모델이 요구한 작업을 얼마나 잘 수행하는지 확인합니다. 모델 지표만 보지 말고, 실제 업무 목표와 오류 비용에도 맞는지 확인해야 합니다.

예를 들어 질병 위험을 놓치는 비용과 정상인을 추가 검토 대상으로 분류하는 비용이 다를 수 있습니다. 어떤 지표가 적절한지는 업무의 우선순위와 오류의 영향을 함께 보고 정합니다.

### 7. 배포와 추론

평가를 통과한 모델을 애플리케이션이나 업무 흐름에서 사용할 수 있도록 배포합니다. 배포 후 새 입력이 들어오면 모델은 추론을 수행해 예측이나 분류 결과를 냅니다.

훈련은 모델을 만드는 과정이고, 추론은 운영 중 새 입력에 결과를 내는 과정입니다. 시험에서는 두 단어를 바꾸어 설명하는 선택지를 주의합니다.

### 8. 모니터링과 재훈련

운영 환경의 데이터와 결과가 시간이 지나도 처음의 가정과 맞는지 관찰합니다. 업무가 바뀌거나 고객 행동이 변하면 모델 성능이 떨어질 수 있습니다.

문제가 확인되면 데이터를 다시 수집·검토하고, 필요하면 모델을 재훈련·재평가·재배포합니다. 따라서 ML은 일회성 프로젝트가 아니라 반복적인 운영 과정입니다.

## MLOps란 무엇인가요?

MLOps는 ML 개발과 운영을 반복 가능하고 안정적으로 수행하기 위한 사람·프로세스·도구의 결합입니다. DevOps가 소프트웨어 개발과 배포의 반복을 돕는 것처럼, MLOps는 데이터와 모델의 변화까지 고려합니다.

MLOps에서 중요하게 보는 항목은 다음과 같습니다.

- 데이터와 모델 버전의 추적
- 훈련·평가 과정의 반복 가능성
- 모델 배포와 롤백을 위한 절차
- 운영 중인 모델과 데이터의 모니터링
- 성능 저하 시 재훈련과 검토
- 모델 결과와 비즈니스 지표의 연결

## AWS 관점과 관련 서비스

Amazon SageMaker AI는 ML 모델의 개발·훈련·배포·모니터링 수명 주기를 관리하는 관점에서 연결할 수 있는 AWS 서비스입니다. 시험에서는 특정 화면이나 명령을 외우기보다, “모델을 실제 환경에서 반복 운영해야 한다”는 요구와 ML 수명 주기를 연결하는 것이 중요합니다. [AWS 공식 Domain 1](https://docs.aws.amazon.com/ko_kr/aws-certification/latest/ai-practitioner-01/ai-practitioner-01-domain1.html)

실제 AWS 설계에서는 데이터 저장, 권한, 비용, 배포 방식, 모니터링 범위를 별도로 결정해야 합니다. 이 문서의 범위는 ML 수명 주기의 개념적 흐름이며, 특정 서비스 기능과 최신 제공 범위는 공식 서비스 문서에서 다시 확인합니다.

## 모델 지표와 비즈니스 지표

| 구분 | 의미 | 질문 예시 |
|---|---|---|
| 모델 지표 | 모델이 예측·분류 작업을 얼마나 잘했는지 나타냄 | 오분류가 얼마나 발생했는가? |
| 운영 지표 | 모델이 실제 환경에서 안정적으로 동작하는지 나타냄 | 응답이 충분히 빠르고 서비스가 안정적인가? |
| 비즈니스 지표 | 모델이 업무 목표에 기여했는지 나타냄 | 처리 시간·비용·고객 만족이 개선되었는가? |

모델 지표가 좋아도 비즈니스 지표가 개선되지 않을 수 있습니다. 따라서 평가 단계에서 “좋은 모델”의 의미를 업무 목표와 연결해야 합니다.

## 실무형 시나리오

은행이 거래 사기 탐지 모델을 운영한다고 가정합니다.

1. 문제 정의: 의심 거래를 조기에 찾아 추가 검토로 보낸다.
2. 데이터 준비: 과거 거래와 사기 여부 레이블을 검토한다.
3. 훈련·평가: 훈련 데이터와 평가 데이터를 구분하고 오류 유형을 확인한다.
4. 배포: 새 거래가 들어올 때 추론 결과를 업무 시스템에 전달한다.
5. 모니터링: 거래 패턴과 사기 수법이 변하는지 확인한다.
6. 개선: 새로운 검토 결과를 반영해 재훈련하고 다시 평가한다.

실제 운영에서는 사기 거래를 놓치는 비용과 정상 거래를 추가 검토하는 비용을 함께 고려해야 합니다.

## 시험에서 판단하는 단서

- “문제 정의 → 데이터 준비 → 훈련 → 평가 → 배포 → 모니터링” 순서를 기억합니다.
- 훈련은 모델이 패턴을 배우는 과정이고, 추론은 새 입력에 결과를 내는 과정입니다.
- “운영 중 성능 저하”, “데이터 변화”, “재훈련”은 모니터링과 MLOps 단서입니다.
- “반복 가능성”, “버전 추적”, “자동화된 배포·평가”는 MLOps의 필요성과 연결합니다.
- 정확도 하나만으로 성공을 판단하지 말고 모델·운영·비즈니스 지표를 구분합니다.

## 자주 하는 오해

### 오해 1: 모델을 배포하면 ML 프로젝트는 끝난다

운영 환경의 데이터와 업무가 변할 수 있으므로, 배포 후 모니터링과 개선이 필요합니다.

### 오해 2: 평가 데이터로 다시 훈련하면 평가가 더 정확해진다

평가 데이터가 학습에 사용되면 새로운 입력에 대한 일반화 성능을 공정하게 측정하기 어려워집니다. 평가 데이터의 역할을 보존해야 합니다.

### 오해 3: MLOps는 모델을 자동으로 정확하게 만든다

MLOps는 반복·추적·운영을 돕는 방법입니다. 데이터 품질, 문제 정의, 평가 기준이 잘못되었다면 자동화만으로 문제를 해결할 수 없습니다.

### 오해 4: 비즈니스 지표가 좋으면 모델 지표는 필요 없다

업무 결과를 보려면 비즈니스 지표가 필요하지만, 원인을 분석하고 모델을 개선하려면 모델 지표와 오류 분석도 필요합니다.

## 핵심 정리

- ML 수명 주기는 문제 정의부터 모니터링과 재훈련까지 반복됩니다.
- 데이터 품질과 평가 데이터 분리가 중요합니다.
- 훈련과 추론은 서로 다른 단계입니다.
- MLOps는 데이터·모델·배포·모니터링을 반복 가능하게 만드는 운영 방식입니다.
- 모델 지표와 비즈니스 지표를 함께 확인해야 실제 가치를 판단할 수 있습니다.

**한 문장 암기 포인트:** `만들기보다 운영이 길다 — 정의, 데이터, 훈련, 평가, 배포, 모니터링, 개선을 반복한다`입니다.

## 스스로 답하는 확인 질문

1. 모델을 평가할 때 훈련에 사용한 데이터와 별도의 평가 데이터를 구분해야 하는 이유는 무엇인가요?
2. 배포된 모델의 성능이 시간이 지나며 떨어진다면 어떤 수명 주기 활동을 확인해야 하나요?
3. MLOps가 일반적인 소프트웨어 배포와 구분되는 이유는 무엇인가요?
4. 모델 정확도는 좋아졌지만 고객 처리 시간이 나빠졌다면 어떤 지표를 함께 검토해야 하나요?
