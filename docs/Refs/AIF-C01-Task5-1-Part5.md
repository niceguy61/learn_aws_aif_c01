## 1. AI 시스템 특정 취약성 5가지 (시험 암기)

### 1) 훈련 데이터 포이즈닝 (Data Poisoning)

- AI 모델 훈련 데이터 동작 학습, 악의적 행위자 훈련 데이터 액세스→모델 예측 변경 데이터 도입 가능
- 예) 사기 탐지 모델 사기 아닌데 사기로 분류된 금융 거래 훈련 가정, 공격자 특정 사기 거래 사기 아닌 것으로 분류된 데이터 추가→모델 잘못 분류→탐지 안되고 사기 가능

### 2) 적대적 입력 (Adversarial Inputs)

- 훈련 데이터 액세스 못해도 모델 실수하게 할 수 있음, 입력 데이터 약간 조작해 잘못 분류하도록
- 예) 얼굴 인식 모델 직원 인식, 공격자 직원 다른 사람 인식하도록 이미지 미묘하지만 세심 설계

### 3) 모델 반전 (Model Inversion)

- 정교한 공격자 모델 출력 사용 훈련 데이터 추론
- 공격자 계속 데이터 모델 입력 + 출력 연구
- 예) 얼굴 인식 모델 직원 이미지 훈련, 출력 직원 이름+신뢰도 점수, 공격자 얼굴 이미지 반복 공급 출력 직원 이름+높은 신뢰도 될 때까지 변경→해커 직원 좋은 이미지 획득→직원 가장
- 입력·출력 페어 충분 시 공격자 반대로 작동 새 모델 생성 가능 = 원래 모델 출력에서 새 모델 훈련 + 이 모델 통해 훈련 입력 데이터 추론 가능

### 4) 리버스 엔지니어링 (모델 도용)

- 해커 모델 리버스 엔지니어링 원래 모델 매우 비슷한 자신만의 모델 만들기 가능
- 해커 모델 정보 많을수록 사본 더 정확

### 5) 프롬프트 인젝션 (Prompt Injection) - LLM 취약

- 공격자 출력 영향 위해 프롬프트 악의적 명령 모델 제공
- 예) 프롬프트 템플릿 무시/변경하도록 LLM 요청→민감 정보 얻을 수 있음

## 2. 취약성 완화 모범 사례 (시험 중요)

### 고객 사전 완화 의무

- 데이터/모델 액세스 보호/제한해 잠재 공격 사전 완화, 프로덕션 모델 드리프트/이상 탐지 모니터링
- **액세스 항상 최소 권한 원칙**, AWS 적절한 권한 정책 구성 + 퍼블릭 액세스 차단
- **추가 보호 계층 데이터/아티팩트 암호화**
- **리버스 엔지니어링 차단:** 모델 액세스 제한/제어
- **입력 데이터 검사/검증:** 모델 입력 비정상 패턴 찾기, 예) 주요 공격 패턴 사용 프롬프트 인젝션 탐지 + "프롬프트 공격 탐지됨" 응답 반환하도록 LLM 학습
- **출력 최소화:** 모델 출력 불필요 정보 제공 X→공격자 정보 추론 방지
- **적대적 입력 훈련:** 모델 속지 않도록 방지→적대적 입력 사용 모델 훈련
- **자주 재훈련:** 새 데이터 자주 재훈련→손상 훈련 데이터 손상 복구
- **검증용 별도 데이터세트 보관:** 배포 전 재훈련 때마다 모델 검증
- **데이터 품질 스캔/모니터링:** 훈련 사용 전 정기 스캔 모니터링 품질 확인 이상 탐지
- **예측 과거 패턴 다를 때 조사:** 근본 원인 낮은 데이터 품질인지 공격인지 확인

## 3. Amazon SageMaker Model Monitor - 프로덕션 품질 모니터링

- 프로덕션 환경 SageMaker ML 모델 품질 모니터링
- 프로덕션 배포 후 **실시간 지속 모니터링 가능**
- **데이터 드리프트/이상 같은 품질 편차 자동 알림 시스템 설정 가능**
- 데이터 품질 모니터링에도 사용 가능
- SageMaker 모델 데이터/모델 기준 비교, SageMaker Studio 볼 수 있고 CloudWatch 보내는 통계/지표 생성
- CloudWatch Logs 모델 상태 모니터링 파일 수집, 품질 사전 설정 특정 임계값 도달 시 사용자 알림, CloudWatch 로그 파일 지정 S3 버킷 저장
- 모델 편차 사전 일찍 탐지→즉각 조치 가능, 품질 유지 보수 개선 가능

### 데이터 품질 모니터링 프로세스

- **데이터 캡처 사용 필요:** 추론 엔드포인트/배치 변환 작업 추론 입력/출력 캡처 + 데이터 S3 저장
- **기준 생성:** 일반적으로 훈련 데이터세트 사용
- 기준 데이터세트 + 분석 현재 데이터세트 통계 생성 **데이터 품질 모니터링 작업 예약**, 결과 SageMaker Studio에서 볼 수 있음

### 모델 품질 모니터링 프로세스

- 레이블 지정 데이터 사용 기준 생성
- 모델 품질 작업 실행 시 동일 입력 대해 **SageMaker Ground Truth 레이블 데이터 + 추론 비교**→성능 평가
- 결과 SageMaker Studio에서 볼 수 있음
